- тесты с моками prisma/auth: `apps/web/src/actions/register.test.ts`, `apps/web/src/app/api/v1/me/route.test.ts`

## Что сделать
1. `apps/web/src/actions/update-nick.ts` (`import "server-only"`): `export async function updateNick(input: NickUpdateBody, headers: Headers): Promise<ActionResult<Me>>`
   - нет сессии или нет строки пользователя → `UNAUTHENTICATED`;
   - `input.nick` уже нормализован схемой; дополнительно `normalizeNick` из `@/domain/nick` для `nickNormalized`;
   - если `nickNormalized` совпадает с текущим у этого пользователя → `{ok:true,data:Me}` без записи;
   - если ник занят другим пользователем (`findFirst` по `nickNormalized`, `id: { not: userId }`) → `{ ok:false, code:"VALIDATION", message:"Nick is taken", field:"nick", reason:"NICK_TAKEN" }`;
   - иначе `prisma.user.update({ where:{id}, data:{ nick, nickNormalized } })`; P2002 при гонке → тот же NICK_TAKEN;
   - возвращает `Me` (через `meSchema.parse`, как в current-user.ts; `timeZone` через `storedTimeZone`).
   - НИКАКИХ записей в `List` (publicToken не трогать — A-26).
   - экспортируй из `apps/web/src/actions/index.ts`, если там реэкспортируются use-case’ы.
2. `apps/web/src/app/api/v1/me/nick/route.ts`: `PUT` — `parseJsonBody(request, nickUpdateBodySchema)` → `toResponse(await updateNick(...))`; GET/POST/PATCH/DELETE/HEAD → `notFoundResponse`. Невалидное тело должно давать 400 VALIDATION с `field:"nick"` (проверь, что `parseJsonBody` так делает; если нет — сообщи, не переделывай общий хелпер).
3. Проверь, что маршрут не перехватывается `app/api/v1/[...slug]` и что proxy/CSRF/origin-проверки (`src/proxy.ts`) пропускают PUT так же, как для time-zone.

## Тесты
- `apps/web/src/actions/update-nick.test.ts`: без сессии → UNAUTHENTICATED; новый свободный ник → update вызван с `{nick, nickNormalized}` и ответ содержит новый nick; тот же ник → update не вызывается; ник другого пользователя → VALIDATION/NICK_TAKEN/field nick и update не вызывается; P2002 от update → NICK_TAKEN; в prisma-моке нет `list` — тест проверяет, что к list никто не обращался.
- `apps/web/src/app/api/v1/me/nick/route.test.ts`: PUT валидный → 200 `{ok:true}`; `{nick:"ab"}` → 400 VALIDATION field nick; битый JSON → 400; GET → 404 конверт.

## Критерии приёмки
- `curl -X PUT /api/v1/me/nick` с cookie-сессией меняет ник; занятый (в любом регистре) → 400 NICK_TAKEN.
- Схема Prisma и миграции не изменены.
