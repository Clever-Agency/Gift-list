# CLE-46 / 03 — mobile: клиент updateNick и обновление me в AuthContext

Story 3.1 (`epics.md:540-556`). Сервер (02) уже отдаёт `PUT /api/v1/me/nick` → `ActionResult<Me>`.

## Образцы
- `apps/mobile/src/api/my-gifts.ts` и `my-gifts.update.test.ts` (как устроены функции клиента и их тесты с подменой fetch)
- `apps/mobile/src/session/auth-context.tsx` (как хранится `me`, как вызывается `/api/v1/me/time-zone`)

## Что сделать
1. `apps/mobile/src/api/me.ts` (новый): `export function updateNick(nick: string): Promise<ClientResult<Me>>` → `apiRequest<Me>("/api/v1/me/nick", { method: "PUT", body: { nick } })`. Ответ `ok:true` валидируй `meSchema` так же, как это делают соседние функции (если они валидируют); иначе — как они.
2. `AuthContext`: добавить в значение контекста метод `setUser(me: Me)` (или `replaceMe` — выбери имя по стилю файла), чтобы экран настроек после успешной смены ника обновил текущего пользователя без перезагрузки. Ничего другого в контексте не меняй.

## Тесты
- `apps/mobile/src/api/me.test.ts`: отправляет PUT на `/api/v1/me/nick` с JSON `{nick}`; 200 → `{ok:true,data}`; 400 NICK_TAKEN → ошибка с `reason:"NICK_TAKEN"`, `field:"nick"`; сеть упала → `{ok:false,network:true}`.
- `auth-context.test.tsx`: после `setUser` потребитель контекста видит новый nick.
