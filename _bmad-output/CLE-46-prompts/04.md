## Что сделать
`apps/mobile/app/(app)/settings.tsx` — именованный компонент `SettingsScreen`:
- заголовок «Настройки» (`app.settings.title`), title страницы `app.settings.pageTitle`;
- кнопка «Назад» (`app.settings.back`) — `router.back()`, если есть история, иначе `router.replace("/")`;
- поле «Ник» (`app.form.nick`) с начальным значением `auth.user.nick` (посмотри фактическое имя поля в контексте), `autoCapitalize="none"`, `autoCorrect={false}`;
- hint: если введённое (trim+lowercase) проходит `NICK_PATTERN` из contracts → `app.form.nickPreview` (`@ник`), иначе правила `app.settings.nickHint`;
- «Сохранить» (`app.settings.save`): клиентская проверка по `NICK_PATTERN` → inline `app.register.nickRules`-текст (через ключ `app.settings.nickHint`) без запроса; если ник = текущему → inline/hint `app.settings.nickUnchanged` без запроса; иначе `updateNick`; пока идёт запрос — кнопка disabled, повторное нажатие не шлёт второй запрос;
- ответ NICK_TAKEN → inline ошибка под полем «Этот ник уже занят.» (через form-issue / `common.errors.reason.NICK_TAKEN`), фокус остаётся/возвращается в поле; VALIDATION field nick → правила ника; network → тост/ошибка `app.form.network`;
- успех → `setUser(data)`, тост «Ник изменён.» (`app.settings.nickSaved`, нейтральный тон), поле показывает сохранённый ник;
- аноним → как на других экранах группы (app) (посмотри, как это сделано в new.tsx: redirect на вход с return path).
Никаких текстов в коде — только ключи.
