## Что сделать
1. `apps/web/src/actions/wishlist-read.ts` (`import "server-only"`):
   `export async function readWishlist(input: { viewer: VisibilityViewer; target: { ownerId: string } | { publicToken: string }; viaListToken?: boolean }, deps = { reader: relationshipReader }): Promise<ListData>`
   - найти `List` по ownerId или publicToken (`select: { id, ownerId }`); нет → `{access:"not_found", gifts:[]}` и `gift.findMany` НЕ вызывается;
   - relations: владелец → `NO_RELATIONS`; иначе `await deps.reader.relationsBetween(viewer?.id ?? null, list.ownerId)` + `viaListToken`;
   - если не владелец и blocked → not_found без чтения желаний;
   - `allowed = VisibilityPolicy.allowedVisibilities(...)`; если пусто → `{access:"gifts", gifts:[]}` без запроса желаний;
   - ЕДИНСТВЕННЫЙ в проекте `prisma.gift.findMany` по listId: `where: { listId, archivedAt: null, visibility: { in: allowed } }` (активный список; архив — Story 2.6, но для не-владельца архив исключён и самим policy), `orderBy: [{createdAt:"desc"},{id:"desc"}]`, select — поля для обоих мапперов (+ `reservationBought`, `holderVisibleToOthers`);
   - результат ВСЕГДА пропускается через `VisibilityPolicy.resolve` (двойная защита: where + policy);
   - маппинг: роль owner → `toOwnerGiftCard`, иначе `toViewerGiftCard(row, viewer?.id ?? null)`;
   - `return listDataSchema.parse(...)`.
2. `getMyGifts` в `my-gifts.ts`: сессия как сейчас → `readWishlist({ viewer: {id}, target: { ownerId: id } })`. Особенность: если списка нет, владелец сейчас получает пустой `access:"gifts"` (см. комментарий в файле) — сохрани это поведение в getMyGifts (not_found владельцу → пустой gifts).
3. Не добавляй новых маршрутов: `/l/:token` — Story 3.3, `/u/:nick` — 3.4. `readWishlist` с `publicToken` пока вызывается только из тестов — это нормально.
