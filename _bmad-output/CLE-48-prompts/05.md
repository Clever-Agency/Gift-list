# CLE-48 / 05 — application: getGift (загрузка формы) через VisibilityPolicy

Story 3.2 AC: «любой server read вишлиста или желания … вызывает resolve» (`epics.md:558-575`, AD-7 в `_bmad-output/planning-artifacts/architecture/architecture-gift-list-2026-09-30/ARCHITECTURE-SPINE.md`: «Любой list/gift read API … вызывает тот же resolve»).

`apps/web/src/actions/gifts.ts` → `getGift(headers, giftId)` сейчас читает `prisma.gift.findFirst({ where: { id, archivedAt: null, list: { ownerId: session.user.id } } })` и отдаёт `toOwnerGiftCard`. Это read формы редактирования — только владельцу.

## Что сделать (минимально)
- Оставь where с ownerId (чужое id по-прежнему → NOT_FOUND без раскрытия существования), но дополнительно прочитай `visibility`, `archivedAt` и `list.ownerId` и пропусти через `VisibilityPolicy.canSee({id: session.user.id}, NO_RELATIONS, {...})`; не прошёл → тот же `notFound`. Комментарий: форма — ветка владельца AD-7; чтение чужих желаний — только через `readWishlist`.
- Мутации (create/update) не трогай.

## Тесты (`apps/web/src/actions/gifts.test.ts`, дополни)
- свой SECRET-подарок открывается;
- если моки вернули строку, чей list.ownerId ≠ пользователь (имитация ошибки where), ответ NOT_FOUND и без полей подарка.
