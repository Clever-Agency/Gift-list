## 1. `apps/web/src/actions/gifts.ts` → `updateGift`
Сейчас (около строк 140-195) `updateGift` пишет любой `visibility` без учёта статуса.
Нужно:
- Если в `update` есть `visibility`: прочитать хранимое `{ status, visibility }` по тому же `ownedGift` where (если не найдено → `notFound`).
  - Если хранимое `visibility === update.visibility` → удалить ключ `visibility` из update (правка забронированного желания из формы шлёт то же значение и не должна падать).
  - Иначе если `status !== "OPEN"` → вернуть `validation("visibility")` (`{ok:false, code:"VALIDATION", message:"Invalid input", field:"visibility"}`), ничего не записав.
  - Иначе (OPEN) — запись делать с where `{ ...ownedGift, status: "OPEN" }`, чтобы гонка (бронь между чтением и записью) не прошла. При P2025 в этом случае перечитай: если желание есть и не OPEN → `validation("visibility")`, иначе `notFound`.
- Существующую логику AD-25 (валюта без суммы) сохрани; объедини чтения в одно, если удобно (select `{ priceAmount, status, visibility }`), но поведение остальных полей не меняй.
- Обнови JSDoc функции (Story 2.3, AD-8).

## 2. Новый use-case `deleteGift(headers, giftId): Promise<ActionResult<{ id: string }>>` в том же файле
- Нет сессии → `unauthenticated`.
- `prisma.gift.deleteMany({ where: { id: giftId, archivedAt: null, status: "OPEN", list: { ownerId: session.user.id } } })`.
- `count === 1` → `{ ok: true, data: { id: giftId } }`.
- `count === 0` → `findFirst` по `{ id, archivedAt: null, list: { ownerId } }` select `{ status: true }`: найдено (значит не OPEN) → `{ ok:false, code:"CONFLICT", message:"Only an open wish can be deleted here" }`; не найдено (чужое, архивное, нет) → `notFound` (тот же ответ, что и для чужого — AD-7, не раскрывать существование).
- JSDoc: Story 2.3, FR-10; RESERVED — Story 5.4, CLOSED — Story 2.6.
- Экспортируй из `apps/web/src/actions/index.ts`, если там реэкспортируются остальные gift-use-case'ы.
