# CLE-51 / 05 — «Мой вишлист»: смена видимости с чипа (optimistic)

Спека: `EXPERIENCE.md` строка «Visibility chip»: «У `открыт` нажатие — выбор из трёх, сохраняется сразу (optimistic), toast «Видимость: друзьям»; при ошибке — чип откатывается, toast «Нет сети. Попробуйте ещё раз.»». В каталоге текст сети — `app.form.network` («Нет соединения. Попробуйте ещё раз.»), используй его, как остальные экраны. `DESIGN.md` VisibilityChip: после сохранения фокус — обратно на чип.

Готово из прошлых микрозадач: `WishCard` принимает `onVisibilityPress` и `visibilityChipRef` (04), `VisibilityPicker` (04), `updateGift(id, { visibility })` уже есть в `src/api/my-gifts.ts`, ключи `app.gift.visibilityLower`, `app.gift.toast.visibility` (01).

## Что сделать — `apps/mobile/app/(app)/index.tsx`
1. Состояние `picker: { gift: GiftCard } | null`. `WishCard` получает `onVisibilityPress={() => setPicker({ gift })}` (передавай всегда — карточка сама не делает чип кнопкой у не-OPEN).
2. Один `<VisibilityPicker>` на экран: `visible={picker !== null}`, `title={picker.gift.title}`, `value={picker.gift.visibility}`, `onClose` → закрыть и вернуть фокус на чип этого желания, `onSelect(next)` → `changeVisibility(gift, next)`.
3. `changeVisibility(gift, next)`:
   - закрыть picker; optimistic: в `state.gifts` заменить visibility этого id на `next`;
   - `const result = await updateGift(gift.id, { visibility: next })`;
   - ok → заменить карточку ответом сервера (`result.gift`), toast info `t("gift.toast.visibility", { value: tLower(next) })`;
   - `network` → откат к прежней visibility, toast error `t("form.network")`;
   - `UNAUTHENTICATED` → откат и тот же путь с истёкшей сессией, что уже есть на экране при чтении (переиспользуй, не дублируй — вынеси в функцию, если надо);
   - `VALIDATION` (желание уже забронировали) или `NOT_FOUND` → откат + toast error `common("errors.code.<CODE>")`, затем тихо перезагрузить список (тот же refetch, что делает focus-обновление), чтобы статус карточки стал актуальным;
   - `invalid` или прочие коды → откат + `common("errors.generic")` / `errors.code.*` как в остальных ветках экрана.
   - Защита от двойного тапа: пока запрос по этому id в полёте — повторное открытие picker для него игнорируется (ref-Set id).
   - Если параллельно пришёл focus-refetch — не страшно, но откат должен возвращать именно прежнее значение этого id, не затирая остальной список.
4. Фокус: держи `Map<id, ref>` для `visibilityChipRef`; после закрытия picker (выбор или отмена) вызови `AccessibilityInfo.setAccessibilityFocus(findNodeHandle(ref))` на native и `ref.focus?.()` на web — посмотри, как фокус возвращается в других местах приложения (`rg setAccessibilityFocus` по apps/mobile; если нигде — сделай маленький helper в `src/ui/focus.ts` с JSDoc).
Больше ничего на экране не меняй (тосты created/updated, footer, сетку).
