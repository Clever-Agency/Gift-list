# CLE-51 / 06 — экран правки: блок видимости у не-OPEN и удаление с подтверждением

Спека: `epics.md` Story 2.3 AC; `EXPERIENCE.md`: «Правка забронированного желания: … Видимость … заблокированы» (~276), таблица статусов (~263-265), «Шторка vs диалог» (~280: confirm внутри формы — шаг того же слоя), `DESIGN.md` BottomSheet/Dialog (~425). Удаление `RESERVED` — Story 5.4, его здесь нет; у RESERVED и CLOSED кнопки «Удалить» нет.
Ключи (01): `app.giftForm.field.visibilityLocked`, `app.giftForm.delete.{action,confirmTitle,confirmBody,confirm,cancel,deleting}`, `app.giftForm.toast.deleted`. Клиент `deleteGift` (03).

## 1. `apps/mobile/src/ui/gift-form.tsx`
- Новый проп `visibilityLocked?: boolean`. Если true: группа видимости показывает текущее значение, но радио `disabled` (`accessibilityState={{ disabled: true, checked }}`), нажатия не меняют выбор, под группой подсказка `field.visibilityLocked` (caption, muted). Остальные поля работают как раньше. Без пропа — поведение не меняется.

## 2. `apps/mobile/app/(app)/gifts/[id]/edit.tsx`
- `visibilityLocked={state.gift.status !== "OPEN"}` в `GiftForm`.
- `toGiftUpdate(values, gift)`: если `gift.status !== "OPEN"` — НЕ включать `visibility` в тело (сервер и так отклонит смену, а то же значение не нужно).
- Удаление (только `state.gift.status === "OPEN"`): под формой вторичная деструктивная кнопка `delete.action` (если в `src/ui` нет варианта кнопки «destructive/ghost» — сделай текстовую `Pressable` с `accessibilityRole="button"`, цвет `colors.destructive` если есть токен, иначе `colors["status-…"]`/ближайший из DESIGN.md; минимальная зона 44).
  - Нажатие → confirm-шаг: RN `Modal` (как `VisibilityPicker` из 04 — переиспользуй его каркас, если вынесен; иначе маленький `src/ui/confirm-dialog.tsx` `ConfirmDialog({visible,title,body,confirmLabel,cancelLabel,busy,onConfirm,onCancel})` с тестом) с заголовком `delete.confirmTitle` ({title}), текстом `delete.confirmBody`, кнопками «Удалить» (деструктивная) и «Отмена».
  - «Удалить» → `deleteGift(id)` с защитой от двойного тапа (ref, как `inFlight` для save), кнопка показывает `delete.deleting` и disabled.
  - ok → `router.dismissTo({ pathname: "/", params: { toast: "gift_deleted" } })`.
  - network → диалог закрыт, toast error `t("form.network")`, форма не тронута.
  - NOT_FOUND → `setState({status:"missing"})` + toast `common("errors.code.NOT_FOUND")`.
  - CONFLICT (желание успели забронировать) → закрыть диалог, toast `common("errors.code.CONFLICT")`, перечитать желание (`setAttempt(v=>v+1)` + loading) — форма обновится и кнопка удаления исчезнет.
  - UNAUTHENTICATED → тот же путь, что у save.
  - invalid/прочее → `common("errors.generic")` / `errors.code.*`.

## 3. `apps/mobile/app/(app)/index.tsx`
Принять `?toast=gift_deleted`: константа `DELETED_TOAST`, toast info `giftForm("toast.deleted")` (рядом с CREATED/UPDATED, в том же эффекте). Больше ничего не трогай.
