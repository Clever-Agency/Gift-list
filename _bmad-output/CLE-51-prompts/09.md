# CLE-51 / 09 — понятный тост, если желание забронировали во время смены видимости

## Проблема
Файл: `apps/mobile/app/(app)/index.tsx`, функция `changeVisibility`, ветка `if ("code" in result && (result.code === "VALIDATION" || result.code === "NOT_FOUND"))` (~строка 345).
Воспроизведение: владелец открыл «Мой вишлист»; в это время желание стало `RESERVED` (кто-то забронировал). Владелец жмёт чип «Видимость: …» и выбирает другое значение. Сервер (`PATCH /api/v1/me/gifts/{id}`) отвечает 400 `{code:"VALIDATION", field:"visibility"}`.
Сейчас: тост «Проверьте введённые данные.» (`common.errors.code.VALIDATION`) — пользователь ничего не вводил, текст сбивает с толку.

## Ожидаемое
- При `VALIDATION` — тост с новым текстом «Желание уже забронировано — видимость не изменить.», тон `error`; откат чипа и тихая перезагрузка списка (`setAttempt`) — как сейчас.
- При `NOT_FOUND` — всё как сейчас (`common.errors.code.NOT_FOUND`).
- Спека: `EXPERIENCE.md` → Visibility chip (ошибка откатывает чип, текст объясняет причину); AD-8 (видимость меняется только у `OPEN`).

## Как сделать
1. `packages/contracts/src/i18n/ru/app.json`: в объект `app.gift.toast` (там уже есть `visibility`) добавь ключ `visibilityLocked`: «Желание уже забронировано — видимость не изменить.». Если есть другие локали в `src/i18n/*/app.json` — добавь ключ и туда (перевод по смыслу); если тест каталогов сверяет ключи — он должен пройти.
2. В `changeVisibility` раздели ветку: `VALIDATION` → `t("gift.toast.visibilityLocked")`, `NOT_FOUND` → прежний текст. Обе ветки по-прежнему вызывают перезагрузку.
Только именованные функции; строки — только через каталог.
