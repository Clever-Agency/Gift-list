## Задача
1. ОДИН компонент `ConfirmDialog` в `apps/mobile/src/ui/confirm-dialog.tsx` с двумя режимами:
   - режим подтверждения (удаление, 2 кнопки): `cancelLabel` + `onCancel`, `confirmLabel` + `onConfirm`, `body?`; начальный фокус на «Отмена» (как в main);
   - режим «несохранённые изменения» (3 действия): `confirmLabel`/`onConfirm` («Сохранить»), `declineLabel`/`onDecline` («Не сохранять»), крестик `closeLabel`/`onClose`; начальный фокус — как в UX (заголовок), Esc/Android-назад/подложка = `onClose`.
   Режим выбирается по наличию пропсов (например, есть `onDecline` → 3 действия) или явным `variant` — выбери понятное и типобезопасное (discriminated union).
   - Единое «занято»: один проп `busy` (или `confirmDisabled` — одно имя на оба режима; второе убрать и обновить вызовы). При busy подтверждение не нажимается повторно (одиночное нажатие из UX сохранить).
   - Возврат фокуса в ОБОИХ режимах — только через `onDismiss` / `useLayerClosed` (фикс 11). Пропс `onReturnFocus` из UX слить с `onClosed` (одно имя, `onClosed`), вызовы в new.tsx/edit.tsx обновить. Никаких `focus()` в эффекте на `visible=false`.
   - Подложка: `focusable={false}`, `tabIndex -1`, aria-hidden (как в main). role/aria-modal/aria-labelledby — без дублирования (RN-web Modal уже даёт role="dialog"; если UX-версия рисует свой `role="dialog"` внутри — оставь одну).

Два независимых состояния диалогов (discard и delete), одновременно открыт максимум один.
