## Баг (воспроизведён в браузере, web, Chromium; воспроизводится и на исходной UX-ветке — это не регрессия слияния, но чинить нужно)
Шаги (создание, `/gifts/new`, открыт по кнопке «Добавить желание» со списка, т. е. без полной перезагрузки):
1. Ввести название → форма грязная.
2. Нажать «Отмена» формы → открывается «Сохранить изменения?».
3. Закрыть его крестиком «Закрыть» ИЛИ Esc → диалог закрыт, черновик на месте. (history.state ещё содержит `giftFormGuard: true`, length=4.)
4. Браузерная кнопка «назад» → диалог «Сохранить изменения?» открывается снова (правильно).
5. Нажать «Не сохранять».
Ожидаемо: уход на список `/` без вопроса (как в сценарии без шагов 2–3 — там всё работает: после «Не сохранять» url `/`, диалога нет).
Фактически: url остаётся `/gifts/new`, диалог «Сохранить изменения?» снова на экране, `history.state` уже БЕЗ `giftFormGuard` (sentinel снят), length=4. То есть уход «съеден» и вопрос задан повторно.
Тот же сценарий нужно проверить и починить для редактирования (`/gifts/[id]/edit`) — логика общая.

Файлы: `apps/mobile/src/session/use-discard-guard.ts`, `apps/mobile/src/session/use-browser-back-guard.ts`, `apps/mobile/app/(app)/gifts/new.tsx` (`cancel`, `leave`, `closeDiscard`, `leaveDiscard`, `saveDiscard`), `apps/mobile/app/(app)/gifts/[id]/edit.tsx` (аналогичные функции).
Гипотезы для проверки (не принимай на веру — найди настоящую причину): после закрытия диалога, открытого «Отменой», `guard.cancel()` / состояние `pending`/`leaving`/`bypass` в двух хуках расходятся; при `proceed()` браузерный guard делает `history.go(-2)`, а `usePreventRemove` expo-router ловит удаление экрана и снова вызывает `onBlocked` (bypass не выставлен), либо `go` делает только один шаг. Также в консоли есть предупреждение react-navigation: «`repeat` or `disablePrevention` from `usePreventRemove` was called, but `preventRemove` is still `true`».
