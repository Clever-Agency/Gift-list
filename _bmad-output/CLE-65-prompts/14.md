## Задача
1. Сделать лимиты настраиваемыми через env, ПО УМОЛЧАНИЮ — текущие прод-значения (5 попыток за 3600 с), т. е. без заданных переменных поведение не меняется ни на байт:
   - `AUTH_RATE_LIMIT_MAX` — целое ≥ 1, по умолчанию 5;
   - `AUTH_RATE_LIMIT_WINDOW_SECONDS` — целое ≥ 1, по умолчанию 3600.
   Одна пара на все четыре места (регистрация, вход по IP, вход по e-mail, сброс пароля) — как сейчас общий `REGISTER_LIMIT`. Пустая строка = не задано (значение по умолчанию). Некорректное значение (не число, 0, отрицательное, дробное) — понятная ошибка валидации env (как остальные переменные в `env.ts`), а не молчаливый NaN.
2. Заменить константу на именованную функцию, например `export function authRateLimit(): { max: number; windowSeconds: number }`, читающую значения через `env.ts`; обновить три action-файла. Константу с прод-значениями по умолчанию оставить экспортируемой (например `DEFAULT_AUTH_RATE_LIMIT`) — её используют тесты. Только именованные функции.
3. Документация: добавить в `apps/web/.env.example` закомментированные строки с пояснением (по-английски, как соседние): что лимитирует, значения по умолчанию, что для локальной разработки/QA можно поднять, в проде оставить по умолчанию. При наличии раздела о переменных окружения в `apps/web/AGENTS.md` или README — добавить туда одну строку. НЕ трогать никакие `.env`, `.env.local` и прочие файлы с секретами.
4. Тесты (vitest, `apps/web`):
   - по умолчанию (переменные не заданы / пустые) → `{ max: 5, windowSeconds: 3600 }`;
   - override (`AUTH_RATE_LIMIT_MAX=100`, `AUTH_RATE_LIMIT_WINDOW_SECONDS=60`) → эти значения;
   - некорректные значения → ошибка;
   - что register/sign-in/password-reset передают в `consumeRateLimit` значения из `authRateLimit()` (замокать `consumeRateLimit`, если в существующих тестах так уже делается — посмотри соседние тесты actions).
   Учитывай кеш env в `env.ts`: дай тестам способ сбросить его (если уже есть — используй) и восстанавливай `process.env` после каждого теста.
