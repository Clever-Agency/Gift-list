# Epic 2 Context: Владелец наполняет вишлист

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Владелец единственного вишлиста создаёт, редактирует, скрывает и удаляет желания, задаёт их тип и теги, срок жизни и фото, а также делится одной ссылкой на список. Эпик закрывает основной сценарий наполнения: желание должно быть понятным дарителю (что это, сколько раз можно дарить, насколько важно) и безопасным для владельца (видимость, архив, отсутствие денежных сборов). Клиент всех историй — приложение (Android, iOS, браузер), сервер — Next.js.

## Stories

- Story 2.1: Экран «Мой вишлист» с gift card и status pill
- Story 2.2: Создание и редактирование желания
- Story 2.3: Видимость и удаление желания
- Story 2.4: Копирование ссылки на вишлист
- Story 2.5: Тип желания и теги
- Story 2.6: Срок жизни желания и архив
- Story 2.7: Фото желания

## Requirements & Constraints

- Желание принадлежит единственному списку владельца (FR-9) и создаётся со статусом `OPEN`.
- Обязателен только `title`; `description`, цена и `linkUrl` необязательны. Нематериальное желание без ссылки допустимо (D-25, D-36).
- Видимость по умолчанию — `PUBLIC`; владелец может поставить `PUBLIC`, `FRIENDS` или `SECRET`. Смена видимости разрешена только у `OPEN`, у `RESERVED`/`CLOSED` — отказ `VALIDATION` (FR-10, FR-11, Story 2.3).
- Тип желания — `SINGLE` или `UNLIMITED`, по умолчанию `SINGLE`; меняется только у `OPEN`. Бронируется только `SINGLE`, у `UNLIMITED` кнопки «Куплю сам» нет ни у кого (FR-41, D-25, Story 2.5).
- Теги: фиксированные «мечта», «нужно сейчас», «когда-нибудь» плюс свой текст ≤ 30 символов. Свой тег виден тем, кто видит желание, и не попадает в агрегаты до одобрения ADMIN (FR-44, D-27, AD-22).
- Одна ссылка на вишлист: `https://{домен}/l/{publicToken}`; домен из конфигурации, смена ника token не меняет (FR-28, AD-6, Story 2.4).
- Срок жизни `expiresOn` необязателен; когда срок прошёл (локальная дата владельца позже `expiresOn`), `OPEN`-желание уходит в архив через `GiftStatusService` (FR-42, D-26, Story 2.6). Ветки `RESERVED` и уведомления держателю — Story 6.6.
- Фото желания — отдельное решение ARCH-A18: файлы в S3-совместимом хранилище, в карточке короткоживущая подписанная ссылка после проверки видимости (Story 2.7).

## Technical Decisions

- AD-1: Server Actions и Route Handlers `app/api/v1/*` вызывают одни и те же use-case/domain-методы; правила не дублируются. Ответ — конверт AD-12 `{ ok: true, data } | { ok: false, code, message, reason?, field?, params? }`.
- AD-12: gift card — закрытый контракт в `packages/contracts`: `id`, `title`, `description`, `priceAmount`, `priceCurrency`, `linkUrl`, `visibility`, `quantity`, `expiresOn`, `archivedAt`, `tags[]`, `status`, `reservedBy`, `reservationLabel`, `ownerAction`. Лишние поля отклоняются, `bought` владельцу не отдаётся.
- AD-8: `Gift` — единственный writer статуса `GiftStatusService`; `quantity` — enum `SINGLE | UNLIMITED`. `UNLIMITED` не переходит в `RESERVED`. Правка полей `RESERVED` разрешена, кроме правил видимости и `quantity`, которые требуют `OPEN`.
- AD-25: цена — целые минорные единицы; валюта `USD | EUR | CNY | BYN | RUB`, при сумме без валюты — `USD`, без суммы валюта `null`.
- AD-7: видимость решает только `VisibilityPolicy`; владелец видит свои желания включая `SECRET`, чужой `SECRET` не раскрывается.
- AD-22/AD-27: фиксированные теги — данные БД с `slug` и `labels` на всех поддерживаемых языках; сервер отдаёт `tags[].label` на языке запроса, клиент показывает `label`. Свои теги не переводятся.
- AD-6: список и его `publicToken` immutable; token не зависит от ника (A-26).
- AD-17/AD-26: `apps/mobile` импортирует только `@gift-list/contracts` и `@gift-list/ui`; UI — Tamagui из `packages/ui`, без API/Prisma/env и без строк интерфейса.

## UX & Interaction Patterns

- «Мой вишлист» показывает все желания владельца, включая `SECRET`, с Visibility chip и Status pill; пустое состояние — «Пока пусто» + «Добавить желание».
- Форма желания: `title` обязателен, остальные поля необязательны; тип и теги выбираются в той же форме, ошибки полей показываются по `field`/`reason`.
- Смена видимости и типа — только у `OPEN`; у `RESERVED`/`CLOSED` контролы недоступны, а повторная отправка сохранённого значения не является изменением.
- Удаление — с подтверждением; удаление `RESERVED` относится к Story 5.4.
- «Скопировать ссылку» кладёт в буфер один URL и показывает toast «Ссылка скопирована»; share-sheet не нужен.

## Cross-Story Dependencies

- Story 2.1 даёт экран и карточку, на которые опираются 2.2–2.7.
- 2.3 задаёт правило «видимость только у `OPEN`», 2.5 повторяет его для `quantity`; общий паттерн валидации и `field` в ошибке.
- 2.4 зависит от `publicToken` списка (Epic 1, Story 1.5) и конфигурации домена (Q-2).
- 2.6 создаёт `GiftStatusService` и cron `api/cron/wish-expiry`; идёт раньше Story 5.1, которая расширяет сервис.
- 2.7 ждёт закрытия ARCH-A18; хранилище и подписанные ссылки не должны нарушать AD-16.
- Теги (2.5) связаны с админкой и агрегатами Story 10.2; до одобрения ADMIN свой тег не входит в статистику.
