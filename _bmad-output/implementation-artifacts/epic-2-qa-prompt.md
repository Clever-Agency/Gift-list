## Шаг 2. Проверка по историям

Для каждого пункта: что сделал, ожидание, факт, вердикт (PASS / FAIL / NOT TESTED + причина). API проверяй `curl` или `fetch` из Node на `http://localhost:3000` с `Accept-Language: ru`; UI — в браузере на SPA из `npm run build`.

Формат ответа API (AD-12): успех `{ ok: true, data }`, ошибка `{ ok: false, code, message, reason?, field?, params? }`, `code` ∈ `UNAUTHENTICATED | FORBIDDEN | NOT_FOUND | CONFLICT | VALIDATION | RATE_LIMITED`. Клиент показывает текст по `reason`, иначе по `code`, и никогда не показывает `message`.

Брони в продукте ещё нет. Состояния `RESERVED` и `CLOSED` создавай прямым SQL в своей БД и отмечай это в доказательстве.

### 2.2. Создание и редактирование
- `title` обязателен; `description`, цена, `linkUrl` необязательны; пустой и слишком длинный `title` → VALIDATION с `field`.
- Новое желание: в единственном вишлисте владельца, `OPEN`, видимость по умолчанию `PUBLIC`.
- Цена: сумма без валюты → `USD`; все пять валют; без суммы валюта `null`; цена хранится в минимальных единицах (0, дробная, отрицательная, очень большая).
- Желание без ссылки сохраняется; `linkUrl` со схемой `javascript:` и не-URL отклоняются, если это задано контрактом.
- Правка сохраняется; чужое желание → `NOT_FOUND` без раскрытия существования (AD-6). Лишнее поле в теле → VALIDATION, а не 500.
- Веб и нативный путь идут через один use-case (`app/api/v1` → `src/actions/gifts.ts`, по коду).
- Кнопка «Отмена» на экранах желания (CLE-65).

### 2.3. Видимость и удаление
- `OPEN`: смена на `PUBLIC`, `FRIENDS`, `SECRET` сразу действует для зрителя: анонимный `/l/<token>` и профиль показывают только разрешённое, число и факт скрытых не раскрываются (AD-7).
- `RESERVED`, `CLOSED` (через SQL): смена видимости → VALIDATION; повторная отправка сохранённого значения не считается изменением.
- `OPEN`: удаление с подтверждением (Esc, «Отмена», подтверждение; фокус возвращается; toast).
- Удаление `RESERVED` и `CLOSED` → CONFLICT (долг, Stories 5.4 и 5.3).
