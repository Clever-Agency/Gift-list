# Epic 3 Context: Обнаружение и открытие вишлиста

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Пользователь находит человека по нику или имени и открывает его вишлист — в приложении или по одной публичной ссылке из мессенджера. Ссылка работает в браузере без установки и входа: аноним сразу видит открытые желания, а бронь уводит его в приложение через регистрацию с возвратом на тот же вишлист. Всё, что видит зритель, решает одно правило видимости: ни один путь чтения не отдаёт чужому «друзьям» или «секрет» и не намекает на существование скрытого.

## Stories

- Story 3.1: Смена Ника в настройках
- Story 3.2: VisibilityPolicy и wire DTO доступа
- Story 3.3: Публичная ссылка `/l/:publicToken`
- Story 3.4: Профиль `/u/:nick`
- Story 3.5: Поиск пользователей и «скрыть из поиска»

## Requirements & Constraints

- **Ник.** 3–24 `[a-z0-9_]`, уникальность без учёта регистра. Смена ника не меняет `List.publicToken`: ссылка вишлиста цела, старый `/u/{ник}` — «пользователь не найден», занятый ник — inline-ошибка у поля, в форме превью `@ник`.
- **Единый фильтр.** Профиль, `/l/:token` и `api/v1` отдают только разрешённые зрителю желания; сырой `findMany` по `listId` в обход политики запрещён. Ответ всегда `access: gifts | not_found`, «закрытого» состояния нет, архив видит только владелец. Число, названия и факт скрытых не отдаются ни в данных, ни в текстах, ни в мета-тегах. Block в любую сторону даёт то же «не найдено», что и невалидный адрес.
- **Публичная ссылка.** Аноним видит «всем», друг — «всем» и «друзьям». Пусто — «Пока нет открытых желаний», не «закрыто» и не «не найдено». «Куплю сам» ведёт на вход/регистрацию с возвратом на вишлист; вход и регистрация по `/l/` дружбу не создают.
- **Профиль.** Карточка (имя, ник) и желания по отношению: друг — «всем» + «друзьям», подписчик и `ContactMatch` — только «всем», без отношения — ноль желаний и кнопки «Добавить в друзья» / «Подписаться». Даты живут по своей видимости.
- **Поиск.** Точный/префикс ника и нечёткое имя с лимитом; любой пользователь, кроме скрытых из поиска (прямые `/u` и `/l` работают). Пусто — пустое состояние, не ошибка; состав желаний не раскрывается.

## Technical Decisions

- **AD-7 — единственный gate.** `VisibilityPolicy.resolve(viewer, list)` → `{ access, gifts }`. `SECRET` — владелец; `FRIENDS` — владелец и принятая дружба; `PUBLIC` — владелец, друг, подписчик, `ContactMatch`, любой обладатель `/l/:token`, включая анонима. Поля брони — по роли зрителя, `reservedBy` может быть `null` при `RESERVED`; контракт принимает поля Epic 5 без изменений.
- **AD-12.** `{ ok: true, data } | { ok: false, code, message, reason?, field?, params? }`; коды закрытые, `reason` — zod-enum (`NICK_TAKEN` и т. п.), тексты — по ключам переводов. Gate-ответы — `ok: true` с `access`. Gift card одна для веба и Expo, в `packages/contracts`.
- **AD-13.** PK — CUID2, ник плюс нормализованная колонка `nickNormalized`. Сравнение только через `normalizeForSearch()` (NFC, нижний регистр, `ё → е`, `й` остаётся `й`): на сервере колонка, на клиенте та же функция. Телефонный поиск — отдельный endpoint.
- **AD-26 — один домен.** Next.js обслуживает `/api`, `/l`, `/i`, `/unsubscribe`, `/admin`, `/.well-known`, остальное — SPA. `/l/:token` при сессии сразу передаёт на `/wishlist/:token`; `?next=` — только относительный путь того же домена. App/Universal Links объявляют `/l/*` и `/wishlist/*`; `/wishlist` Next.js не обслуживает.
- **AD-2.** Серверная `/l` собирается из тех же компонентов `packages/ui`, что экран вишлиста в приложении; CSS Tamagui — в HTML первого ответа (`useServerInsertedHTML`).
- **AD-27.** Язык Next-страниц — `negotiateLocale()` из `Accept-Language` (иначе `ru`), `lang` у `<html>` — выбранный, ответ с `Vary: Accept-Language` или `Cache-Control: private`. Сегмента языка в URL нет — он ломает App Links. Каталоги и `normalizeForSearch` — в `packages/contracts/src/i18n`; строки в компонентах запрещены, имя продукта — `{brand}`.
- **AD-1/AD-21.** Server Actions, `api/v1` и cron вызывают те же domain-методы, правила видимости не дублируются. Дружбу создаёт только `/i/:token`, `/l/:token` — никогда.
- **Тесты (AD-15).** Аноним по `/l/:token` — только `PUBLIC` и без числа остальных; Block с валидным токеном — `not_found`; подписчик не получает `FRIENDS`; регистрация по `/l/` не создаёт дружбу.

## UX & Interaction Patterns

- **`/l/{token}`.** Имя владельца — `h1` (`display-sm`), ниже `@ник`. Карточки — тот же Gift card, но только «всем», без чипа видимости и счётчика скрытых; одна колонка до 600 px, дальше сетка до трёх. Пусто — «Пока нет открытых желаний», невалидный токен или Block — «Список не найден». Мета-теги превью: имя владельца и бренд, без названий и фото желаний.
- **«Куплю сам» на `/l`.** Ссылка (`<a>`, видимый текст тот же, `aria-label` с названием), не кнопка-заглушка: без сессии — вход с возвратом и открытым подтверждением брони, с сессией — сразу экран вишлиста.
- **Профиль и поиск.** Человек везде строкой: статус отношения чипом справа, действия в `⋯`; в профиле — кнопками. Заблокированный не виден в поиске и списках. «Ожидает ответа» — чип, желания «друзьям» скрыты.
- **Состояния.** «Пока нет открытых желаний» — один текст для профиля, вишлиста по ссылке и `/l`, одинаково для анонима, подписчика и друга, без CTA. «Профиль не найден» — для несуществующего ника и Block. Нет приложения — тот же экран в браузере плюс одна ненавязчивая подсказка установки.
- **Настройки.** Поле ника с превью `@ник`, переключатель «не показывать в поиске», ошибки форм inline у поля.

## Cross-Story Dependencies

- 3.3–3.5 читают только через политику и DTO из 3.2: новое чтение добавляет кейс в `resolve`, а не свой запрос.
- Экран `/wishlist/:token` и чтение вишлиста — из Epic 2, поля брони — из Epic 5; контракт принимает их без переделки.
- «Добавить в друзья» / «Подписаться» и «Ожидает ответа» работают на механике Epic 4; до неё профиль даёт точки входа, но рёбра не создаёт.
- Даты в профиле — Epic 7 (своя видимость); Epic 3 не задаёт их правила.
- Смена ника влияет на все `/u`-ссылки, поэтому профиль и поиск идут через `nickNormalized`; ссылка вишлиста от ника не зависит, её копирование — Epic 2, Epic 3 отвечает за неизменность `publicToken`.
- `ContactMatch` (Epic 8) даёт право на `PUBLIC` в профиле, но не создаёт подписку и не меняет поиск.
