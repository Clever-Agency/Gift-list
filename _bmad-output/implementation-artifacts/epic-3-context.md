# Epic 3 Context: Обнаружение и открытие вишлиста

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Пользователь находит человека по нику или имени и открывает его вишлист в приложении или по публичной ссылке. По ссылке аноним сразу видит открытые желания, а после входа для брони возвращается к подтверждению в вишлисте. Единая политика видимости определяет состав выдачи и защищает скрытые данные.

## Stories

- Story 3.1: Смена ника в настройках
- Story 3.2: VisibilityPolicy и DTO доступа
- Story 3.3: Публичная ссылка
- Story 3.4: Профиль
- Story 3.5: Поиск пользователей и «скрыть из поиска»

## Requirements & Constraints

- **Ник.** 3–24 символа `[a-z0-9_]`, уникальность без учёта регистра, превью `@ник`. Правка в `/profile`. После смены старый `/u/{ник}` недоступен, `List.publicToken` сохраняется. Для занятого ника ошибка у поля.
- **Видимость.** `SECRET` видит владелец, `FRIENDS` — владелец и принятые друзья. `PUBLIC` также видят подписчики, зрители с `ContactMatch` и обладатели ссылки, включая анонимов. Архив видит владелец. Количество и названия скрытых желаний отсутствуют в выдаче и превью.
- **Публичная ссылка.** В браузере аноним видит имя владельца и только `PUBLIC`. Вошедший по доступной ссылке переходит на `/wishlist/:token`. Карточка желания на серверной странице ведёт на `/l/:token/:giftId`, где действует та же видимость. Вход или регистрация после «Куплю сам» возвращает в вишлист с подтверждением брони выбранного желания. Дружба по `/l/*` не создаётся.
- **Профиль.** У доступного профиля видны имя, ник и аватар с инициалами. Посторонний видит действия дружбы и подписки при пустой выдаче желаний. ДР без года, пол, страну и «Обо мне» владелец видит всегда. Принятые друзья видят их при включённом у владельца переключателе. Личные даты имеют собственную видимость. Карточка желания ведёт на `/gifts/{id}`.
- **Поиск.** Точное совпадение и префикс ника, нечёткое совпадение имени с лимитом. Скрытый из поиска пользователь исключён из выдачи, прямые ссылки подчиняются общей политике. Пустая выдача показывает пустое состояние.

## Technical Decisions

- **Единая политика.** Чтения профиля, ссылки и API используют `VisibilityPolicy`. Успешный ответ списка содержит `access: "gifts"` и разрешённые карточки. Поля брони зависят от роли. Владелец получает `OPEN` вместо `RESERVED`, без признаков брони.
- **HTTP 404.** Неизвестный, невалидный или недоступный адрес и блокировка в любую сторону дают неразличимый ответ. Next.js вызывает `notFound()` на исходном URL с общим каркасом, локализованным текстом, футером и `noindex`. Это распространяется на недоступное желание по публичной ссылке. API возвращает HTTP 404 с `{ ok: false, code: "NOT_FOUND", message }` без подробностей причины.
- **Один домен.** Next.js обслуживает серверные страницы и API. Веб-сборка Expo обслуживает `/wishlist/:token` и экраны приложения. Возврат через `?next=` принимает относительный путь того же домена. Публичные ссылки на вишлист и желание сейчас открываются в браузере. Системное открытие в установленном приложении по App Links и Universal Links запланировано отдельной поставкой Раунда 1 по CLE-108 (D-65).
- **Язык и рендер.** Серверная страница использует общие компоненты Tamagui и передаёт CSS в первом HTML. Язык из `Accept-Language` с резервом `ru`; `lang` отражает выбранный язык, ответ содержит `Vary: Accept-Language` или `Cache-Control: private`. В поиске `normalizeForSearch()` нормализует регистр, NFC и `ё → е`, сохраняя различие `й` и `и`.
- **Тесты видимости (AD-15).** Аноним видит только `PUBLIC` и не получает число остальных желаний. Подписчик по нику не получает `FRIENDS`. Блокировка с валидным токеном неотличима от отсутствующего списка. Регистрация по `/l/*` не создаёт дружбу.

## UX & Interaction Patterns

- В публичном вишлисте имя владельца — заголовок `h1`, ниже ник и карточки желаний в адаптивной сетке. Пустой доступный вишлист показывает «Пока нет открытых желаний». Недоступный список показывает «Список не найден», недоступный профиль — «Пользователь не найден». Превью публичной ссылки содержит имя владельца и бренд, без названий и фото желаний.
- На публичной странице единичного открытого желания ссылка «Куплю сам» с `aria-label`, содержащим название желания, ведёт к подтверждению брони в приложении. Без сессии этому предшествует вход или регистрация.

## Cross-Story Dependencies

- Публичная ссылка, профиль и поиск используют правила доступа и договорённости о данных из 3.2. Копирование неизменной ссылки относится к эпику 2, бронь — к эпику 5.
- Дружба, блокировка и подписка приходят из эпика 4. Личные даты управляются эпиком 7. Сопоставление контактов появляется в 8.1 и даёт доступ к `PUBLIC` без создания подписки.
