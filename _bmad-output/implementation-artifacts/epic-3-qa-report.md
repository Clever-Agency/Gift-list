| История | Независимый результат на staging | Дополнительные доказательства |
|---|---|---|

| 3.2 · Видимость | Владелец получил `PUBLIC`, `FRIENDS`, `SECRET`, друг — `PUBLIC` и `FRIENDS`, подписчик по нику — `PUBLIC`, посторонний по нику — пустой список, аноним по ссылке — `PUBLIC`. Успешный ответ содержит `access: "gifts"`. Блокировка в обе стороны закрыла профиль. Для недоступного списка по токену и профиля получены те же статус, JSON и заголовки приложения, что для неизвестных адресов. Из сравнения исключены динамические заголовки транспорта и CDN. Контроль путей чтения связывает список, профиль и карточку с общей политикой видимости. |
| 3.3 · Публичная ссылка | Первый HTML списка содержал имя владельца, `PUBLIC`, CSS и `lang="ru"` при неподдерживаемом языке. Ответ имел `Cache-Control: private`. Превью не содержало названий желаний. Карточка ведёт на серверную страницу одного желания. «Куплю сам» у `SINGLE` передал выбранное желание через маршрут вишлиста, регистрация вернула тот же `next` и не создала дружбу. Вошедший получил 307 на веб-экран доступного списка или желания, друг получил `PUBLIC` и `FRIENDS` через API. Существующий пустой список и список только со скрытыми желаниями вернули 200 с пустым состоянием. Неизвестный и невалидный токен, неизвестное и недоступное желание и Block вернули 404 без перенаправления. На том же URL после `PUBLIC → SECRET` желание стало 404 для анонима и вошедшего. Заголовки документа различают ресурс («Список не найден» и «Желание не найдено») и сохраняют `noindex`. | Общий UI и футер подтверждены компонентными тестами и ранее полученным браузерным прогоном. Сценарий возврата из формы входа покрыт тестами и контрактом безопасного `next`. |
| 3.4 · Профиль | У постороннего — карточка и пустые желания, после подписки — только `PUBLIC` без «Обо мне». После принятия заявки — `PUBLIC` и `FRIENDS` с «Обо мне», `SECRET` скрыт. Выключение переключателя убрало «Обо мне» у друга. Владелец продолжил видеть это поле. Доступное желание открылось через API универсальной страницы, секретное вернуло 404. Block и неизвестный ник дали одинаковый ответ. | Тесты API покрывают правила для ДР, пола, страны и «Обо мне». Тесты экрана покрывают карточку, кнопки, 404 и переход на `/gifts/{id}`. Переданный браузерный прогон на `/u/qa_refresh_261126` подтвердил появление `PUBLIC` после подписки, затем `FRIENDS` и «Обо мне» после принятия заявки без ручной перезагрузки. `SECRET` оставался скрыт. |
| 3.5 · Поиск | Точный ник, префикс и нормализованное имя привели к тестовому профилю. «Алена» нашла «Алёна», «Маика» не нашла тестовую «Майка», запрос по заведомо несуществующему имени вернул пустой массив. После включения «Не показывать в поиске» аккаунт исчез из выдачи, прямые профиль и список остались доступны по политике. Названия желаний в поиске отсутствовали. | Тесты покрывают нормализованный поиск по подстроке имени, порядок совпадений, лимит в 20, пустое состояние и форму карточки результата. |

## Сквозной прогон и автоматика

- Независимо прошла цепочка запросов поиск → профиль → подписка → принятие заявки → чтение доступного желания. Отдельно проверены живое бронирование и снятие тестовой брони, Block и повторные запросы к тем же публичным адресам после изменения видимости. Обновление на открытом экране профиля и общий браузерный каркас 404 приняты по переданному браузерному прогону и тестам.
- Целевые локальные тесты прошли: **263 серверных в 17 файлах и 244 клиентских в 5 файлах**. Они покрывают политики, адаптер отношений, HTTP-маршруты и серверные представления публичных ссылок, поиск, смену ника и экраны приложения.
- Полный CI на push в `staging` для указанного SHA зелёный. Через GitHub Actions подтверждены `typecheck`, `lint`, полный `test`, `build`, gzip-бюджет, наличие standalone-выхода и отсутствие в нём `.env`, запуск сервера и отдельная проверка публичных 404. [Прогон CI](https://github.com/Clever-Agency/Gift-list/actions/runs/45853850182) · [Workflow](../../.github/workflows/ci.yml)

- Ранние записи об отсутствии маршрутов и заглушке отношений из 3.1–3.2 устарели. Смену ника, публичное чтение, дружбу, подписку и Block подтвердили запросы к staging. `contactMatch: false` сохраняется до 8.1. Доступ к `PUBLIC` при `ContactMatch` подтверждён автоматикой. Личные даты проверяются в эпике 7. [Отложенные работы](deferred-work.md)

Архив и лимит выдачи покрыты автоматическими сценариями с фикстурами, без ожидания архивирования по расписанию и создания более 20 пользователей на staging.
