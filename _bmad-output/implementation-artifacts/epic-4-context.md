# Epic 4 Context: Дружба, подписка, приглашение

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Эпик задаёт круг доступа к вишлисту: взаимную дружбу, подписку, приглашение по ссылке, удаление из друзей и блок. Без него желания «друзьям» некому показывать; разрыв отношений при этом сразу снимает видимость, не раскрывая скрытого и не ломая брони.

## Stories

- Story 4.1: Отправка Приглашения в друзья
- Story 4.2: Принятие и отклонение Приглашения
- Story 4.3: Друзья, подписки и заявки
- Story 4.4: Удаление из друзей
- Story 4.5: Блокировка и разблокировка
- Story 4.6: Подписка
- Story 4.7: Ссылка-приглашение `/i/:token`

## Requirements & Constraints

- Приглашение: без дубликатов pending, no-op при дружбе, запрещено при блоке. Принятие взаимно открывает «друзьям»; отказ удаляет приглашение и запрещает повтор 24 ч.
- Удаление из друзей сразу закрывает «друзьям» с обеих сторон — в профиле и по ссылке; новая дружба только через принятое приглашение.
- Блок: взаимная невидимость («не найдено» в обе стороны), рвёт дружбу и подписки, запрещает новые приглашения и подписки; разблокировка ничего не восстанавливает.
- Подписка без подтверждения даёт только «всем» — не «друзьям», не дни рождения и личные даты; снимает любая сторона.
- Регистрация по `/i` создаёт дружбу, по `/l` — нет; превью ссылки мессенджером не создаёт ничего.
- Скрытое не отдаётся, не считается и не объясняется. Всё работает на Android, iOS и в браузере.

## Technical Decisions

- Дружба — `Friendship(userLowId,userHighId)` UNIQUE, ожидание — направленный `FriendshipInvite`. Accept — одна транзакция: вставка Friendship и удаление всех приглашений пары; встречный pending принимается тем же протоколом. Reject/cancel пишет кулдаун пары 24 ч.
- Unfriend удаляет ребро и приглашения; Block дополнительно удаляет подписки в обе стороны и вставляет `Block`; проверка блока в начале чтения профиля или вишлиста даёт `not_found`. Ни один из них не снимает брони: потерявший видимость держатель видит только reservation card своего желания.
- `Subscription(subscriberId,targetId)` уникальна, без подтверждения, даёт ровно `PUBLIC`; `ContactMatch` подписку не создаёт.
- Видимость решает единая политика: `FRIENDS` — владелец и принятая дружба; `PUBLIC` — владелец, друзья, подписчики, ContactMatch, обладатель ссылки на вишлист. Ответ чтения — `access: gifts|not_found`.
- Один неизменяемый invite-token на пользователя, путь `/i/:token`; регистрация с ним создаёт дружбу в той же транзакции при отсутствии блока, вошедший подтверждает вручную.
- Слои UI → use-case → domain → db; приложение зовёт только `app/api/v1`, `/i` — серверный рендер. Мутации отвечают конвертом `{ok,data} | {ok:false,code,message,reason?}` с закрытым набором кодов. Списки — курсор по 15, поиск по всему набору через общую нормализацию.
- Тесты: блок с валидным токеном → not_found; unfriend при брони → reservation card; подписчик не видит FRIENDS и дат; `/i` создаёт дружбу, `/l` — нет.

## UX & Interaction Patterns

- «Друзья»: сегменты «Друзья · Подписки · Запросы» с badge входящих; входящие выше исходящих. Входящая — «Принять»/«Отклонить», исходящая — «Ожидает ответа» + «Отменить».
- В «Друзьях» — поиск по имени и @нику (`@` необязателен, регистр не важен), счётчик «N из M», при нуле «Никого не нашли по «…»»; подгрузка порциями по 15.
- «Подписки»: переключатель «Я подписан · Мои подписчики», действия «Отписаться» / «Убрать подписчика»; подписчик об удалении не узнаёт.
- Профиль и строки людей: один чип сильнейшего отношения, действия в «⋯»; у друга подписки нет. Подтверждение — только для unfriend, «Убрать подписчика» и блока, остальное сразу с toast; optimistic с откатом.
- Блок: confirm «Вы перестанете видеть друг друга, дружба и подписки удалятся. Его бронь ваших желаний останется»; разблокировка — в настройках.
- `/i/:token` — mobile first, серверный HTML: «{Имя} приглашает вас в друзья», «Принять приглашение» → регистрация с токеном, «У меня уже есть аккаунт» → вход; также «Это ваша ссылка», «Вы уже друзья», «Приглашение не найдено».
- Пустые состояния: «Пока нет друзей», «Вы ни на кого не подписаны», «Пока никто не подписан», «Запросов нет».

## Cross-Story Dependencies

- Внутри эпика: 4.2 опирается на протокол 4.1 (auto-accept), 4.3 показывает данные 4.1/4.2/4.6, 4.4 и 4.5 меняют те же ребра, 4.7 переиспользует транзакцию создания дружбы.
- Epic 1 — регистрация с токеном и `?next=`; Epic 2 — копирование ссылки-приглашения; Epic 3 — профиль, поиск и кнопки отношений; Epic 5 — reservation card; Epic 6 — доставка событий и заблокированные; Epic 7 — даты; Epic 8 — ContactMatch без дружбы и подписки.
