## Что сделано

Владелец получает неизменяемый `List.publicToken` в уже существующем ответе «Мой вишлист» — отдельный API не заводили.

Изменённые файлы:

- `packages/contracts/src/index.ts` — в вариант `listDataSchema` с `access: "gifts"` добавлено необязательное поле `publicToken: string`. В гейте `not_found` его быть не может. В JSDoc зафиксировано: поле приходит только владельцу, токен не зависит от ника (AD-6, A-26).
- `apps/web/src/actions/wishlist-read.ts` — `prisma.list.findUnique` теперь выбирает `publicToken`; в ответе `access: "gifts"` токен добавляется только когда зритель — владелец списка. Друзья, подписчики, аноним по ссылке и профиль по нику токен не получают.
- `apps/mobile/src/api/my-gifts.ts` — `fetchMyGifts()` прокидывает токен наружу: `MyGiftsResult` для `access: "gifts"` теперь содержит `publicToken: string | null` (`null`, только если сервер его не прислал; штатный ответ владельца всегда с токеном).
- Тесты:
  - `apps/web/src/actions/wishlist-read.test.ts` — владелец получает токен (в том числе при пустом списке), не-владелец — нет; проверен `select` запроса.
  - `apps/web/src/actions/my-gifts.test.ts` — use-case владельца содержит `publicToken`; обновлён ожидаемый `select`.
  - `apps/web/src/app/api/v1/me/gifts/route.test.ts` — HTTP-ответ `GET /api/v1/me/gifts` содержит токен, в том числе для пустого вишлиста; обновлены ожидания.
  - `packages/contracts/src/index.test.ts` — контракт принимает `publicToken` в `gifts` и отвергает его в `not_found` и нестроковое значение.
  - `apps/mobile/src/api/my-gifts.test.ts` — токен возвращается клиенту, в том числе при пустом списке; отсутствие токена даёт `null`.

## Как клиент читает `publicToken`

`getMyGifts` (`GET /api/v1/me/gifts`) → `readWishlist` → ответ `{ ok: true, data: { access: "gifts", gifts, publicToken } }`. На клиенте `fetchMyGifts()` возвращает `publicToken` в результате `access: "gifts"`. Экран «Мой вишлист» (`app/(app)/index.tsx`) сможет сохранить его в состоянии `ready` и собрать `https://{домен}/l/{publicToken}`; домен и сама кнопка копирования — следующие срезы (2.4.2+). Смена ника токен не меняет: `List` при обновлении ника не трогается.

Известное ограничение: аварийная ветка `getMyGifts`, когда у сессии вообще нет строки `List` (нарушение AD-6), по-прежнему отвечает пустым списком без токена — тогда `fetchMyGifts` вернёт `publicToken: null`.
