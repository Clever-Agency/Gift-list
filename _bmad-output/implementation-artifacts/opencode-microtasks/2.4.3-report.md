# Отчёт по микротаске 2.4.3 — CLE-49 / Story 2.4

Ветка: `evivanchikov/cle-49-story-24-kopirovanie-ssilki-na-vishlist` (продолжение 2.4.1 и 2.4.2).

## Что сделано

На экране «Мой вишлист» появилась кнопка «Скопировать ссылку»: она кладёт в буфер один URL `https://{домен}/l/{publicToken}` (AD-6) и показывает toast «Ссылка скопирована» — точный текст из `epics.md` (Story 2.4) и `EXPERIENCE.md` (микрокопирайт). Share-sheet не добавляли.

Изменённые и новые файлы:

- `apps/mobile/app/(app)/index.tsx`:
  - состояние `ready` теперь хранит и `publicToken` из ответа `fetchMyGifts()` (2.4.1); `null` — если сервер его не прислал;
  - обработчик `copyLink()` вызывает общий helper `copyWishlistShareLink(publicToken)`: успех — info-toast «Ссылка скопирована», ошибка — error-toast «Не получилось скопировать ссылку. Попробуйте ещё раз.»;
  - кнопка владельца вынесена в строку над сеткой справа (`DESIGN.md` → App → «Широкий экран»: «Добавить желание», «Скопировать ссылку»), на compact строка занимает всю ширину и переносится. Кнопка — `Button` из `@gift-list/ui` (`variant` по умолчанию `primary`, как в таблице Components: «Button primary → … Скопировать ссылку»), `testID="wishlist-copy-link"`;
  - «Добавить желание» осталось primary и показывается в той же строке, когда в списке есть желания; в пустом вишлисте единственная CTA пустого состояния не дублируется, а «Скопировать ссылку» доступна и там — делиться вишлистом можно до первого желания.
- `apps/mobile/src/platform/clipboard.ts` — веб-реализация: `navigator.clipboard.writeText`, при отказе или отсутствии API — резервный путь через скрытое поле и `document.execCommand("copy")` (так же поступает `expo-clipboard` в браузере). Отказ записи возвращает `false`, а не бросает исключение.
- `apps/mobile/src/platform/clipboard.native.ts` — телефон: `expo-clipboard.setStringAsync`, исключение платформы превращается в `false`.
- `apps/mobile/src/wishlist/copy-link.ts` — тонкий helper `copyWishlistShareLink(publicToken, origin?)` поверх готового `wishlistShareLink()` (2.4.2):
  - ссылка `null` (нет ориджина в конфигурации или пустой токен) — `failed`, в буфер ничего не попадает;
  - запись в буфер не удалась — тоже `failed`: пользователю один и тот же текст ошибки, потому что ссылки в буфере нет в обоих случаях.
- `packages/contracts/src/i18n/ru/app.json` — ключи в `app.myWishlist`: `copyLink` («Скопировать ссылку»), `copyLinkDone` («Ссылка скопирована»), `copyLinkFailed` («Не получилось скопировать ссылку. Попробуйте ещё раз.»). Других локалей в приложении пока нет, каталог один.
- `apps/mobile/package.json` + корневой `package-lock.json` — зависимость `expo-clipboard@~58.0.4` (версия из `expo/bundledNativeModules.json` для SDK 58, не `latest`).

## Поведение по критериям Story 2.4

| Критерий | Как выполнено |
| --- | --- |
| В буфере один URL `https://{домен}/l/{publicToken}` (AD-6) | `wishlistShareLink()` из 2.4.2; токен кодируется как один сегмент пути |
| Домен — из конфигурации (Q-2) | `getPublicWebOrigin()`: `EXPO_PUBLIC_WEB_ORIGIN`, иначе `EXPO_PUBLIC_API_BASE_URL` |
| Toast «Ссылка скопирована» | ключ `app.myWishlist.copyLinkDone`, info-тон |
| Смена ника token не меняет (A-26) | ссылка строится только из `publicToken`, ник не участвует |
| Share-sheet не требуется | не добавляли |
| Битая ссылка не копируется | при `null` от `wishlistShareLink()` — error-toast и никакой записи в буфер |
