### Каталог и загрузка (`apps/mobile`)

- `src/api/tags.ts`: `fetchTagCatalog()` читает `GET /api/v1/tags` через общий `apiRequest`, который уже ставит `Accept-Language` устройства. Ответ разбирается `tagCatalogSchema`; чужое тело — `invalid`, сеть — `network`.
- `src/ui/use-tag-catalog.ts`: `loading | ready | error`, повтор запроса; пустой готовый каталог остаётся `ready` с `[]` и тоже получает «Повторить», чтобы подхватить появившийся сид. Каталог не связан с выбранными тегами, поэтому его пустота или ошибка ничего не сбрасывает.

### Форма (`src/ui/gift-form.tsx`)

- `GiftFormValues.tags` — `GiftFormTag[]`: `{ catalogId, label }` для фиксированного и `{ text }` для своего. На провод уходит ровно один источник (`{ catalogId }` / `{ text }`).
- Начальные значения edit берутся из `GiftCard.tags`; подпись фиксированного тега — серверная. Перед отправкой подписи обновляются из текущего каталога, но идентичность остаётся `catalogId`.
- Фиксированные чипы строятся из каталога; выбранный фиксированный тег, которого нет в каталоге (ошибка, пустой каталог, удалённый id), остаётся видимым по сохранённой серверной подписи. Это не destructive reset.
- Свой тег: trim, непустой, ≤ 30 кодовых точек, без NUL (контракт), без дубля после trim. «Добавить тег» недоступна на пустом поле; негодный текст блокирует submit и объявляется. Недобавленный валидный текст при сохранении становится тегом, а не теряется.
- Удаление: повторное нажатие снимает фиксированный, крестик — свой. Удаление всех тегов даёт `[]`.
- Dirty: набор сравнивается без учёта порядка и подписи фиксированного тега; ключ — `JSON.stringify`, поэтому перевод строки в своём тексте не склеивает разные наборы. Недобавленный текст тоже делает черновик грязным.
- Ошибки: `tags`, `tags.N`, `tags.N.text`, `tags.N.catalogId` относятся к блоку тегов; у группы `aria-invalid`/`aria-describedby`, сообщение `role="alert"`. `catalogId`-ошибка говорит, что тега больше нет; текстовая — про длину/повторы. Ошибка своего тега — под полем.
- Состояния каталога: загрузка — подпись, ошибка — подпись и «Повторить», пустой — подпись и «Повторить»; поле своего тега доступно во всех состояниях.

## Ревью

Blind review (отдельный субагент без контекста) нашёл 16 пунктов. Проверено по коду; исправлено до коммита:

- `tags.N.catalogId` показывался фразой про длину/дубли — добавлена отдельная фраза «тега больше нет»; `tags.N.text` остаётся общей, потому что поле приходит плоской строкой;
- число 30 дублировалось в плейсхолдере и общей ошибке — переведено на `{max}`;
- NUL проходил клиентскую проверку и падал бы `VALIDATION` на сервере — добавлен `invalid` и `error.tagInvalid`;
- ошибка своего тега не сбрасывалась после удаления вызвавшего её тега — сбрасывается;
- ошибка блока не была связана с группой — добавлены `aria-invalid` и `aria-describedby`;
- «Добавить тег» была активна на пустом поле и не объявляла ошибку — кнопка недоступна, ошибка объявляется, `returnKeyType: done` убран;
- пустой каталог показывал «нет тегов» при видимом выбранном чипе — сообщение только при отсутствии чипов, у пустого каталога есть «Повторить»;
- ключ dirty-набора склеивал разные наборы переводом строки — `JSON.stringify`, тест на коллизию;
- мёртвая ветка `case "tags"` в `serverErrorField` — удалена;
- добавлены тесты: hook каталога, RESERVED с тегами, клавиатура `TagChip`, пустая кнопка, NUL, повторное добавление, `aria-describedby`.

Отклонено: «свой и фиксированный тег с одинаковым текстом неразличимы» — у фиксированного checkbox/галочка, у своего крестик; «`TagChip` допускает неполные пропсы» — внутренний вызов всегда передаёт нужное, расширение API сейчас не нужно.

Отложено: скелетон загрузки каталога (визуальное улучшение вне AC); глифы `×`/`✓` вместо иконок (нужна визуальная проверка платформ); активность полей во время сохранения — общее поведение формы, не следствие этого среза.

## Находки: предлагаемые fixup-микротаски (не реализованы)

### Настоящие дефекты / требуют решения

1. **F-2.5.6-1 (= F-2.5.5-2): лимит числа тегов не задан.** В AC и UX лимита нет («Несколько можно»); picker его не вводил. Тело до 32 КБ по-прежнему может создать много строк. Нужно продуктовое решение: максимум тегов и текст ошибки.
2. **F-2.5.6-2 (= F-2.5.5-3): теги у `CLOSED`.** AC молчит; сейчас набор меняется у любого статуса, как название. Нужно решение до Story 2.6/2.5.7: разрешать, запрещать или скрывать редактор.
3. **F-2.5.6-3: `tags.N` не привязывается к конкретному чипу.** Ошибка показывается блоком с причиной (`catalogId` vs текст), но номер элемента не разворачивается в чип: поле приходит плоской строкой. Для точечной подсветки нужен либо индекс в ответе с сохранённым порядком, либо сопоставление на сервере.
4. **F-2.5.6-4 (= F-2.5.3-1/F-2.5.4-2): сид не в deploy-path.** Пока `Tag` не засеян, picker честно показывает пустой каталог с «Повторить», но фиксированных тегов в проде не будет. Это деплой-вопрос, не дефект формы.
5. **F-2.5.6-5: нет проверки на реальной PostgreSQL.** Каталог и PATCH тегов проверены на моках; живая БД недоступна (продолжение F-2.5.4-3/F-2.5.5-6).

### Необязательные улучшения / открытые вопросы

6. **F-2.5.6-6: каталог не перезапрашивается при смене языка на лету.** Загрузка при монтировании; для текущего поведения приложения достаточно, но подписка на локаль не сделана.
7. **F-2.5.6-7: нет скелетона загрузки каталога.** Сейчас подпись, затем чипы — возможен скачок layout.
8. **F-2.5.6-8: `giftTagListSchema` не экспортирован, у `catalogId` нет max.** Форме не требуется: она собирает `GiftTagInput[]` и не валидирует весь список повторно. Max для id не выдумывался (F-2.5.5-8).
9. **F-2.5.6-9: порядок тегов на проводе — порядок выбора.** Серверный порядок показа всё ещё не определён (F-2.5.5-1); для карточки 2.5.7 нужно правило `sortOrder`/позиции.
10. **F-2.5.6-10: `×`/`✓` — текстовые глифы.** Нужна визуальная проверка, что шрифты обеих платформ их показывают; иначе заменить на иконки.
