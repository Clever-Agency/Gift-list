### Порядок тегов (`apps/web/src/domain/tag.ts`)

Согласованного порядка показа в документах не было: `EXPERIENCE.md` задаёт только «до трёх, дальше +N», `DESIGN.md` — внешний вид, а F-2.5.5-1/F-2.5.6-9 оставляли порядок открытым. Порядок каталога уже зафиксирован: `tags.ts`/`tag.ts` сортируют каталог по `slug` в кодовых единицах Unicode.

Итоговое правило (задокументировано в JSDoc `toGiftTags` и в `giftCardSchema`):

1. Фиксированные теги — первыми, по неизменному `slug` каталога в кодовых единицах Unicode (тот же порядок, что у `GET /api/v1/tags`). Одобренный ADMIN свой тег становится фиксированным и сортируется там же.
2. Свои теги — после фиксированных, по сохранённому тексту в кодовых единицах Unicode.
3. Локальная коллация (`Intl.Collator`) и переведённые подписи для сортировки не используются. Равные ключи недостижимы из-за `@@unique([giftId, tagId])`/`@@unique([giftId, customText])`; индекс — только стабильный tie-break.

`slug` добавлен в `select` тегов в `gifts.ts` и `wishlist-read.ts` и стал обязательным в `GiftTagRow.tag`; на провод по-прежнему уходят только `catalogId` и `label`, DTO не расширялся. Тест `toGiftTags` проверяет обратный порядок вставки (результат одинаков) и отличие от `Intl.Collator` на паре `iPhone`/`айфон`; тест use-case `createGift` проверяет порядок в ответе независимо от порядка строк.

## Ревью (blind review)

Отдельный субагент без контекста нашёл 18 пунктов. Проверено по коду; исправлено до коммита:

- «+N» был строкой интерфейса внутри `packages/ui` — вынесен в пропсы `moreLabel`/`moreAccessibilityLabel`, приложение передаёт переводы;
- свёрнутый чип не называл скрытые теги в карточке без `onPress` — добавлено доступное имя с подписями, покрыто тестом;
- `max` не проверял `NaN` — добавлен `Number.isFinite`, тест `max=1`;
- тесты сравнивали склеенный `textContent` — добавлены `testID` на чипы и проверки по элементам;
- не проверялся перенос ряда — добавлены `flexWrap=wrap`/`maxWidth=100%` (реальная раскладка остаётся на визуальную проверку);
- тест доступного имени использовал два тега — переведён на пять, скрытые подписи проверяются в `aria-label`;
- тест «без клиентских переводов» не мог упасть — фикстура использует `label: "подарок-сюрприз"` при `catalogId: "tag_dream"`;
- не было покрытия без `onPress`, `CLOSED` и наличия testID — добавлены сценарии;
- `slug` был необязателен с fallback на CUID — сделан обязательным, фикстуры и типы обновлены;
- фикстуры действий не проверяли slug-ветку — добавлен тест порядка в `createGift`;
- комментарий про независимость от вставки был сильнее кода — уточнён (уникальности, индекс только для стабильности);
- не было теста «кодовые единицы, не коллация» — добавлен;
- порядок не был описан в контракте — добавлен к `giftCardSchema`.

Отклонено как не стоящее правки в этом срезе: discriminated union для `variant` (внутренний вызов и так передаёт нужное), вынос общего shell чипа (рефакторинг без пользовательского эффекта), `role`/testID на слоте `tags` (слот принимает произвольный `ReactNode`, семантика у `TagChipList`), тест-хелпер `editLabel` (читает тот же JSON и те же плейсхолдеры, что мок).

Отложено: смена модели доступного имени всей карточки (действие-первым вместо фразы DESIGN) — существующее поведение 2.1/CLE-65, не следствие тегов; визуальная проверка `role="note"` на реальных скринридерах.

## Находки: предлагаемые fixup-микротаски (не реализованы)

### Настоящие дефекты / требуют решения

1. **F-2.5.7-1: доступное имя карточки начинается с действия.** Сейчас «Изменить «{title}». Теги: …»; DESIGN требует фразу «{название}, {цена}, {статус}, {теги}, {строка брони}, видимость {всем}». Это существующая модель 2.1/CLE-65, не следствие тегов; менять её нужно сразу для всех карточек и тестов, иначе имя одной и той же правки звучит по-разному. Предлагается отдельная задача по доступности карточки.
2. **F-2.5.7-2: фиксированные теги вытесняют свой за «+N».** При трёх фиксированных тегах свой тег всегда скрыт первым. Порядок «фиксированные первыми» выбран как порядок каталога; нужно продуктовое/UX-решение, резервировать ли слот под свой тег или показывать его иначе. В этом срезе правило не менялось.
3. **F-2.5.7-3: нет визуальной проверки.** Не проверены перенос ряда, длинный текст, высота чипа и «+N» на Android/iOS/вебе. Скриншоты в этой сессии недоступны.

### Необязательные улучшения / долги

4. **F-2.5.7-4: `role="note"` — веб-приближение для свёрнутого чипа.** Нужно подтвердить, что NVDA/VoiceOver/TalkBack читают `aria-label` с скрытыми тегами; если нет — добавить визуально скрытую сводку.
5. **F-2.5.7-5: дублирование рамки чипа в трёх ветках `TagChip`.** Вынос общего shell уменьшит риск расхождения card/picker; сейчас отклонено как рефакторинг вне среза.
6. **F-2.5.7-6: `slug` теперь обязателен в `GiftTagRow`.** Любой новый select тегов должен его включать; общий select-фрагмент (F-2.5.5-10) снизит риск.
7. **F-2.5.7-7: нет интеграционного теста порядка на PostgreSQL.** Порядок проверен на моках; продолжение F-2.5.5-6/F-2.5.4-3.
8. **F-2.5.7-8: лимит числа тегов и теги у `CLOSED`.** Не вводились (F-2.5.6-1/-2): нужны продуктовые решения, чтобы не менять поведение задним числом.
