## Поведение

1. Аноним с валидным токеном уходит на `/login` ровно с `next=/wishlist/{token}` и не вызывает API списка. `next` собран из проверенного сегмента, а не из pathname/query/`Referer`.
2. Битый сегмент (пустой, >128, `/`, `\`, `?`, `#`, `%`, управляющие символы, `.`/`..`, лишние сегменты) не уводит на вход, не вызывает API и показывает «Список не найден».
3. Вошедший читает через существующий `apiRequest`: cookie на вебе, bearer на телефоне, `Accept-Language` уже ставит клиент. Сервер применяет `VisibilityPolicy`; друг получает PUBLIC и FRIENDS, клиент ничего не пересчитывает и не читает `gift.visibility`.
4. `ready`: `h1` — имя владельца, ниже `@nick`, сетка карточек. Пусто — точная фраза «Пока нет открытых желаний»; `not_found` — точная фраза «Список не найден». Второй формулировки для Block нет.
5. Ошибка сети — «Не получилось загрузить. Проверьте сеть.» + toast + «Повторить»; ответ не по контракту — общий текст ошибки. Сессия истекает при чтении — `signOut` и вход с тем же `next` и `reason=session_expired`.
6. `ready` хранит токен ответа: если маршрут переиспользуется с другим токеном, экран показывает skeleton, а не список прошлого владельца, пока не придёт новый ответ.

## GOAL B: причина и исправление корневой сборки

Падение было окружением, а не страницей 3.3.2:

- `D:\Clever\Gift-list-story-33\node_modules` был junction на `D:\Clever\Gift-list\node_modules`.
