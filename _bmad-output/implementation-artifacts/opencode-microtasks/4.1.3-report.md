## Что сделано

- `apps/mobile/app/u/[nick].tsx`:
  - «нет связи» и не свой профиль — кнопка «Добавить в друзья»;
  - исходящий pending — только chip «Ожидает ответа», без второй отправки и без отмены;
  - входящий pending — chip «Зовёт в друзья» и кнопка «Принять приглашение», которая вызывает тот же `POST /api/v1/u/:nick/invite`;
  - после `FRIENDS_CREATED`/`ALREADY_FRIENDS` — toast «{имя} теперь в друзьях», chip «Друзья» и перечитывание профиля;
  - дружба — только chip «Друзья»; свой профиль — только chip «Это вы»;
  - `not_found` — «Пользователь не найден.» без кнопки.
- `apps/mobile/src/api/friend-invite.ts` — один вызов invite API для первой заявки и принятия входящей; ник нормализуется `profileRoute`, тело не отправляется, ответ проверяется `friendInviteDataSchema`. Отдельного accept-эндпоинта Story 4.2 нет.
- `apps/mobile/src/api/profile.ts` — `relationship` из ответа 4.1.2 попадает в `ProfileResult`; при отсутствии поля берётся `NONE`, дружба из карточек не выводится.
- `packages/contracts/src/i18n/ru/app.json` — канонические строки `app.profile.relationship.*` и точка в `notFound` по EXPERIENCE.
- `packages/ui/src/relationship-chip.tsx` — статический chip отношения на токенах DESIGN; кнопки — общий `Button` с зоной касания 48 и `aria-label`, равным подписи.
- Optimistic: chip меняется сразу, при сети/отказе возвращается прежнее отношение и показывается «Нет сети. Попробуйте ещё раз.»; 401 уходит на вход с прежним безопасным `next`.
- Защита от гонок: `inviteInFlight` не даёт отправить второй запрос по тому же нику; `requestSeq`/`nickRef` отбрасывают ответ старого запроса; `pendingNick` и `toast.nick` привязаны к нику, поэтому смена маршрута не оставляет состояние предыдущего человека.
- Видимость желаний экран по-прежнему не фильтрует: рисуется только то, что вернул сервер. Протокол R1 и API 4.1.2 не менялись.

## Ограничения и остаточные риски

- Живая PostgreSQL и полный `npm run build` не запускались по условию микрозадачи; экран проверен на моках API и контрактов.
- Принятие входящей заявки optimistic: chip «Друзья» появляется до ответа сервера и откатывается при сети/отказе. Это соответствует общему правилу optimistic из EXPERIENCE; серверный ответ и перечитывание профиля остаются источником истины.
- После дружбы профиль перечитывается отдельным запросом. Если параллельно уже идёт другое чтение профиля, последний ответ сервера и будет показан; отдельной транзакции на клиенте нет.
- Для входящей заявки до нажатия показан канонический chip «Зовёт в друзья» из таблицы «Отношение → статус и меню» EXPERIENCE; в перечне микрозадачи он не назван отдельно, но новая строка не выдумывалась.
- Выбор `NONE` при отсутствии поля `relationship` — безопасный дефолт для старого/неполного ответа; сервер 4.1.2 всегда присылает поле для профиля.
