## Что исправлено

`apps/mobile/app/u/[nick].tsx`, `relationshipAction`: после отката оптимистичного состояния ветка отказа теперь распознаёт `code: "RATE_LIMITED"` + `reason: "INVITE_COOLDOWN"`.

- При целом `params.hours ≥ 1` toast показывает каталожную строку `common("errors.reason.INVITE_COOLDOWN", { hours })` — «Можно снова через {hours} ч».
- Профиль перечитывается существующим `setAttempt`, поэтому серверные `inviteCooldown.hours` и `rejected` заменяют устаревшее локальное состояние: отправитель получает чип «Отклонено», отклонивший — выключенную кнопку и часы.
- Рефетч выполняется по самому `reason`, даже если `hours` пришёл нечисловым; в этом случае текст остаётся общим `RATE_LIMITED`, но экран всё равно синхронизируется.
- Остальные исходы не менялись: сеть — прежний откат и «Нет сети. Попробуйте ещё раз.», кривое тело — общий текст, 401 — выход на вход, 404 — `missing`, прочие коды — `errors.code.*`. Защита от одновременного нажатия (`inviteInFlight`, `pendingNick`, `requestSeq`) не тронута.
- Домен, протокол, контракты, миграции, каталог переводов и Choice не менялись.

`apps/mobile/src/session/profile-screen.test.tsx`: 7 новых детерминированных тестов (1 + 1 + 1 + 4 параметризованных):

| Сценарий | Проверка |
|---|---|
| Устаревшее «нет связи», сервер уже в паузе, зритель — отправитель | 1 POST, 2 чтения профиля, toast «Можно снова через 7 ч», чип «Отклонено», кнопки нет, общий текст лимита не показан |
| То же, зритель — отклонивший | 2 чтения профиля, toast и подпись «Можно снова через 24 ч», кнопка есть и `aria-disabled="true"`, слова «Отклонено» нет |
| Другой `RATE_LIMITED` без reason | общий текст «Слишком много попыток», 1 чтение профиля, кнопка возвращается |
| `INVITE_COOLDOWN` с `hours` = `undefined`, `0`, `2.5`, `"7"` | общий текст, но профиль всё равно перечитывается (2 чтения), кнопка возвращается |

Проверка toast идёт по `[data-testid="toast-host"]`, а не только по общему `document.body.textContent`.
