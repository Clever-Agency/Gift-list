# F4 — гонки FK/unique каталога в конверте AD-12

Дата: 2026-11-06. Ветка: `evivanchikov/story-24-25-auth-fixups`, база — `1bba346` (отчёт F3). Код F4: `1a00255`. Статус: готово, на ревью.

## Что сделано

`apps/web/src/actions/gifts.ts` — обе гонки тегов теперь отвечают конвертом AD-12 вместо необработанного исключения Prisma:

| Сценарий | Prisma | Ответ |
|---|---|---|
| Тег каталога удалён между проверкой `tagId` и вставкой `GiftTag` | P2003 | `VALIDATION`, `field: "tags"` — тот же ответ, что у неизвестного `catalogId` |
| Параллельная замена набора тегов нарушила уникальный индекс `GiftTag` | P2002 | `CONFLICT`, `field: "tags"`, диагностический `message` |
| Сбой FK на другую таблицу (например, `Gift.listId`) | P2003 | пробрасывается, как раньше |
| Любая другая ошибка Prisma | — | пробрасывается, как раньше |

- `constraintDetail()` собирает `modelName`/`field_name`/`target` из `meta`; `tagWriteFailure()` применяет маппинг только для кода P2003/P2002 и только если ограничение называет тег (или `meta` отсутствует). Так исчезнувший список не выдаётся за ошибку тегов.
- `createGift`: вложенный `prisma.gift.create` обёрнут в `try/catch`; маппинг включается только при непустом наборе тегов. Вложенный write остаётся одним statement — при ошибке подарок не создаётся.
- `updateGift`: маппинг добавлен в существующий `catch` после `MissingCatalogTagError` и работает только при `tags !== undefined`. Замена тегов по-прежнему идёт одной транзакцией: обновление полей, `deleteMany`, `createMany` и перечитывание карточки откатываются вместе.
- JSDoc `fixedTagsExist` уточнён: P2003 на create теперь отображается в конверт.

Новых кодов ошибок, `reason`, лимитов тегов, ограничений для `CLOSED`, изменений PRD/эпиков/архитектуры нет; `INTERNAL` не вводился. Правила статуса/eligible и порядок тегов не менялись.

## Решения и источники

- `fixup-queue.md` Q-10 и `fixup-plan.md` F4 требуют отобразить гонки в существующие `VALIDATION`/`CONFLICT` AD-12; закрытый набор кодов AD-12 не расширялся. `field: "tags"` — имя поля формы по AD-12, клиент уже группирует ошибки `tags`/`tags.N` в блок тегов.
- P2003 — невалидный вход (тега больше нет), поэтому `VALIDATION`; P2002 — конфликт с параллельной записью, поэтому `CONFLICT`. Оба ответа воспроизводят поведение соседних веток: неизвестный `catalogId` уже даёт `VALIDATION` с `field: "tags"`, а конкурентные изменения в других use-case дают `CONFLICT`.
- Закрытие каталога от удаления при связях (`onDelete: Restrict` уже стоит) и модерация тегов остаются Story 10.2 — в F4 не кодировались.
- `bmad-correct-course`/`bmad-architecture` не запускались: продуктовые документы не менялись. Q-34 не трогался.

## Ограничения

- Живая/общая БД не использовалась; `migrate`, `migrate deploy`, `db push`, `db seed` и deploy не запускались. Поведение P2003/P2002 проверено на моках Prisma; реальные гонки на PostgreSQL остаются за F5/Q-04.
- Формат `meta` у Prisma проверен только типами и тестовыми фикстурами; при отсутствии `meta` ошибка трактуется как ошибка тегов, потому что маппинг вызывается только после отправки строк тегов.
- Клиент не менялся: `CONFLICT` показывается существующим текстом `common.errors.code.CONFLICT` с привязкой к блоку тегов; новых строк интерфейса нет.
- `apps/web/AGENTS.md` (правка `next dev`/build), prompt/log/keyword-файлы и `fixup-queue.md` не индексировались; очередь обновлена и оставлена unstaged.
- F7 и последующие пункты не начинались.
