## Что изменено

- `packages/ui/src/tag-chip.tsx`
  - Новый тип `TagChipError` (`{ id, message }`) и необязательное поле `error` у `TagChip`.
  - У фиксированного тега `aria-invalid`/`aria-describedby` ставятся на `checkbox`, у своего — на кнопку-крестик (единственный фокусируемый элемент чипа). `message` уходит в `accessibilityHint` — на телефоне `aria-describedby` не работает.
  - Сам текст ошибки не дублируется: id ведёт на единственный узел, который рисует форма.
  - `variant="card"` ошибку игнорирует; визуальный вид чипа не менялся.
- `packages/ui/src/index.ts` — `TagChipError` экспортируется рядом с остальными типами чипа.
- `apps/mobile/src/ui/gift-form-validation.ts`
  - Чистая `tagErrorKey(field, submitted, selected)`: путь `tags.<N>[.<ключ>]` → идентификатор чипа из порядка последней отправки или `null` для общей ошибки. Суффикс `.text`/`.catalogId` не важен; номер вне отправки, пустая отправка и удалённый тег дают `null`.
- `apps/mobile/src/ui/gift-form.tsx`
  - `submittedTagKeys` запоминает `giftTagKey` тегов ровно в том массиве, который ушёл в `onSubmit` (включая свой тег, добавленный при отправке), и обновляется только при реальной отправке.
  - При `serverError.field = tags.N…` ошибка вешается на найденный чип. Группа `role="group"` получает `aria-invalid`/`aria-describedby` только когда сопоставление не удалось (групповая ошибка).
  - Данные, порядок выбранных тегов, коды, тексты, лимиты и сервер не менялись. Сервер уже отдавал индекс через `firstIssueField`.
- Тесты

  - `apps/mobile/src/ui/gift-form-validation.test.ts`: сопоставление индекса с отправкой, суффиксы, порядок/идентичность, удалённый тег, выход за диапазон, нечисловые пути.
  - `apps/mobile/src/ui/gift-form.test.tsx`: индекс считается по порядку отправки, а не по порядку каталога; свой тег, добавленный при отправке; снятие и повторный выбор; удаление отвергнутого тега → общая ошибка без чужого чипа; номер вне набора; группа не невалидна при точечной ошибке.

## Ограничения

- Реальная проверка NVDA, VoiceOver и TalkBack **не выполнялась**: проверены только DOM-атрибуты (`aria-invalid`, `aria-describedby`) и косвенно `accessibilityHint`. Фактическое чтение на устройствах не подтверждено.
- Визуальной пометки ошибочного чипа нет (цвет/иконка): `DESIGN.md` не задаёт отдельный вид, а общий текст ошибки уже виден. Визуальный проход остаётся за Q-05.
- Невалидный чип не прокручивается в видимую зону при длинном каталоге — вне F8, визуальная проверка Q-05.
- Свои теги рисуются отдельным рядом вне подписанной группы: при **групповой** ошибке связь с их рядом не появляется (поведение было до F8). Точечная ошибка своего тега связана с его кнопкой удаления.
- Дубль тега приходит из контракта как `tags` без индекса и остаётся групповой ошибкой; общий текст `error.tags` («до 30 символов и без повторов») не менялся — новые тексты и контракт запрещены условием.
- Реальная БД, миграции, сиды, деплой и Vercel не использовались. `main`, push, PR и merge не трогались. Одноразовая PostgreSQL не поднималась.
