Дата: 2026-11-06. Ветка: `evivanchikov/story-24-25-auth-fixups`, база `057805d` (стек CLE-62/CLE-52/CLE-49). Источник находок — `fixup-queue.md`; дубликаты сведены в один пункт, исходные ID сохранены в скобках. Статус ведётся в `fixup-queue.md`, этот файл — порядок работ и границы.

Правила пакета:

- Один fixup — один логический коммит; без `main`, push, PR и merge. Каждый пункт заканчивается отчётом и готов к ревью, но не закрывает весь пакет.
- Никаких новых продуктовых лимитов, кодов ошибок, изменений PRD/эпиков/архитектуры. Если пункт требует продуктового решения, он остаётся в разделе «Требует решения» и не кодируется.
- Не запускать `migrate`/`migrate deploy`/`db push`/`db seed` против живой или общей БД, не читать секреты, не менять настройки Vercel. Все проверки — офлайн или на одноразовой локальной PostgreSQL.
- Перед каждым пунктом сверять фактическое состояние `main`-ветки и очередь: часть находок могла быть закрыта соседними задачами.

## F1 — инициализация каталога в деплое (Q-01)

**Проблема.** Поддерживаемый путь выката — `prisma migrate deploy` (`README.md`, раздел «Деплой вне Vercel», и `AGENTS.md`). Он применяет миграции, но не запускает `prisma db seed`; в `package.json`, `apps/web/package.json`, `apps/web/vercel.json` и CI шага сида нет. На чистой БД после выката `Tag` пустая, `GET /api/v1/tags` отдаёт `{ tags: [] }`, фиксированные теги выбрать нельзя.

**Решение.** Добавить отдельную аддитивную data-миграцию `20261106120000_fixed_tags_catalog`, которая идемпотентно вставляет стартовые строки по `slug`. Не менять уже существующую `20261105120000_tags`: она могла быть применена удалённо. Не добавлять шаг сида в общий CI/Vercel: это широкое изменение поведения деплоя, а миграция проходит тем же поддерживаемым шагом.

**Границы.** Существующие строки не удаляются и не перезаписываются: при конфликте по `slug` существующие подписи выигрывают, недостающие языковые ключи добавляются. `db seed` остаётся идемпотентным для разработки/ремонта. Схема, API и продуктовые документы не меняются.

**Проверка.** Тест читает SQL миграции и сверяет slug/подписи с `FIXED_TAGS`; проверяет `ON CONFLICT ("slug")`, сохранение существующих подписей и отсутствие `DELETE`/`TRUNCATE`/`DROP` для `Tag`. Реальное применение — только в F5 на одноразовой БД.

**Порядок выката.** Сначала `prisma migrate deploy` (применяет и структурную, и data-миграцию), затем старт сервера. Повторный deploy безопасен: миграция уже в истории, а её SQL идемпотентен. Если нужно добрать новые языковые ключи вручную, `prisma db seed` сливает их, не затирая правки ADMIN.

## F2 — сбой БД каталога (Q-02)

`getTagCatalog` ловит любую ошибку и возвращает `NOT_FOUND`, поэтому клиент показывает «Не найдено» вместо сетевой ошибки. Использовать уже разрешённую конвенцию: при сбое инфраструктуры — 500 без конверта AD-12 (см. `deferred-work.md`, пункт про Story 1.4), клиент трактует не-конверт как `network`. Новый код `INTERNAL` не вводить. Тесты: ошибка Prisma → ответ не `NOT_FOUND`, лог сохранён, успешный путь не изменился.

**Сделано (2026-11-06).** `getTagCatalog` больше не превращает сбой в `NOT_FOUND`, а пробрасывает исключение; `GET /api/v1/tags` логирует его один раз и отвечает пустым телом 500 с `Cache-Control: private, no-store` и `Vary: Accept-Language`, без конверта AD-12 и без кода `INTERNAL`. Сбой контракта (невалидная строка) идёт тем же путём. Пустая таблица по-прежнему `200 { ok: true, data: { tags: [] } }`; локаль, порядок по `slug` и happy path не менялись. Focused-тесты — `tags.test.ts`, `route.test.ts`, `api-v1.test.ts`; спека — `spec-f2-catalog-db-error.md`; отчёт — `fixup-F2-report.md`. Реальная БД не использовалась, миграции/сиды не запускались.

## F3 — доступное имя карточки (Q-03)

Сейчас нажимаемая карточка читается как «Изменить «{title}». Теги: …», а `DESIGN.md` требует «{название}, {цена}, {статус}, {теги}, {строка брони}, видимость {всем}». Нужно единое имя для всех нажимаемых карточек (включая Story 2.1/CLE-65): все теги, включая скрытые за «+N»; без `onPress` общего имени нет, скрытые подписи не остаются только в имени чипа «+N». Менять строку и тесты, не трогая визуальный порядок чипов. Проверка диктором — отдельный ручной пункт Q-06.

**Сделано (2026-11-06).** `apps/mobile/src/ui/gift-card.tsx` собирает одно имя кнопки: название, цена, статус, все теги в порядке показа (включая скрытые за «+N»), строка брони и «видимость {значение}»; пустые части опускаются, разделитель — запятая. Визуальный ряд и порядок чипов не менялись, `onPress` на ряд и чипы не добавлялся. Ключ `app.gift.visibilityInCardName` — в `packages/contracts/src/i18n/ru/app.json`; мёртвые строки действия удалены. `packages/ui/src/wish-card.tsx` больше не подставляет одно название вместо полной фразы. Focused-тесты: `gift-card.test.tsx` (точная фраза, обе фазы `ownerAction`, пустые части, обновление, порядок чипов), `wish-card.test.tsx`, сессионные тесты списка и потока. Спека — `spec-f3-card-accessible-name.md`; отчёт — `fixup-F3-report.md`. Проверка NVDA/VoiceOver/TalkBack не выполнялась — Q-06; действие «Изменить» в имени не звучит — Q-34. F4 не начат.
