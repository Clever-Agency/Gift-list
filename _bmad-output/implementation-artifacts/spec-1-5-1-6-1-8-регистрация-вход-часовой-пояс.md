## Intent

**Problem:** Регистрация всё ещё создаёт два `List` с колонкой `type`, экраны входа и регистрации в Expo — заглушки, сессия клиента не восстанавливается, `User.locale` и `User.timeZone` не пишутся. Истории 1.5 (CLE-37), 1.6 (CLE-38) и 1.8 (CLE-39) — один заход: общие экраны auth.

**Approach:** Один use-case регистрации через `POST /api/v1/register`: пользователь, credential-аккаунт и ровно один `List` с `publicToken` в одном вложенном `create`, затем сессия Better Auth. Вход и выход — `POST`/`DELETE /api/v1/session` с одинаковым ответом на неверный пароль и неизвестный email. Пустой `User.timeZone` клиент заполняет один раз IANA-поясом устройства. Клиентская часть 1.4 берётся только в объёме этих историй.

## Boundaries & Constraints

**Always:**
- Конверт AD-12. `message` — английская диагностика, UI его не показывает. Занятый email: `VALIDATION`, `reason: EMAIL_TAKEN`, `field: email`, текст каталога и ссылка «Войти». Занятый ник: `NICK_TAKEN`, `field: nick`. Оба заняты — только email.
- Ровно один `List` на пользователя: колонки `type` и enum `ListType` нет, API второго списка нет. `publicToken` — CUID2, UNIQUE, не меняется. Боевых данных нет; миграция схлопывает возможные dev-дубли.
- `User.locale` при создании = `negotiateLocale(Accept-Language)`, иначе `ru`. Клиент шлёт `Accept-Language` в каждом запросе.
- `?next=` — только относительный путь (`/…`), иначе `/`. `/l/:token` → `/wishlist/:token`, `/i/:token` → `/invite/:token` (путь `/i` принадлежит Next). Дружба по приглашению не создаётся (Story 4.7).
- Вход: один и тот же `UNAUTHENTICATED` без `field` и `reason` для неизвестного email и неверного пароля. Сессия: браузер — cookie (токен в JS не кладём), Android/iOS — `set-auth-token` только при `expo-origin` / `origin: giftlist://`, хранение в SecureStore, дальше `Authorization: Bearer`. Выход удаляет сессию этого клиента и cookie, клиент стирает токен.
- `User.timeZone` nullable: `null` — ещё не сообщали. Первый `PUT /api/v1/me/time-zone` пишет валидный IANA или `UTC`. Уже записанный пояс, включая `UTC`, не перезаписывается. Клиент: `expo-localization` на Android/iOS, `Intl` в браузере.
- `disableSignUp` остаётся: сырой `/api/auth/sign-up` закрыт. `GET /api/v1/me` отдаёт `timeZone`.
- Тексты UI — ключи каталога `ru`. Ник 3–24 `[a-z0-9_]`. Пароль 8–128. Телефон, ДР и пол не спрашиваются.

**Never:**
- Форма сброса пароля (Story 1.7), кроме ссылки «Забыли пароль» на заглушку `/forgot`. Экран «Мой вишлист» со желаниями (Story 2.1). Дружба, OAuth, SMS. Правки PRD, эпиков, спайна. Секреты и `.env`. Общий UI-пакет. Импорт `apps/web` из `apps/mobile`.

## Design Notes

Prisma nested `create` пользователя, аккаунта и списка — одна транзакция. `accountId` равен `user.id`, иначе `signInEmail` не найдёт credential. После создания сессия открывается тем же `signInEmail`, что и вход: неизвестный email и неверный пароль внутри Better Auth дают один `INVALID_EMAIL_OR_PASSWORD`, наружу уходит только наш конверт.

`User.timeZone = null` читатели пояса до Story 5.1 трактуют как UTC. Записанный пояс — единственный источник.
