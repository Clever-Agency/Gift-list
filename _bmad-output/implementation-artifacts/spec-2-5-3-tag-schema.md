## Intent

**Problem:** Story 2.5 требует хранить на желании фиксированные теги «мечта», «нужно сейчас», «когда-нибудь» и свой текст ≤ 30 символов. В схеме Prisma тегов нет, поэтому каталог, карточка и модерация Story 10.2 не на что опереться. Свой тег должен быть виден с желанием, но не попадать в агрегаты до одобрения ADMIN (AD-22, AD-27).

**Approach:** добавить каталог `Tag` (`slug` + `labels jsonb` на каждый язык `SUPPORTED_LOCALES`) и связь `GiftTag` с необязательной ссылкой на каталог, своим текстом и явным признаком допуска в агрегаты. Проверить в репозиторий SQL-миграцию, сгенерированную офлайн через `prisma migrate diff`, и идемпотентный сид трёх стартовых тегов через upsert по `slug`. Не добавлять endpoint каталога, выбор тегов в форме, UI модерации и изменения PRD/эпиков/архитектуры.

## Boundaries & Constraints

**Always:** каталог — данные БД, а не JSON-каталог; `Tag.slug` неизменяем и уникален; `labels` содержит подпись для каждого языка из `SUPPORTED_LOCALES` (сейчас `ru`); сид идемпотентен по `slug` и не удаляет теги, добавленные ADMIN; свои теги не переводятся; фиксированные теги и одобренные свои допускаются в агрегаты, неодобренные — нет.

**Never:** не запускать `prisma migrate dev/reset/deploy`, `db push`, `db seed` и любые команды, подключающиеся к БД из `apps/web/.env*`; не менять `main` и ветку CLE-49; не трогать `package-lock.json`, версии Prisma и UI-слои.

## Implementation Notes

- Схема: `Tag` (каталог) и `GiftTag` (связь с желанием). В `GiftTag` — `tagId` для фиксированного тега, `customText VARCHAR(30)` для своего, `aggregateEligible` — явный допуск в агрегаты. Каталожные теги создаются с `aggregateEligible=true`; свой текст — с `false` до одобрения ADMIN (Story 10.2). Уникальность: один каталожный тег и один и тот же свой текст на желание.
- В миграции вручную добавлены CHECK-ограничения, которых Prisma не моделирует: `labels` — JSON-объект; у `GiftTag` есть хотя бы один идентификатор (`tagId` или непустой `customText`); `aggregateEligible` допускается только вместе с `tagId`.
- Сид: `apps/web/src/db/seed.ts`, точка входа `prisma db seed` (команда в `prisma.config.ts`). Upsert по `slug`: существующие подписи ADMIN сохраняются, недостающие языковые ключи добавляются из сида; повторный запуск не создаёт дублей и не удаляет теги, добавленные ADMIN. Прямой `node src/db/seed.ts` работает при заданном `DIRECT_URL`/`DATABASE_URL`.
- Миграция: `prisma migrate diff --from-schema-datamodel <копия до правки> --to-schema-datamodel src/db/schema.prisma --script` с фиктивными `DATABASE_URL`/`DIRECT_URL`; shadow DB не используется. Применение миграции не проверялось.
- Проверки: `prisma validate`, `prisma generate`, `npm run typecheck`, `npm run lint`, `npm test`, `npm run build` — успешно (подробности в отчёте `opencode-microtasks/2.5.3-report.md`).
