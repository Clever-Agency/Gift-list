## Intent

**Problem:** Story 2.5 требует, чтобы фиксированные теги приходили с сервера с `label` на языке запроса (AD-22, AD-27), но каталога в API нет: клиент не может получить ни `id`/`slug`, ни локализованную подпись, не держа её у себя.

**Approach:** добавить контракт каталога в `packages/contracts` и `GET /api/v1/tags`, который читает `Tag` из БД, выбирает подпись на языке `Accept-Language` через `negotiateLocale()` и отдаёт только `id`, `slug`, `label` в конверте AD-12. Пустая таблица — пустой каталог; порядок — детерминированный по `slug`.

## Boundaries & Constraints

**Always:** подпись выбирается на сервере из `labels` в БД; неизвестный/отсутствующий язык — `DEFAULT_LOCALE` (`ru`); порядок стабилен и документирован; пустая таблица — `{ tags: [] }` без подстановки тегов; в ответе только `id`, `slug`, `label`; БД в тестах — мок.

**Never:** не сидить и не подставлять фиксированные подписи в коде; не запускать `migrate`/`db push`/`db seed` и не подключаться к живой БД; не добавлять назначение тегов в create/update желания, UI, модерацию, агрегаты; не менять PRD/эпики/архитектуру; не трогать `main` и ветку CLE-49.

</frozen-after-approval>

## Implementation Notes

- Контракт: `tagCatalogItemSchema` (`id`, `slug`, `label`, непустые, strict) и `tagCatalogSchema` (`{ tags: [...] }`, strict) в `packages/contracts/src/tag.ts`, экспорт из `src/index.ts`. В JSDoc зафиксированы порядок `slug` и правило «клиент не сортирует и не хранит каталог после смены языка».
- Домен: `pickTagLabel(labels, locale)` — подпись запрошенного языка с `trim()`, затем `DEFAULT_LOCALE`, иначе пустая строка; `compareTagCatalogSlugs` — порядок по `slug` в кодовых единицах, независимо от коллации PostgreSQL; `toTagCatalogItem` — только три поля.
- Use-case: `apps/web/src/actions/tags.ts`, `getTagCatalog(headers)`. Локаль — `negotiateLocale(preferredFromAcceptLanguage(...))`, как при регистрации. `prisma.tag.findMany` с `select: { id, slug, labels }`; сортировка в приложении, чтобы порядок не зависел от БД. Строка без пригодной подписи отбрасывается, а не отдаётся пустой. Ошибка БД или контракта ловится, пишется в `console.error` и отдаётся конвертом `{ ok: false, code: "NOT_FOUND", message: "Tag catalog is unavailable" }`.
- HTTP: `apps/web/src/app/api/v1/tags/route.ts`, `GET`; `POST`/`PUT`/`PATCH`/`DELETE`/`HEAD` — `notFoundResponse`; `Vary: Accept-Language` при `Cache-Control: private, no-store`; маршрут всегда читает БД, общего кэша нет.
- Решения (зафиксированы в отчёте): endpoint публичный — каталог не содержит пользовательских данных, AD-27 привязывает ответ только к заголовку языка, а review 2026-10-28 предлагает `GET /api/v1/tags` как обычное чтение; сессия не требуется. Код `NOT_FOUND` для сбоя БД — вынужденное следствие закрытого набора `ERROR_CODES` (AD-12); `deferred-work.md` (пункт 1.4) фиксирует, что внутреннего кода нет и клиент трактует не-конверт как `network`. Это компромисс, вынесен в находки отчёта.
- Порядок: `slug` по возрастанию (кодовые единицы): `dream`, `need-now`, `someday`. Правило закрывает F-2.5.3-5 без нового поля; при необходимости ручного порядка в Story 10.2 добавить `sortOrder`.
- БД: миграция и сид не применялись, изолированной PostgreSQL нет; тесты используют моки. Пустая таблица, порядок, локализация, fallback, отбрасывание строки без подписи и сбой БД проверены на моках.
- Story 2.5 остаётся `in-progress`: назначение тегов, picker и карточка — 2.5.5+; F-2.5.3-3 (флаг агрегатов) и F-2.5.3-4 (trim своего текста) переходят туда же.
- Проверки: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build` — успешно; числа и подробности в `_bmad-output/implementation-artifacts/opencode-microtasks/2.5.4-report.md`.
