## Intent

**Problem:** сервер уже принимает и отдаёт теги (2.5.5), каталог `GET /api/v1/tags` готов (2.5.4), но в форме желания нет выбора тегов. Владелец не может отметить «мечта», «нужно сейчас», «когда-нибудь» или добавить свой текст, а ошибки `tags.N.*` некуда показать.

**Approach:** добавить в `GiftForm` блок тегов на общих примитивах `@gift-list/ui`: чипы фиксированных тегов из каталога (подписи только с сервера) и поле своего тега до 30 символов. Экран загружает каталог с языком запроса через `Accept-Language`; форма переживает загрузку, пустой каталог и ошибку, не сбрасывая уже выбранные теги. В create теги уходят, если выбраны; в edit набор отправляется только при изменении: отсутствие `tags` сохраняет, `[]` очищает. Вложенные ошибки `tags.N.*` показываются в блоке тегов доступным сообщением.

## Boundaries & Constraints

**Always:** фиксированные подписи — только `label` сервера; несколько фиксированных тегов и свой текст ≤ 30 кодовых точек Unicode; trim, непустой текст, без дублей; начальные значения из карточки; удаление тега и явная очистка пустым набором; dirty-трекинг; ошибки `tags`/`tags.N.*` доступны скринридеру; состояния каталога loading/empty/error с сохранением выбора; существующие правила статусов не менять.

**Never:** не добавлять ограничение `CLOSED` или лимит числа тегов (в AC их нет); не делать карточку 2.5.7, модерацию, новые API-правила; не менять видимость/quantity; не трогать `main`, не пушить, не мержить; не подключаться к живой БД, не запускать миграции/сид.

## Implementation Notes

- Контракт: `giftTagListSchema` не экспортируется. Форме он не нужен: `GiftTagInput` (`{catalogId}` | `{text}`) уже экспортирован, правило длины — `GIFT_TAG_TEXT_MAX`. Экспорт списка не добавлялся.
- `packages/ui`: новый `TagChip` — чип-`checkbox` с `aria-checked` и чип с крестиком «Убрать тег {имя}»; собран из `Pressable`, `Text`, `XStack`, без прямого импорта `tamagui`. Экспортирован из `index.ts`.
- `apps/mobile/src/ui/gift-form-tags.ts`: модель `GiftFormTag` (`{catalogId,label}` | `{text}`), ключи идентичности (порядок не важен, подпись не влияет; ключ — `JSON.stringify`, чтобы перевод строки в своём тексте не склеил наборы), `customTagIssue` (empty/invalid/tooLong/duplicate, где invalid — NUL из контракта), `GiftCard.tags` → форма, форма → `GiftTagInput[]`.
- `apps/mobile/src/api/tags.ts`: `GET /api/v1/tags` через `apiRequest` (он уже ставит `Accept-Language`), разбор `tagCatalogSchema`, `invalid` для чужого тела. `useTagCatalog` — loading/ready/error + retry; пустой готовый каталог тоже даёт retry, чтобы подхватить появившийся сид.
- `GiftForm`: состояние тегов локальное, каталог приходит пропсами (`tagCatalog`, `onRetryTagCatalog`). Выбранные фиксированные теги без каталожной строки (ошибка/пустой каталог/старый id) остаются видимыми по подписи из карточки. Пустой/упавший каталог не очищает выбор. Свой тег добавляется кнопкой (недоступна на пустом поле) и при отправке; пустой, NUL, длинный или дублирующий текст блокирует submit и объявляется. Подписи фиксированных тегов перед отправкой обновляются из текущего каталога, но идентичность остаётся `catalogId`.
- Ошибки: `serverErrorField` относит `tags`, `tags.N`, `tags.N.text`, `tags.N.catalogId` к полю `tags`; группа получает `aria-invalid`/`aria-describedby`, сообщение — `role="alert"`. `tags.N.catalogId` говорит «тега больше нет», текстовые ошибки — про длину/повторы. Клиентская ошибка своего тега — под полем (`error.tagEmpty`/`tagInvalid`/`tagTooLong`/`tagDuplicate`).
- `new.tsx`: каталог через `useTagCatalog`; `tags` в теле только если выбраны (контракт по умолчанию даёт `[]`). `edit.tsx`: начальные теги из карточки; тело получает `tags` только если набор отличается (сравнение без учёта порядка), поэтому неизменная правка ключ не шлёт, а удаление всех тегов шлёт `[]`.
- Статусы: теги доступны при любом статусе, как название; `visibility`/`quantity` остаются замороженными вне `OPEN`. `CLOSED`-ограничение и лимит числа тегов не вводились — вопросы в отчёт.
- Тесты: `gift-form-tags.test.ts`, `gift-form.test.tsx` (каталог loading/empty/error, выбор/удаление/очистка, свой тег, Unicode/NUL, dirty, `tags.*` и `aria-describedby`), `tags.test.ts` (клиент каталога), `use-tag-catalog.test.tsx` (loading→ready, error→retry, invalid), экраны create/edit (тело с тегами, неизменность → ключа нет, очистка → `[]`, RESERVED без `visibility`/`quantity`), `packages/ui/tag-chip.test.tsx` (checkbox, клавиатура, крестик).
- Проверки: `npm run typecheck`, `npm run lint`, `npm test` (mobile 518, web 469, contracts 164, ui 59, boundaries 5/5), `npm run build` — успешно; визуальная проверка в браузере/на устройстве не выполнялась — отражено в отчёте.

## Review Triage Log

- `tags.N.*` показывались одной фразой про длину/дубли: верно. Исправлено: `.catalogId` получает `error.tagUnavailable`, остальные — общую фразу; `index` не разворачивается в конкретный чип, потому что поле приходит как плоская строка, а блок и так связан с группой. Средний, исправлен частично.
- Число 30 продублировано в плейсхолдере и общей ошибке: верно. Оба места переведены на `{max}`/`GIFT_TAG_TEXT_MAX`. Низкий, исправлен.
- NUL не проверялся клиентом: верно, контракт его отвергает. Добавлен `invalid` и сообщение `error.tagInvalid`, тест. Средний, исправлен.
- Ошибка своего тега переживала удаление тега: верно. `customTagError` сбрасывается при переключении/удалении, тест на повторное добавление. Средний, исправлен.
- Ошибка не связана с группой, счётчик не live: связь добавлена (`aria-invalid`, `aria-describedby`), счётчик остаётся `hint`/`accessibilityHint` — отдельный live-регион не вводился, чтобы не дублировать текст. Средний, исправлен частично.
- «Добавить тег» активна на пустом поле, нет объявления, `returnKeyType: done`: кнопка недоступна на пустом вводе, ошибка объявляется, `returnKeyType` убран, Enter по-прежнему добавляет. Низкий, исправлен.
