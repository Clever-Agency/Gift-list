## Intent

При открытии `/l/:token` с действующей сессией Next.js перенаправляет пользователя в приложение до проверки доступа. По Story 3.3 и AD-7 неизвестный токен и блокировка должны давать одинаковый HTTP 404 на самом `/l/:token`.

Перед перенаправлением проверить доступ к списку для текущего пользователя через общую политику. Доступный список, включая пустой, открывается в приложении. Аноним по доступной ссылке продолжает получать публичную страницу.

</frozen-after-approval>

## Implementation Notes

- Открытие списка и перенаправление используют общую проверку списка и отношений через `VisibilityPolicy.resolve`. Перед перенаправлением карточки и архив не запрашиваются.
- В тестах вошедший зритель с доступом получает перенаправление. Неизвестный токен и блокировка выдают одинаковое состояние, которое Next-страница передаёт в `notFound()`.
- Прошли 298 серверных и 145 клиентских целевых тестов, `typecheck` веб-пакета и ESLint изменённых файлов.

## Review Triage Log

- `medium` — нужен HTTP-прогон с действующей сессией и настоящим Block. Локального одноразового PostgreSQL не обнаружено, проверка остаётся за приёмкой на staging.
- `low` — проверка повторно читает связи в SPA. Сохранён общий источник фактов доступа. Запросы к связям выполняются параллельно, карточки и архив перед редиректом не читаются.
- `low` — описание возврата после «Куплю сам» уточнено до вишлиста с открытым подтверждением брони.
- `false` — локальный `.codex/config.toml` существовал до начала работы. В изменения исправления он не входит.
