## Intent

**Problem:** После 4.2.2 сервер умеет явно принимать и отклонять входящее приглашение и отдаёт в профиле `inviteCooldown`, но экран `/u/[nick]` всё ещё принимает входящее через 4.1.3 `POST /invite`, не умеет отклонять и не показывает последствий отказа. У отправителя нет слова «Отклонено», у отклонившего нет «Можно снова через N ч», а «Добавить в друзья» остаётся доступной в живом окне.

**Approach:** рядом с «Принять приглашение» добавить «Отклонить»; принятие перевести на `POST .../invite/accept`, отказ — на `POST .../invite/reject`. Читать `inviteCooldown` из того же профильного DTO. После отказа перечитать профиль; при живом окне показать отклонившему недоступную «Добавить в друзья» и «Можно снова через N ч», отправителю — chip «Отклонено» без кнопки. Видимость желаний по-прежнему решает только сервер.

</frozen-after-approval>

## Implementation Notes

- Решение: входящее принятие переведено с `POST /invite` на явный `POST /invite/accept` (4.2.2); первая заявка по-прежнему идёт в `POST /invite` (4.1.3).
- Решение: отказ зовёт `POST /invite/reject`; оптимистично показывается окно 24 ч (AD-10 п. 3), затем профиль перечитывается и часы заменяются целым `inviteCooldown.hours` от сервера.
- Решение: отклонивший (B) не получает chip, видит недоступную «Добавить в друзья» и «Можно снова через N ч»; отправитель (A, `rejected: true`) видит chip «Отклонено» без кнопки новой заявки.
- Решение: `ownProfile` проверяется раньше `inviteCooldown`, поэтому свой профиль не получает ни действий, ни окна, даже если сервер прислал бы поле.
- Решение: видимость желаний не фильтруется на клиенте; после принятия показываются ровно карточки из нового ответа `GET /api/v1/u/:nick`.
- Изменены: `packages/contracts/src/i18n/ru/app.json`, `apps/mobile/src/api/friend-invite.ts`, `apps/mobile/src/api/profile.ts`, `apps/mobile/app/u/[nick].tsx`, три точечных теста.
- Проверки: точечный Vitest mobile — 3 файла / 64 теста, exit 0; contracts — 7 файлов / 187 тестов, exit 0; корневые `npm run typecheck` и `npm run lint` — exit 0. Полные `npm test`/`npm run build` (4.2.4) не запускались.
- Ревью: Blind Hunter пропущен по указанию микрозадачи; самопроверка покрыла четыре состояния, откат, дубли нажатий и отсутствие чужих действий. Нативный прогон и диктор не выполнялись.
