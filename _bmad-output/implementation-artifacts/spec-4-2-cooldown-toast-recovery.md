## Intent

**Problem:** если профиль был прочитан до паузы, кнопка «Добавить в друзья» на экране ещё доступна, а сервер уже держит 24-часовой cooldown, то `relationshipAction` в `apps/mobile/app/u/[nick].tsx` показывает общий текст `errors.code.RATE_LIMITED` («Слишком много попыток…») вместо каталожного «Можно снова через {hours} ч», а профиль остаётся устаревшим: часы и запрет новой заявки не появляются, пока экран не перезагрузят вручную.

**Approach:** в ветке отказа `relationshipAction` распознать `code: "RATE_LIMITED"` вместе с `reason: "INVITE_COOLDOWN"` и целым `params.hours ≥ 1`; показать `common("errors.reason.INVITE_COOLDOWN", { hours })` и перечитать профиль через существующий `setAttempt`, чтобы экран получил серверные `inviteCooldown` и `rejected`. Остальные ошибки, сетевой откат, защита от повторного нажатия и поведение accept/reject не меняются. Без правок домена, протокола, миграций, контрактов и каталога переводов: каталожная строка уже есть.

</frozen-after-approval>

## Implementation Notes

- Изменён только `apps/mobile/app/u/[nick].tsx` (`relationshipAction`) и тесты экрана `apps/mobile/src/session/profile-screen.test.tsx`.
- Новая ветка стоит после отката оптимистичного состояния и после обработки сети, кривого тела, 401 и 404, поэтому остальные исходы сохраняют прежний текст и поведение.
- Часы берутся только из `params.hours`; не число, не целое или меньше 1 — падение в прежний общий текст `RATE_LIMITED` без перечитывания профиля.
- Перечитывание идёт существующим `setAttempt`; серверный ответ сам решает, показать «Отклонено» (отправитель) или выключенную кнопку с часами (отклонивший).
- Локально `rejected` не выдумывается: до ответа сервера остаётся откатанное прежнее состояние, поэтому чип не мигает неверным значением.
- Проверки: `npm test -w @gift-list/mobile -- src/session/profile-screen.test.tsx` — 45/45, exit 0; `npm run typecheck` — exit 0; `npm run lint` — exit 0; полный `npm test` — mobile 722, web 695, contracts 187, ui 83, границы 5/5, exit 0. Полный прогон повторён после правок ревью. Нативные и дикторские проверки не выполнялись и в доказательство не записываются.
- Ревью (Blind Hunter): 13 находок. Исправлено: перечитывание профиля больше не зависит от валидности `hours` (рефетч по самому `reason`, текст — по часам); тесты проверяют именно `toast-host`; уточнён комментарий и docblock. Отклонено: `tone: "error"` (тот же тон, что у прежнего `RATE_LIMITED`, это ошибка действия); дубль фразы у отклонившего (требуемое поведение «toast + серверная подпись»); отсутствие разделов dispatch-спеки (oneshot-маршрут их не требует); traceability (спека, коммит и отчёт). Отложено: фоновый рефетч при сетевой ошибке заменяет готовый экран на `RetryView`; общий `RATE_LIMITED` на профиле не передаёт `unit`/`count` (оба — прежнее поведение вне рамок задачи).
