## Цель

Закрепить в CI поведение публичной ссылки из истории 3.3. Недоступная карточка должна вернуть 404 в первом HTTP-ответе даже вошедшему посетителю. Для доступной карточки требуется браузерное свидетельство, что после входа открывается подтверждение брони выбранного желания.

## Границы

Проверка использует собранный Next.js, настоящую сессию и одноразовую PostgreSQL с синтетическими данными. Видимость определяет существующая серверная политика (AD-7). Страница возвращает HTML, API — стандартный JSON ошибки (AD-12). Эпик и история уже приняты. Исполнитель публикует в CLE-130 результат браузерного прогона без персональных данных, cookie и токенов публичных ссылок.

## Сценарии

| Исходное состояние | Действие | Ожидаемый результат |
| --- | --- | --- |
| Чужое активное PUBLIC-желание, зритель без Block | Открыть карточку до и после входа | Аноним получает HTML 200. С действующей сессией исходный ответ перенаправляет на доступную карточку в приложении |
| То же желание стало SECRET либо по валидной ссылке запрошено отсутствующее желание | Запросить карточку анонимно и с сессией постороннего | Первый ответ 404, заголовок Location отсутствует |
| То же PUBLIC-желание, Block в любую сторону | Запросить карточку с cookie зрителя | Первый ответ 404 без Location. Состояние сессии проверено положительным сценарием |
| Недопустимый сегмент токена | Запросить страницу списка и API с тем же сегментом | Закрытый 404 у обоих, для API конверт NOT_FOUND. Отклонение до чтения сессии и БД |
| В списке два различимых открытых желания SINGLE | На странице одного желания нажать «Куплю сам» и войти тестовым зрителем | Открывается подтверждение брони именно выбранного желания. Проверить ID и название |

Согласовано 26 ноября 2026 года. Первый ответ на GET `/api/v1/l/` — 308 с переходом на `/api/v1/l`. Канонический адрес возвращает стандартный JSON 404.

## Карта кода

- `apps/web/src/app/l/[token]/link-page.ts`, `[giftId]/wish-page.ts` и `apps/web/src/actions/public-wishlist.ts` проверяют доступ. Страница проверяет пригодность токена для URL строже, чем API. Общая проверка и построение ссылок находятся в `apps/web/src/lib/public-token.ts`.
- `apps/web/src/app/api/v1/l/[[...token]]/route.ts` разбирает сегменты уже после канонизации Next.js. Тест непосредственного вызова GET не подтверждает сетевой контракт со слешем.
- `apps/web/scripts/verify-public-404-http.mjs` проверяет документ 404 без БД. В `verify-friendship-42-http.mjs` есть образцы регистрации с cookie, подготовки Block и запуска сервера. `src/db/disposable-pg/guard.ts` проверяет целевую БД до записи.
- `apps/web/src/app/l/[token]/[giftId]/public-wish-view.tsx` передаёт ID в параметре reserve. `apps/mobile/app/(link)/wishlist/[token].tsx` восстанавливает выбор после входа и открывает экран желания с openReserve.

## Задачи и приёмка

- [x] В `apps/web/src/lib/public-token.ts` и тестах публичного списка закрепить единые границы сегмента. Проверить обычный токен и недопустимые значения, в том числе управляющий символ. Сохранить поведение ссылок приглашения.
- [x] Дополнить `apps/web/scripts/verify-public-404-http.mjs` проверкой некорректного сегмента у страницы и API и согласованного поведения адреса без токена. Уточнить комментарий GET в `apps/web/src/app/api/v1/l/[[...token]]/route.ts`.
- [x] В `apps/web/scripts/` добавить целевой сценарий с одноразовой БД и подключить его после сборки в `.github/workflows/ci.yml`. При запросах отключить следование редиректам. Провал любого ожидания должен завершать проверку с ошибкой.
- [x] На собранном приложении пройти путь до диалога в настоящем браузере. Записать шаги, окружение и наблюдаемый результат в CLE-130. Отразить проверку у истории 3.3 в `_bmad-output/implementation-artifacts/sprint-status.yaml`.

Когда CI получает 200, перенаправление или 404 с Location для закрытой карточки, проверка падает. Когда первый ответ для адреса API со слешем отклоняется от согласованного, проверка также падает. Когда выполнен вход через публичную карточку, в Linear зафиксирован результат сравнения выбранного желания с диалогом брони.

## Заметки реализации

Проверены обе HTTP-команды на локальной standalone-сборке и PostgreSQL 17.12. Chrome 158 после входа открыл диалог «Забронировать «Зелёный термос»?» для выбранного ID. [Результат в CLE-130](https://linear.app/cleverwebagency/issue/CLE-130#comment-855a4a06-e687-4541-9e67-5bc9b638418a).
