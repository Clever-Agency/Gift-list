## Цель

Закрепить поведение истории 3.5 на реальной PostgreSQL. При заполненной выдаче пользователь находит точный ник и буквальный префикс с подчёркиванием. Поиск по имени работает одинаково для старых и новых профилей согласно `normalizeForSearch()` (AD-13, AD-27, D-30).

## Границы

Проверки выполняются на одноразовой PostgreSQL с синтетическими профилями. Сохраняются лимит выдачи, фильтры видимости и блокировки, формат карточки. По согласованию с пользователем, после применения SQL-миграций команда выкладки запускает Node с той же функцией normalizeForSearch(), которую вызывает приложение. Выкладка в общие среды выполняется отдельно.

## Заметки реализации

Итоговая команда `npm run migrate:deploy -w @gift-list/web` выполняет Prisma, затем читает профили по возрастанию ID порциями по 500. Пересчёт использует ту же `normalizeForSearch()`, что и запись профиля. При обновлении проверяются актуальное имя и текущее поисковое значение. Оператор может повторить команду после сбоя. [Инструкция выкладки](../../docs/deployment-environments.md)

Оба фильтра Prisma экранируют спецсимволы SQL-шаблона до ограничения выборки. В CI набор запускается на отдельной базе UTF8 с локалью C. Первый вариант исправления миграции использовал ICU-коллацию `pg_catalog."ru-x-icu"`. После воспроизведения ошибки U+1C89 этот вариант удалён из каталога миграций.

## История изменений спецификации

Пользователь согласовал перенос пересчёта из SQL в Node после применения миграций. Требование совпадения поисковых ключей для старых и новых аккаунтов сохранено. Исторический SQL остаётся частью проверяемой цепочки миграций.

Расширенная проверка на той же PostgreSQL 17.12 воспроизвела несовпадение версий Unicode. Для U+1C89 приложение сохраняет U+1C8A, а SQL с ICU 67 сохраняет U+1C89 и перезаписывает корректный ключ. Исходный вариант исправления миграции не прошёл ревью. При доработке сохранить буквальную фильтрацию до лимита, проверку старого профиля и сравнение с контрактом.

## Проверка

[Итоговый протокол пяти регрессий в CLE-131](https://linear.app/cleverwebagency/issue/CLE-131#comment-cc76bda2-d5ed-473d-9ef7-49c4707d9843).

**Итоговый прогон CLE-131.** Все пять регрессий прошли на новой PostgreSQL 17.12, UTF8, `LC_CTYPE=C`, `LC_COLLATE=C`. Проверены точный ник и буквальные префиксы при заполненном лимите, подстрока с подчёркиванием, процент и обратная косая черта, нормализация семи старых имён и поиск обоих профилей по U+1C8A. Тест подготавливает историю штатным Prisma CLI, дважды выполняет команду выкладки и сравнивает версии строк PostgreSQL (`xmin`). Первая порция содержит только корректные ключи.

Отдельный прогон команды выкладки в нестандартной схеме с `DIRECT_URL` исправил 1 201 строку. При втором запуске версии всех строк сохранились, таблица в соседней схеме осталась без изменений. При одновременном переименовании пересчёт дождался снятия блокировки, и новый ключ совпал с новым отображаемым именем.

Для повторения нужна пустая одноразовая PostgreSQL 17 или 18 с кодировкой UTF8 и локалью C. Параметры `DISPOSABLE_DATABASE_URL`, `DISPOSABLE_DIRECT_URL` и `DISPOSABLE_PG_CONFIRM` задаются для процесса по [правилам тестовой базы](../../apps/web/src/db/disposable-pg/guard.ts). Запуск из корня — `npm run verify:search-postgres -w @gift-list/web`. Дополнительно выполняются тесты действия поиска, `npm run typecheck`, `npm run lint`, `npm test` и `npm run build`.

На PostgreSQL 17.12 с UTF8, `LC_CTYPE=C` и `LC_COLLATE=C` команда `npm run verify:search-postgres -w @gift-list/web` воспроизвела все четыре сбоя. После исправлений прошли 4/4 на новой базе. Запрос `nick_` вернул точный ник и 19 префиксов. Семь старых профилей сохранили отображаемые имена, и их поисковые значения совпали с функцией контракта. Запрос `josé` вернул старый и новый профили. Модульные тесты действия прошли 23/23. [Протокол в CLE-131](https://linear.app/cleverwebagency/issue/CLE-131#comment-e388e041-b8fb-44a4-819a-549fb651eb4c).

После ревью в проверке точного ника участвуют 23 настоящих префикса и 23 ложных совпадения. Приватность дополнительно проверяется отдельным запросом по имени. Смена имени нового профиля проходит через `updateName`. Тесты HTTP-маршрута прошли 7/7. Расширенный PostgreSQL-набор с первой корректирующей миграцией прошёл 4/5. Пятый тест выявил потерю обоих профилей по U+1C8A.

В промежуточном прогоне после удаления пробной миграции прошли три сценария поиска из трёх. Обе регрессии миграции тогда воспроизвелись. Новый профиль с U+1C8A остаётся доступен, старый по тому же запросу отсутствует. SQL создания отдельной базы для CI выполнен на PostgreSQL 17.12, сервер подтвердил UTF8 и локаль C.

Локально прошли `npm run typecheck`, `npm run lint`, `npm run build` и полный `npm test` (4 545 тестов пакетов и 24 проверки скриптов). При первом прогоне проверка генератора иконок обнаружила разницу CRLF/LF в двух манифестах Windows. Повторный прогон прошёл с файлами, созданными самим генератором. После проверки восстановлены исходные байты обоих файлов. Удалённый запуск GitHub Actions ожидает публикации ветки.
