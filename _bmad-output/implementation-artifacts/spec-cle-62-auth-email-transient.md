## Intent

**Problem:** Вход, регистрация и сброс пароля передают удобный email в query-параметре (`/login?email=…`). Адрес с email попадает в историю браузера, логи прокси и закладки; приёмка эпика 1 зафиксировала это как PASS, но для приватности это дефект. `next` и проверка `safeNextPath` при этом должны работать как раньше.

**Approach:** Убрать `email` из всех переходов между тремя экранами. Передавать email только через эфемерное состояние в памяти модуля мобильного приложения: исходный экран запоминает значение перед нажатием ссылки, целевой читает его при монтировании и сразу очищает. URL, история, логи и постоянное хранилище email не содержат. Перезагрузка, глубокий переход и возврат без состояния дают пустое поле email; параметр `?email=` больше не читается.

</frozen-after-approval>

## Implementation Notes

- `apps/mobile/src/session/auth-navigation.ts` — один слот в памяти: `rememberAuthEmail(target, email)` запоминает email только для конкретного экрана (`/login`, `/register`, `/forgot`) на 60 секунд; `consumeAuthEmail(target)` атомарно читает и очищает; `forgetAuthEmail()` сбрасывает слот. Пустое значение и истёкший срок очищают слот. URL, `history`, `localStorage`, `sessionStorage` и логи не используются.
- `apps/mobile/src/session/use-carried-auth-email.ts` — хук читает перенос при фокусе экрана. Это покрывает и первый монтаж, и повторный фокус уже смонтированного экрана (Expo Router может переиспользовать маршрут). Поле стартует пустым, поэтому перезагрузка, глубокий переход и возврат без состояния дают пустой email.
- `apps/mobile/app/(auth)/login.tsx`, `register.tsx`, `forgot.tsx` — `email` убран из `useLocalSearchParams` и из всех `href`. Ссылки несут только `next`; `rememberAuthEmail` вызывается в `onPress` ссылки, до перехода роутера. `next` по-прежнему проходит через `returnPath`/`safeNextPath` без изменений.
- `apps/mobile/src/ui/nav-link.tsx` — добавлен необязательный `onPress`, который роутер вызывает до навигации. В комментарии зафиксировано: изменённый клик или новая вкладка пропускают перенос, такой глубокий переход открывается с пустым полем.
- `apps/mobile/src/session/auth-context.tsx` — успешный `signOut` (включая уже истёкшую сессию) сбрасывает ожидающий перенос.
- Тесты: новый `auth-email-transient.test.tsx` (20 тестов) проверяет отсутствие email в href, включая `%40`; перенос login → forgot → register → login; сохранение `next`; отбрасывание опасного `next`; изоляцию целей; одноразовое чтение, пустое значение, срок жизни; перезагрузку, глубокий `?email=`, повторный фокус и отсутствие записи в URL/хранилище. Обновлены mock `useFocusEffect` в `login-screen.test.tsx`, `password-rule.test.tsx`; `auth-context.test.tsx` проверяет сброс при выходе.
- Ограничения: визуальная проверка в браузере, Android и iOS не проводилась; реальные переходы Expo Router на устройствах не проверялись. Старые закладки `/login?email=…` поле больше не заполняют, но сам параметр из адресной строки не переписывается. Экран `reset` вне области задачи. Живая БД, seed и миграции не использовались.
- Проверки: целевые mobile-тесты, `typecheck`, `lint`, полный `npm test` и `npm run build` — результаты в `_bmad-output/implementation-artifacts/opencode-microtasks/cle-62-report.md`.
