## Intent

**Проблема:** сервер отвечает `VALIDATION` с полем `tags.N` / `tags.N.text` / `tags.N.catalogId`, но `GiftForm` показывает один общий текст под блоком тегов. Номер элемента не разворачивается в конкретный чип, поэтому ни диктор, ни зрячий пользователь не узнают, какой из выбранных тегов отвергнут (Q-09, F-2.5.6-3).

**Подход:** форма запоминает идентификаторы тегов в том порядке, в котором они ушли на сервер. При ответе `tags.N…` номер разворачивается в идентификатор из этой отправки и связывается с текущим чипом того же тега: `aria-invalid` + `aria-describedby` на чипе (в браузере) и `accessibilityHint` (на телефоне). Если путь без номера, номер вне отправленного набора или тег уже убран из формы — остаётся прежняя общая ошибка группы. Данные и порядок выбранных тегов не меняются; серверный контракт, коды ошибок и продуктовые правила не трогаются.

</frozen-after-approval>

## Implementation Notes

- Индекс в ответе уже есть: `firstIssueField` в `apps/web/src/lib/api-v1.ts` отдаёт путь zod, например `tags.1.catalogId` (для `invalid_union` — `tags.1`). Сервер, контракты и `packages/ui` без доменных знаний не менялись.
- `tagErrorKey` в `gift-form-validation.ts` — чистая функция: путь `tags.<N>[.<ключ>]` + отправленный порядок + текущий набор → идентификатор чипа или `null` для общей ошибки. Суффикс `.text`/`.catalogId` на сопоставление не влияет.
- `GiftForm` хранит порядок последней отправки в `submittedTagKeys` и обновляет его только когда `onSubmit` действительно вызывается. Поэтому индекс сопоставляется с тем набором, который видел сервер, а не с текущим порядком чипов.
- `TagChip` получил необязательное `error: { id, message }` (`TagChipError` экспортируется из `packages/ui`): id ведёт на единственный текст ошибки, message идёт в `accessibilityHint`. Для своего тега связь ставится на кнопку-крестик — единственный фокусируемый элемент чипа.
- Группа чипов помечается `aria-invalid`/`aria-describedby` только когда ошибка осталась групповой: при точечной ошибке невалиден ровно один чип, а не группа и чип одновременно.
- Снятие и повторный выбор тега не сбивают связь (идентификатор тот же). Удаление отвергнутого тега или номер вне отправки дают общую ошибку группы: подсветки чужого чипа не бывает.
- Визуальная пометка чипа (цвет/иконка) не добавлялась: `DESIGN.md` не задаёт отдельного вида ошибочного чипа, а общий текст ошибки уже виден под блоком. Это остаётся визуальной проверкой Q-05.
