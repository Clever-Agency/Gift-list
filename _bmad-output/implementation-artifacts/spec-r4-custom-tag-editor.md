## Intent

**Problem:** Свой тег сейчас добавляется через отдельное пунктирное превью-чип: набранный текст не виден в самом первом теге, повторное нажатие на «Свой тег» ничего не закрывает, Escape/отмена не работают, а уже добавленный свой тег можно только удалить. Это расходится с запросом пользователя t267u.

**Approach:** Первый чип «Свой тег» становится единственным индикатором ввода: пока открыт редактор добавления, он показывает набранный текст (при пустом вводе — снова «Свой тег»), пунктирный превью-чип удаляется. Нажатие на чип переключает редактор (`aria-expanded`), Escape и «Отмена» закрывают его с возвратом фокуса на чип. Нажатие на текст уже добавленного своего тега открывает тот же редактор с этим текстом; текст в чипе меняется live, а сохранение заменяет тег с прежними правилами длины, NUL и дублей. Звезда берёт цвет из токена темы, а не из захардкоженного `colors.accent`.

</frozen-after-approval>

## Implementation Notes

- `packages/ui/src/tag-chip.tsx`: ветка `preview` и проп `preview` удалены; чип с `onRemove` получил необязательную кнопку редактирования (`onPress` + `editLabel`), `TagChip` стал `forwardRef` на `Pressable` для возврата фокуса; цвет `Star` читается через `useTheme().accent.get("web")` (в web — `var(--accent)`).
- `apps/mobile/src/ui/gift-form.tsx`: добавлено состояние `editingCustomTag` (null — добавление), общий коммит для добавления и замены, toggle/Escape/«Отмена» с `restoreFocus` на чип-триггер. `ref={tagsRef as never}` заменён на `useRef<ComponentRef<typeof XStack>>(null)`.
- Live-текст в первом чипе показывается только в режиме добавления; при редактировании live-текст показывается в редактируемом чипе, чтобы значение менялось именно в нём. Видимый текст — черновик, доступное имя триггера остаётся «Свой тег: {text}», чтобы контрол не терял назначение.
- Добавление оставляет поле открытым для следующего тега; сохранение правки закрывает редактор. Toggle, Escape и «Отменить» закрывают поле и возвращают фокус на чип.
- Черновик редактирования не делает форму грязной, пока текст совпадает с исходным: в `isGiftFormDirty` передаётся пустая строка для неизменённого `editingCustomTag`.
- Копирайт: `field.tagEdit` («Редактировать тег {name}»), `field.tagSave` («Сохранить тег»), `field.tagCancel` («Отменить») и `field.tagCustomLive` («Свой тег: {text}»).
- `closeCustomTagEditor` вынесен в `useCallback` и переиспользуется Escape-обработчиком; Escape слушает только события внутри редактора или на триггере и не перехватывает уже обработанные (`defaultPrevented`), поэтому слой поверх формы сохраняет свой Escape.
- Удаление редактируемого тега крестиком закрывает редактор и не оставляет висящего `editingCustomTag`.
- Тесты: live-текст в первом чипе и возврат к «Свой тег», toggle/`aria-expanded`, Escape (в добавлении и правке) и «Отменить» с фокусом, редактирование с live-текстом и заменой, дубль при редактировании, удаление редактируемого тега, ошибка на кнопке редактирования, длинный тег, доступные имена.
- Не менялись: правила валидации тегов, бронь, приватность, маршруты, API и сервер.
