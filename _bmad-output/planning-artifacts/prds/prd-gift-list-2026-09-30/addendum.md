# Addendum к PRD: Gift List

Материал вне основного повествования PRD: отклонённые альтернативы, отложенный платёжный поток, заметки для downstream.

## Зафиксированные решения (см. также PRD §12)

| ID | Решение | Статус |
|----|---------|--------|
| **D-10** | Взаимная дружба: любой может пригласить; после принятия оба видят Friends-only; до принятия скрыто. Заменяет «только владелец приглашает». | **Locked** (Sergey подтвердил Q-4) |
| **D-11** | Ссылки на списки: свой URL у каждого Списка ≠ `/u/{ник}`; Discoverable — подарки для auth; Friends-only — подарки Другу, не-другу объяснение «только для друзей» (не blank / не «не найдено»); аноним — вход → то же; не per-gift; копирование; share-sheet вне scope; Профиль сохраняется | **Locked** (Sergey, уточнение Friends-only) |
| **A-24** | Первый запуск без оплаты; платежи — Раунд 2 | **Locked** |
| **D-12** | Жизненный цикл брони: Срок задаёт Даритель (по умолчанию +7, не дальше +30 дней, продления без лимита); по наступлении Срока — уведомление Дарителю, через 72 ч — запрос Владельцу, ещё через 168 ч молчания обоих — авто-снятие только без «Купил»; «Купил» и «Подарил» не снимаются автоматически; закрытие — только Владелец, отмена 10 с; email по событиям брони в R1. Заменяет A-9 | **Locked** (Sergey, 2026-10-10) |
| **D-13** | Видимость держателя Брони: «видим Владельцу» (по умолчанию выкл.) и «видим другим зрителям» (по умолчанию вкл.); Владелец видит статус без имени. Заменяет A-23 | **Locked** (Sergey, 2026-10-10) |

## Отклонённые / отложенные альтернативы

| Тема | Решение | Почему |
|------|---------|--------|
| Оплата в первом запуске | **Отложено на Раунд 2** (A-24) | Решение Sergey: первый запуск без оплаты |
| Только владелец шлёт инвайт | **Отклонено** в пользу D-10 | Подтверждено Sergey (Q-4) |
| Только ссылка на профиль / один URL на всё | **Отклонено** в пользу D-11 | Нужна ссылка, открывающая один Список |
| Per-gift share links | **Вне R1** | Явно не входит в D-11 |
| Полноценный share-sheet | **Вне R1** | Достаточно копирования ссылки (FR-28) |
| Единый список «только контакты» | Снято 2026-10-28 | D-23: один вишлист, видимость на желании |
| Телефонная книга как источник дружбы | Отклонено | D-30: книга находит человека и показывает публичные желания, другом не делает |
| Два списка Discoverable / Friends-only | Заменено D-23 | Историческое D-11; боевых данных нет |
| Guest checkout | Отклонено (и для R2) | Анти-абьюз, идентичность |
| Stripe / мультивалюта в R2 | По умолчанию ЮKassa + RUB | Пилот RU-контекст; смена — правка A-17/A-18 |
| Анонимные взносы | Отклонено для R2 | Прозрачность (A-8) |
| Авто-снятие брони по фиксированному TTL (14 суток) | Отклонено (D-12) | Купленный и ждущий праздника подарок снова открывается → двойная покупка |
| Дата события на Списке / Подарке, привязка брони к ней | Отклонено | Даритель сам знает, когда дарит; одна дата не покрывает несколько поводов |
| Лимит числа продлений брони | Отклонено | Каждое продление — живое подтверждение; защищает горизонт 30 дней |
| Автозакрытие Подарка при молчании Владельца после «Подарил» | Отклонено | Слов Дарителя недостаточно; Подарок никому не мешает |
| Владелец не видит даже статус брони («spoiler mode») | Вне R1 | Ломает FR-10 (перенос только из `открыт`) и создаёт риск, что Владелец купит сам |
| Единый мировой часовой пояс для Сроков | Отклонено (A-27) | Ломает Сроки на другом краю карты (РБ → РФ сейчас, другие регионы в перспективе) |
| Обычный reopen `закрыт` → `открыт` | Отклонено | Ломает аудит; заменено отменой 10 с и «Хочу ещё такой» |

## Платёжный поток — Раунд 2 (не строить в R1)

1. Даритель выбирает полную оплату или Взнос → видит итог с комиссией (A-20).
2. ЮKassa проводит платёж → сервис идемпотентно применяет к Подарку.
3. До Закрытия средства «к выплате Владельцу» (A-19, A-21).
4. Возвраты по FR-22.

API, webhooks, ledger — зона `bmad-architecture` **Раунда 2**. Архитектура Раунда 1 не должна блокировать добавление платежей, но и не обязана реализовывать ledger заранее.

## Для UX / architecture Раунда 1

- Критичный UX: статусы `открыт` / `забронирован` / `закрыт` и единственная бронь без обучения; экран по Ссылке на список = один Список.
- Не показывать рабочие кнопки оплаты; не обещать «скоро оплата» как CTA, если нет явного запроса.
- Критичная архитектура R1: сериализация переходов статуса при конкурентной брони; модель видимости Списков; отдельные URL Списков (A-25); валидная Friends-only-ссылка для не-друга → объяснение (не 404), без утечки состава Подарков.
- Заложить расширяемые статусы/`сбор` без реализации платёжного контура — по усмотрению architecture, без scope creep.
- Не тащить в R1: OAuth, ленту друзей, рекомендации, ЮKassa, share-sheet, per-gift links.
