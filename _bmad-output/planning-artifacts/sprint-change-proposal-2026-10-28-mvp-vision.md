## 3. Рекомендуемый подход

**Гибрид: пересмотр MVP и прямая правка историй.** Откат Story 1.1 не нужен: Next.js остаётся сервером и вебом ссылки. Story 1.2 переписывается.

Почему не PWA и не обёртка сайта. Книга контактов «как в Telegram» в браузере не открывается целиком. Обёртка сайта рискует не пройти проверку Apple как просто сайт и всё равно потребует нативный доступ к контактам. Expo SDK 58 с текущим Next.js стыкуется: приложение ходит в `app/api/v1`, сессия — Better Auth с `expo` и `bearer`, веб по-прежнему на cookie. Vercel Hobby остаётся хостом разработки API; бинарник на Vercel не деплоится. Пилот с живыми пользователями по-прежнему запускает переезд D-15.

Трудоёмкость для кода высокая: новый клиент, новая видимость, контакты, админка. Риск высокий в правилах доступа и средний в сроке стора. Рычаг срока — снять P1 из таблицы раздела 0, не P0.

### 4.1 Архитектура (bmad-architecture)

Обновлён существующий spine, номера AD-1…AD-16 не сдвигались.

Expo подходит при таких правилах:

- Один сервер Next.js. Веб вызывает Server Actions, Expo — те же методы через `app/api/v1` (AD-1, AD-17).
- Better Auth один. Веб — cookie, натив — `@better-auth/expo` той же версии, что серверный пакет, плюс bearer и SecureStore (AD-3). Сейчас в репозитории better-auth 1.7.6.
- Expo SDK 58.0.20, React Native 0.88, expo-contacts 58.0.9. Проверено 2026-10-28. React веба (19.2.8) и React Expo (19.3.0) не сводить общим UI-пакетом.
- Чужие номера не хранятся. Совпадение — HMAC с pepper и ребро `ContactMatch` без телефона (AD-18). Apple 5.1.2: не собирать базу контактов и не рассылать «всем».
- Удаление аккаунта одно на веб и натив, до отправки в App Store (AD-20, D-33).
- Один список, видимость на желании (AD-6, AD-7). Безлимитное не бронируется. Архив и первое право брони входят в CAS (AD-8, AD-9).

Рецензия spine: механический lint без замечаний. Независимые рецензенты нашли дыры в стыке новых полей со старым CAS, карточкой AD-12 и удалением аккаунта. Эти дыры в spine закрыты. Версии Expo и Better Auth подтверждены.
