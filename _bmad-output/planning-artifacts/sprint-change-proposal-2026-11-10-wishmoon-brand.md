## 1. Суть

**Что запустило.** Пользователь Evgeniy 2026-11-10 выбрал отображаемое имя продукта — **WishMoon** — и публичный контакт автора — `clever.web.agency@gmail.com`. Ссылка «Написать автору» должна открывать `mailto:`.

Это не новый выбор дизайна и не новая функциональность: имя и контакт уже существуют в продукте как конфигурация, но их значения — временные («Gift List», пустой `EXPO_PUBLIC_AUTHOR_URL`). AD-24 прямо фиксирует, что имя «ещё не выбрано», а D-35 — что «строка выбирается позже по спросу в поиске». Решение закрывает это допущение.

**Тип:** новое требование от стейкхолдера (продуктовое решение владельца), не техническая находка. Продукт, объём MVP, порядок историй не меняются.

## 4. Подход

**Прямая корректировка (Option 1).** Механизм AD-24 («одно отображаемое имя, без литералов в компонентах») сохраняется и усиливается: значения по умолчанию переезжают в один файл `packages/contracts/src/brand.ts`, а переменная окружения остаётся осознанным переопределением, а не вторым источником. Контакт автора живёт там же и выводится из одного адреса.

**Почему `packages/contracts`:** это единственный пакет, который видят оба клиента (AD-17, AD-26); в нём нет React, Prisma и env, поэтому константа и чистая функция границу не нарушают. `packages/ui` не подходит — в нём нет данных и строк (AD-2).

**Трудоёмкость:** низкая (полдня–день): один новый файл констант, правки двух дефолтов, `app.config.ts`, `AuthorLink`, `sync-spa.mjs`, два `.env.example`, README и шесть тестов.

**Риски:**

| Риск | Закрытие |
|---|---|
| `app.config.ts` не сможет импортировать TS из воркспейса (Expo CLI грузит конфиг до Metro) | W1b проверяет `npx expo config --type public` без `.env`. Основной путь — подпуть `@gift-list/contracts/brand`. Запасной — литерал в `app.config.ts`, но тогда **тест** сверяет его с `PRODUCT_NAME`, чтобы литерал не разошёлся с константой |
| Скрытое расхождение SSR и SPA: на хосте задан только `BRAND_NAME`, SPA собралась с другим/пустым именем | `sync-spa.mjs` передаёт в Expo `EXPO_PUBLIC_BRAND_NAME: process.env.BRAND_NAME ?? ""` (та же схема, что уже применяется к `EXPO_PUBLIC_API_BASE_URL`), пустое значение означает дефолт из константы. Ручной `EXPO_PUBLIC_BRAND_NAME` в окружении сборки веб-SPA перекрывается так же, как сейчас перекрывается API base |
| Публичный e-mail в публичном репозитории (D-17) | Адрес публичный по решению владельца и не является секретом; в `.env*` он не попадает, живёт в коде как константа. Секретов в изменении нет |
| Тест каталогов (`packages/contracts/src/i18n/i18n.test.ts:87`) запрещает литерал «Gift List» в переводах | Тест не удаляется, а расширяется: запрещены оба значения (`Gift List` и `WishMoon`), чтобы AD-27 не нарушался при смене имени |
| Смена имени «протечёт» в неизменяемые идентификаторы (пакеты, slug, bundle id, домен) | §7: явный список неизменяемого; W1b не трогает ни один из этих файлов |
