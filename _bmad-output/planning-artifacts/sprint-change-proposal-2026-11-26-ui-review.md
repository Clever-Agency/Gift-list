# Sprint Change Proposal — 2026-11-26, UI-ревью

> **Статус: утверждён (`status: approved`, 2026-11-26).** Инициатор — Evgeniy, владелец продукта; согласовал Sergey 26.11.2026. Ветка — `feature/cle-129-ui-review`, карточка — CLE-129. Документы правятся этим proposal; код идёт следующими шагами `bmad-build` по плану T1–T9 из `PLAN.md`.

## 1. Причина и контекст

26.11.2026 владелец продукта прошёл по интерфейсу собранного MVP и записал 14 замечаний. Часть из них — ошибки против уже утверждённых документов (навигация, ховеры, поле даты, красный колокольчик), часть — новые продуктовые решения (профиль с полями, разделение профиля и настроек, карточка брони, страница желания вместо окна).

Проверка кода ветки `origin/staging` (d4914d2) и документов BMAD показала:

- **Ошибки против документов.** EXPERIENCE требует, чтобы вложенные экраны сохраняли подсвеченную вкладку, а навигация нарисована только на пяти корневых экранах. DESIGN и решение UI-polish 2026-11-10 требуют hover у всего нажимаемого и переход 160 мс — у большинства нажимаемых поверхностей их нет. В бронях стоит голое поле `<input type="date">`, хотя в `packages/ui` есть стилизованный `DateField`. Иконка колокольчика не принимает цвет и краснеет от браузерного `:active`.
- **Новые решения.** CLE-84 (18.11.2026) сделал деталь желания диалогом; ревью возвращает страницу `/gifts/{id}`. Профиль получает поля (пол, страна, «Обо мне», ДР без года) и общий переключатель видимости для друзей. Настройки остаются только настройками. Карточка брони становится похожа на карточку желания и получает цену и фото-заглушку.

Ошибки исправляются кодом без правки документов (T1, T2 частично). Новые решения требуют синхронной правки PRD, эпиков, архитектуры и UX — это и есть предмет proposal.

## 2. Принятые решения (14)

Источник правды — раздел «Принятые решения» в `PLAN.md`. Тексты пользователю — дословно из решений.

1. **D-50. Навигация на всех экранах вошедшего.** Боковое меню на широком экране и нижние вкладки на узком есть на всех экранах вошедшего: профиль, настройки, уведомления, деталь и формы желания (включая экран с «Куплю сам»), вишлист по ссылке, приглашение, «не найдено». Экраны без входа остаются без навигации.
2. **D-51. «Друзья» без шапки.** Над вкладками убрать видимый заголовок «Друзья» и строку «Найти знакомых». Заголовок `h1` остаётся только для экранного диктора. Кнопка «Найти знакомых» остаётся внутри вкладки в пустом состоянии.
3. **D-52. Поиск друзей при 3+.** Поле «Искать среди друзей» видно, только если всего друзей 3 и больше. Если запрос уже введён, поле не прячется.
4. **D-53. «Написать в техподдержку».** Ссылка «Написать автору» переименовывается. У вошедшего она есть только в `/profile`; в футере — только на экранах без входа (вход, регистрация, сброс пароля, `/l`, `/i`, «не найдено» для анонима) и на Next-страницах. В письмах ссылка остаётся, но с новым текстом.
5. **D-54. Чип видимости убирается с карточки желания.** Видимость меняется только в форме желания. На карточке нет ни чипа, ни кнопки «Кто видит «…»».
6. **D-55. Имя дарителя — ссылка на профиль.** Если даритель разрешил показывать себя, у других гостей его имя в карточке и на странице желания ведёт на `/u/{ник}`. Владелец имени не видит никогда.
7. **D-56. Новая карточка брони.** Карточка строится на основе карточки желания: фото-заглушка, название, цена, «у @ника», срок и этап, главная кнопка по этапу, «Продлить» вторичной кнопкой только до срока, ⋯ со «Снять бронь». Цена и фото добавляются в DTO карточки брони, поэтому меняется AD-12.
8. **D-57. Один переключатель брони.** Вместо раскрывашки «Кто видит, что это я» — один переключатель «Показывать другим гостям, что дарю я».
9. **D-58. Профиль с полями.** День рождения без года, пол, страна, «Обо мне», смена ника, смена email с подтверждением на новый адрес. Фото будет позже, пока — кружок с инициалами. Все эти данные видят только друзья; включает их один общий переключатель «Показывать мои данные друзьям». Профиль `/u/{ник}` (свой и чужой): аватар, имя, ник, ДР, пол, страна, «Обо мне», ниже открытые желания. Править данные — в `/profile`.
10. **D-59. В настройках только настройки.** В `/settings` остаются «Не показывать в поиске», уведомления, часовой пояс, «Заблокированные», выход и удаление аккаунта. Правка данных переезжает в `/profile`.
11. **D-60. Дата в бронях — наше поле.** В окнах брони и продления используется `DateField` с `min` и `max`. Своего календаря не делаем.
12. **D-61. Колокольчик не краснеет.** Иконка принимает цвет, как остальные иконки. Это исправление ошибки, продуктового поведения не меняет.
13. **D-62. Ховеры и плавность.** Ховер есть у всего, на что можно нажать, у карточки желания — на всей площади. Цвет и тень меняются плавно через `transition` Tamagui (160 мс, только веб); при «уменьшить движение» переход выключается.
14. **D-63. Желание открывается страницей.** Нажатие на карточку везде открывает `/gifts/{id}`, а не окно. Для анонима на `/l` — отдельная страница Next `/l/{token}/{giftId}`. У владельца на странице есть ссылка «Изменить» на `/gifts/{id}/edit`. Окно подробностей (CLE-84) убирается. Правило сюрприза AD-15: страница владельца читает данные из «моих» желаний и ничего не знает о брони.

## 3. Решения по умолчанию (D-64)

Приняты ночью без владельца, к утренней проверке; в документах зафиксированы как значения по умолчанию.

- **D-64.1.** Переключатель «Показывать мои данные друзьям» по умолчанию **включён**. Выключен — друзья видят только имя, ник и аватар. Остальным (подписчикам, зрителям по ссылке, незнакомым) профильные данные не показываются никогда.
- **D-64.2.** Пол: «Мужской», «Женский» или не указан. Все профильные поля необязательные.
- **D-64.3.** Страна хранится кодом ISO 3166-1 alpha-2; названия берутся из встроенного `Intl.DisplayNames` без библиотек, выбор из списка с поиском.
- **D-64.4.** «Обо мне» — обычный текст до 500 знаков.
- **D-64.5.** День рождения хранится как день и месяц, без года; 29 февраля разрешено. Напоминания Epic 7 не расширяются: только поле и показ.
- **D-64.6.** Анонимная страница желания — `/l/{token}/{giftId}` (Next). Показывает только то, что уже видно по ссылке; «Куплю сам» ведёт на вход, как сейчас.
- **D-64.7.** Цена в карточке брони — текущая цена желания; если желание недоступно (`canOpenGift = false`), цены нет. Поле фото в DTO готовится, но фото пока нет ни у кого — на карточке заглушка.
- **D-64.8.** Ник и имя, как и раньше, видны всем, кто может открыть профиль.

## 7. План реализации T1–T9

Подробности — `PLAN.md` (разделы «Задачи (истории) и шаги»). Кратко:

- **T1.** Быстрые исправления: цвет иконки колокольчика (D-61), `DateField` в бронях (D-60), `AppShell` на все экраны вошедшего (D-50).
- **T2.** Ховеры и плавность: общий hover и `transition` 160 мс с гейтом `reduce` (D-62).
- **T3.** Брони: один переключатель (D-57), поля `priceAmount`, `priceCurrency`, `photoUrl` в DTO (D-56, AD-12), новая `ReservationCard` (D-56).
- **T4.** Карточка и страница желания: убрать чип (D-54), имя дарителя ссылкой (D-55), страница владельца (D-63, AD-15), карточки ведут на страницу, анонимная страница `/l/{token}/{giftId}` (D-63).
- **T5.** «Друзья»: без шапки и строки «Найти знакомых», поиск при 3+ (D-51, D-52).
- **T6.** Техподдержка: переименование, `/profile` и футер анонима (D-53).
- **T7.** Разделить `/profile` и `/settings` (D-59).
