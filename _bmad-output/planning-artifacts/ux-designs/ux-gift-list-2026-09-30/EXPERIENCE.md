# Gift List — Experience Spine

> MVP после D-20…D-33. Визуал веба — в `DESIGN.md`. Этот spine — поведение. Нативный клиент повторяет те же состояния, не второй копирайт.
> Оплата, денежный сбор, share-sheet, per-gift links — **вне** этого документа.
> Модель брони D-12 / D-13 отражена в `prototype/index.html` (2026-10-11): confirm брони, метки владельца и зрителей, «Мои брони», уведомления, «Получено», отмена 10 с. При конфликте главнее этот spine.

## Foundation

- **Форм-фактор:** нативное приложение для вошедшего пользователя; веб — публичная ссылка, регистрация по ссылке и админка (D-20). Сначала Google Play, затем App Store. Потоки одни и те же. Имя продукта на экранах берётся из одной переменной, не из текста макета (D-35).
- **UI-система:** [ASSUMPTION: UX-A1] shadcn/ui на Next.js + Tailwind; behavioral delta здесь, visual delta в `DESIGN.md`.
- **Локаль:** [ASSUMPTION: UX-A9] UI на русском; multi-locale вне R1.
- **Тема:** [ASSUMPTION: UX-A8] только light.
- **Аутентификация:** бронь, друзья и свой вишлист — после сессии. Аноним на `/l/{token}` видит желания «всем» и кнопку «Куплю сам», которая ведёт на вход (D-29).
- **Стейки:** [ASSUMPTION: UX-A10] consumer/hobby (узкий круг); ошибка статуса брони дороже отсутствующей «вау»-фичи.

## Voice and Tone

Микрокопирайт. Brand voice — `DESIGN.md` Brand & Style.

| Do | Don't |
|----|-------|
| «Куплю сам» | «Забронировать айтем» / «Claim gift» |
| «Этот список только для друзей {Имя}» | «Доступ запрещён» / «404» / пустой экран |
| «Ссылка скопирована» | «Successfully copied to clipboard!» |
| «Берёт Марина» — только тем, кому Марина разрешила | Показывать имя владельцу без согласия дарителя (D-13) |
| «Срок брони истёк» + понятные кнопки | «Вы забыли!», «Напоминаем ещё раз» |
| «Подарок у вас?» | «Подтвердите, что даритель не врёт» |
| «Подарок закрыт — уже получен» | «Error: closed state» |
| «Войдите, чтобы увидеть подарки» | Показывать названия подарков анониму |
| Спокойно про конкуренцию: «Кто-то только что забрал этот подарок» | Обвинять пользователя |
| Без обещаний оплаты в R1 | Кнопка «Скоро можно будет оплатить» как CTA |

**Friends-only gate (канон D-11):**  
Заголовок (`display-sm`): «Список только для друзей».  
Текст: «Подарки из этого списка видят только люди из списка друзей {Отображаемое имя}. Станьте друзьями в Gift List, чтобы открыть их.»  
CTA: если есть профиль → «Открыть профиль {имя}» (Discoverable виден; приглашение оттуда); secondary — «Найти в поиске». **Не** показывать состав/названия Подарков.

**Аноним на ссылке вишлиста:** желания «всем» видны сразу. У «Куплю сам»: «Чтобы забронировать, войдите или зарегистрируйтесь.» После входа — тот же URL, без новой дружбы.

**Пусто, когда закрытое не показывают:** «Пока нет открытых желаний.» Не писать «список только для друзей» и не показывать число скрытых. Старый Friends-only gate снят (D-23).

## Interaction Primitives

- **Primary input:** touch + pointer; формы — клавиатура.
- **Бронь:** один тап/клик по «Куплю сам» → Reserve confirm (дата + два переключателя, см. Component Patterns) → Подтвердить / Отмена. Confirm нужен: необратимость социальной координации важнее скорости (SM-2).
- **Снятие своей брони:** confirm «Снять бронь? Подарок снова станет открытым.»
- **Закрытие владельцем:** confirm «Подарок «{название}» получен?» (+ при брони «Бронь будет закрыта, бронировавший получит уведомление»); затем toast «Отменить» 10 с. Иного возврата нет *[UX-A11]*.
- **Снятие чужой брони владельцем:** confirm; при «Купил» — «Даритель отметил, что подарок уже куплен. Если снять бронь, его может купить кто-то ещё»; при «Подарил» — основные «Получил» / «Не получал».
- **Правка забронированного подарка:** hint в форме «Подарок забронирован — бронировавший получит уведомление».
- **Копирование ссылки:** без confirm; Toast.
- **Удаление подарка `забронирован`:** сильный confirm + предупреждение, что бронь снимется и бронировавший получит уведомление (FR-10); при «Купил» — предупреждение «уже куплен»; при «Подарил» основное действие — «Отметить полученным».
- **Esc / overlay:** закрывает dialog/sheet; не сбрасывает черновик формы без «Отменить».
- **Banned R1:** infinite scroll как единственный способ (исключение: список друзей — подгрузка при прокрутке допустима, потому что есть строка поиска; в остальных списках — пагинация/«ещё» при >50); drag-reorder; hover-only actions на mobile; modal stack >1; рабочие кнопки оплаты.

## Accessibility Floor

Behavioral; контраст — `DESIGN.md` / shadcn AA.

- WCAG 2.2 AA на ключевых потоках: регистрация, бронь (confirm с датой и переключателями), закрытие + toast отмены, Friends-only gate, копирование ссылки.
- Undo toast: объявляется через `aria-live="polite"`, кнопка «Отменить» достижима с клавиатуры; основная защита от промаха — confirm до закрытия, отмена 10 с — дополнительная.
- Каждое поле формы — видимый `<label>`; ошибки — текст рядом с полем, не только цвет.
- Status pill не кодирует смысл одним цветом: всегда текст («Открыт» / …).
- Focus ring `{colors.ring}` на всех интерактивных.
- Gate Friends-only и anon gate — заголовок уровня `h1`, объявляется screen reader при входе на страницу.
- Toast — `aria-live="polite"`; гонка брони — `assertive`.
- Sidebar: `<nav aria-label="Основная навигация">`, активный пункт `aria-current="page"`; drawer на mobile — фокус внутрь при открытии, возврат на ☰ при закрытии, `Esc` закрывает.
- Меню пользователя: кнопка `aria-haspopup="menu"` + `aria-expanded`, пункты `role="menuitem"`, навигация стрелками и `Esc`.
- Вкладки «Друзья»/«Запросы»: `role="tablist"`/`tab`, `aria-selected`; подгрузка списка объявляется через `aria-live="polite"` («Загружаем…», «Показаны все (N)»).
- Не полагаться на hover для снятия брони / меню владельца на touch.

## Inspiration & Anti-patterns

- **Взять:** дисциплину «один ясный статус» у хороших RSVP/registry; спокойный copy у Linear-like tools (без hype).
- **Отвергнуть:** Amazon Wishlist «buy for me» checkout в R1; напоминания до Срока брони и повторные «пинги» (одно письмо за 3 дня до даты окончания желания — отдельное правило D-26); автозакрытие по словам дарителя; авто-снятие купленной брони; empty state вместо отказа без утечки; «не найдено» как soft-deny; feed/stories друзей; gamification streaks.

## Key Flows

Имена и сценарии зеркалят PRD UJ-*; кульминация обязательна.

### Flow 1 — Сергей готовит один вишлист (UJ-1)

**Протагонист:** Сергей, владелец, вечер перед днём рождения.

1. Уже в сессии; открывает **Мой вишлист**.
2. Добавляет «Наушники» с видимостью «всем» и «Клавиатуру» с видимостью «друзьям».
3. Копирует одну ссылку и отправляет Марине вне продукта.
4. Через поиск находит Марину → «Добавить в друзья».
5. **Кульминация:** до принятия Марина по ссылке видит только «Наушники». После принятия видит и клавиатуру.
6. **Резолюция:** ждёт броней единичных желаний.

**Край:** Дима отклоняет инвайт → желания «друзьям» ему не видны; Сергей видит «Отклонено».

**Failure:** ник занят при смене в настройках → inline error «Этот ник уже занят».

### Flow 2 — Марина бронирует Friends-only (UJ-2)

**Протагонист:** Марина, близкая подруга.

1. Принимает приглашение на **Друзья**.
2. Открывает Ссылку на FO (или Профиль Сергея — видит оба списка).
3. Открывает «Механическая клавиатура» → «Куплю сам» → confirm: дата по умолчанию (+7 дней), переключатели по умолчанию.
4. **Кульминация:** pill «Забронирован»; Диме видно «Берёт Марина», Сергею — «Забронирован» без имени; кнопка у других недоступна.
5. Покупает вне сервиса → «Купил»; после праздника → «Подарил»; Сергей получает «Подарок у вас?» → «Получил» → `закрыт`.

**Край (гонка с Димой):** второй получает Toast «Кто-то только что забрал…».

### Flow 3 — Алексей по публичной ссылке (UJ-3)

**Протагонист:** Алексей, коллега, не друг.

1. Анонимно открывает ссылку и видит «Наушники» (видимость «всем»). Клавиатуру «для друзей» не видит и не знает, что она есть.
2. Жмёт «Куплю сам» → регистрация → возврат на ту же ссылку. Другом не стал.
3. Бронирует «Наушники».
4. **Кульминация:** бронь видна; желания «для друзей» по-прежнему отсутствуют в списке.

### Flow 4 — Марина, уже друг, открывает ту же ссылку (UJ-3b)

1. Видит публичные желания и желания «для друзей».
2. **Край:** подписчик на той же ссылке видит только публичные, без текста «остальное скрыто».

### Flow 5 — Дима снимает бронь (UJ-4)

1. **Мои брони** → «Снять бронь» → confirm.
2. **Кульминация:** подарок `открыт`; владелец получает in-app уведомление.

### Flow 6 — Бывший друг и бронь (UJ-5)

1. Сергей удаляет Диму из друзей.
2. Дима по FO-ссылке видит **gate** (не 404).
3. **Кульминация:** в **Мои брони** бронь жива со всем циклом сроков; может продлить, отметить «Купил» / «Подарил», снять. Названия других FO-подарков не утекают.

### Flow 7 — Забытая бронь (UJ-7)

1. Срок брони Димы наступил → уведомление + письмо с действиями «Подарил» / «Купил, ещё не вручил» / «Продлить до…» / «Снять бронь».
2. Дима молчит 3 дня → Сергею «Срок брони «Y» истёк, даритель пока не ответил. Подарок уже у вас?».
3. **Кульминация:** Сергей жмёт «Не получал, оставить бронь» → Диме «Владелец продлил вашу бронь «Y» до DD.MM».

**Край:** оба молчат 7 дней, «Купил» нет → бронь снята, оба получают уведомление и письмо.
**Край:** «Купил» стоит → бронь висит с меткой «Срок брони истёк», новых уведомлений нет.

### Flow 8 — Подарок пришёл не через сервис

1. Сергей получил «Наушники» от коллеги офлайн; на подарке анонимная бронь.
2. «Отметить полученным» → confirm → toast «Отмечено полученным · Отменить».
3. **Кульминация:** через 10 с держателю «Владелец отметил «Наушники» полученным. Если вы его ещё не вручали — подарок пришёл от кого-то другого».

### Flow 9 — Напоминание о ДР (UJ-8)

1. До ДР Сергея 14 дней; у него 4 открытых подарка, видимых Марине.
2. Около 10:00 по её поясу Марине приходит письмо и уведомление «У Сергея день рождения 14 ноября» с тремя названиями.
3. «Открыть списки» → вход, если нет сессии → Профиль Сергея → «Куплю сам» (Flow 2).
**Край:** все подарки заняты или ДР скрыт → письма нет.
**Край:** «Отписаться» в футере → `/unsubscribe/{token}` → «Вы отписались от напоминаний о днях рождения друзей» · «Вернуть».

### Flow 10 — Подписка и контакты

1. Сергей разрешает контакты. В списке появляется Марина, потому что номер совпал. Дружба не создаётся.
2. Он открывает её профиль и видит только желания «всем». День рождения не показан.
3. «Подписаться» оставляет тот же объём. «Добавить в друзья» — заявка, как раньше.
**Край:** разрешение контактов отклонено → поиск по нику работает, экран не блокируется.

### Flow 11 — Предложить идею

1. Сергей пишет брату идею «рыбацкий дождевик» и снимает галочку «показать, что это я».
2. Брат получает уведомление туда, где у него включены каналы.
3. Брат принимает и оставляет видимость «друзьям».
4. **Кульминация:** у брата в вишлисте появляется обычное желание. У Сергея нет отдельной кнопки «забронировать первым». Если желание видно Сергею, он бронирует его как любое другое. Брат имя не видел.
**Край:** брат прячет желание в «секрет» → права брони нет.

### Flow 12 — Удаление аккаунта

1. Настройки → «Удалить аккаунт» → подтверждение с именем.
2. **Кульминация:** сессия закончилась, ссылка вишлиста открывается как «не найдено». Тот же путь на вебе и в приложении.

### Flow 13 — Срок желания через 3 дня (D-26)

1. Марина забронировала «Билет на БИ-2». У желания дата окончания через 3 дня.
2. Около 10:00 по её поясу приходит одно письмо и уведомление: «Срок желания «Билет на БИ-2» через 3 дня».
3. **Кульминация:** в день даты, если бронь ещё активна и покупка не отмечена, желание уходит в архив, Марина получает «Срок вышел» и может отметить «Подарил» или снять бронь.
**Край:** Марина забронировала за день до даты → письма «через 3 дня» нет, есть только письмо в день срока.
**Край:** она уже отметила «Купил» → в день срока бронь не снимается, просят отметить вручение.
