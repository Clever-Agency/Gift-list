# Gift List — Experience Spine

> Раунд 1. Визуал — в `DESIGN.md` (токены `{path.to.token}`). Этот spine — IA, поведение, состояния, микрокопирайт, journeys. Spines выигрывают у mockups при конфликте.
> Оплата, Сбор, ЮKassa, share-sheet, per-gift links — **вне** этого документа.

## Foundation

- **Форм-фактор:** адаптивный веб; mobile browser — first-class (PRD §7).
- **UI-система:** [ASSUMPTION: UX-A1] shadcn/ui на Next.js + Tailwind; behavioral delta здесь, visual delta в `DESIGN.md`.
- **Локаль:** [ASSUMPTION: UX-A9] UI на русском; multi-locale вне R1.
- **Тема:** [ASSUMPTION: UX-A8] только light.
- **Аутентификация:** все продуктовые экраны списков/брони — после сессии (A-1). Аноним на Ссылке на список / deep-link — gate «войти», без Подарков.
- **Стейки:** [ASSUMPTION: UX-A10] consumer/hobby (узкий круг); ошибка статуса брони дороже отсутствующей «вау»-фичи.

## Information Architecture

|---------|----------------------|-----|------------|

| Профиль | `/u/{ник}` | auth | Карточка человека + Discoverable; Friends-only только Другу (FR-7) |
| Поиск | `/search` | auth | Ник / отображаемое имя (FR-6) |
| Друзья | `/friends` | auth | Друзья, входящие, исходящие (FR-15) |

**Глобальный chrome (auth):** верхняя полоса — логотип Gift List → Мои списки; иконки Поиск, Друзья (badge входящих), Уведомления (badge), «Мои брони», Avatar → настройки/выход. На `< md` — нижняя tab-bar: Списки · Поиск · Друзья · Брони · Ещё.

**Не в IA R1:** оплата, «Мои взносы», payout, share-sheet, лента, OAuth, dark toggle, self-serve delete (только копирайт), self-serve репорт (UX-A2).

**Closure check:** UJ-1→Мои списки+Друзья+копирование; UJ-2→Друзья+Ссылка/Профиль+бронь; UJ-3→Ссылка Discoverable; UJ-3b→Ссылка Friends-only (+gate); UJ-4→Мои брони; UJ-5→gate + Мои брони.

## Voice and Tone

Микрокопирайт. Brand voice — `DESIGN.md` Brand & Style.

| Do | Don't |
|----|-------|
| «Куплю сам» | «Забронировать айтем» / «Claim gift» |
| «Этот список только для друзей {Имя}» | «Доступ запрещён» / «404» / пустой экран |
| «Ссылка скопирована» | «Successfully copied to clipboard!» |
| «Марина берёт этот подарок» | Скрывать имя бронировавшего (A-23) |
| «Подарок закрыт — уже получен» | «Error: closed state» |
| «Войдите, чтобы увидеть подарки» | Показывать названия подарков анониму |
| Спокойно про конкуренцию: «Кто-то только что забрал этот подарок» | Обвинять пользователя |
| Без обещаний оплаты в R1 | Кнопка «Скоро можно будет оплатить» как CTA |

**Friends-only gate (канон D-11):**  
Заголовок (`display-sm`): «Список только для друзей».  
Текст: «Подарки из этого списка видят только люди из списка друзей {Отображаемое имя}. Станьте друзьями в Gift List, чтобы открыть их.»  
CTA: если есть профиль → «Открыть профиль {имя}» (Discoverable виден; приглашение оттуда); secondary — «Найти в поиске». **Не** показывать состав/названия Подарков.

**Anon gate на любой Ссылке на список:**  
«Чтобы посмотреть этот список, войдите или зарегистрируйтесь.» CTA: Войти / Создать аккаунт. После входа — тот же URL; дальше по правилам FR-27.

## State Patterns

| Состояние | Поверхность | Поведение |
|-----------|-------------|-----------|
| Cold load | Любая | Skeleton карточек/строк под ожидаемый layout. |
| Пустой свой список | Мои списки | Empty gifts (выше). |
| Пустой Discoverable у другого | Профиль / ссылка | «У {имя} пока нет открытых подарков.» Без CTA создания. |
| Friends-only, друг, пусто | Ссылка FO | «Пока нет подарков в списке для друзей.» |
| Friends-only, не-друг | Ссылка FO | **Gate-объяснение** (не empty, не 404). |
| Friends-only, аноним | Ссылка FO | Anon gate → после входа gate или подарки. |
| Discoverable, аноним | Ссылка D | Anon gate; после входа — подарки. |
| Список не найден | `/l/{bad}` | «Список не найден.» — **только** для невалидного token; не для отказа не-другу. |
| Профиль не найден | `/u/{bad}` | «Пользователь не найден.» |
| Гонка брони | Деталь | Toast: «Кто-то только что забрал этот подарок.» Карточка → `забронирован` с чужим именем. |
| Сеть недоступна | Действие | Toast destructive: «Нет сети. Попробуйте ещё раз.» Не молчаливый fail. |
| Снята бронь / таймаут 14д | Мои брони, уведомления | Статус снова `открыт`; уведомление бронировавшему (A-9). |
| Unfriend при активной брони | FO / Мои брони | FO скрыт → gate по ссылке; бронь живёт в «Мои брони» (UJ-5, A-14). |
| Скрыт из поиска | Поиск | Не в выдаче; прямые `/u/{ник}` и Ссылки на списки работают (FR-8). |
| Pending invite | Профиль | Не показывать FO; chip «Ожидает ответа». |

**Статусы подарка (R1) — единый словарь UI:**

| Код | Label pill | Даритель видит | Владелец доп. |
|-----|------------|----------------|---------------|
| `открыт` | Открыт | «Куплю сам» | Редактировать, перенести, удалить |
| `забронирован` | Забронирован | «Берёт {имя}»; снять — только держатель | Снять чужую бронь; «Отметить полученным» → `закрыт` |
| `закрыт` | Закрыт | Без действий | Можно оставить в истории списка; удаление — с confirm |

Нет UI для `сбор` / оплаты в R1.

## Interaction Primitives

- **Primary input:** touch + pointer; формы — клавиатура.
- **Бронь:** один тап/клик по «Куплю сам» → confirm-dialog короткий: «Забронировать «{название}»? Другие увидят, что подарок берёте вы.» → Подтвердить / Отмена. Confirm нужен: необратимость социальной координации важнее скорости (SM-2).
- **Снятие своей брони:** confirm «Снять бронь? Подарок снова станет открытым.»
- **Закрытие владельцем:** confirm «Отметить как полученный? Вернуть в открытые будет нельзя из этого статуса в R1.» *[ASSUMPTION: UX-A11] R1 не даёт «открыть снова» после `закрыт`; правка — на подтверждение.*
- **Копирование ссылки:** без confirm; Toast.
- **Удаление подарка `забронирован`:** сильный confirm + предупреждение, что бронь снимется и бронировавший получит уведомление (FR-10).
- **Esc / overlay:** закрывает dialog/sheet; не сбрасывает черновик формы без «Отменить».
- **Banned R1:** infinite scroll как единственный способ (пагинация/«ещё» ок при >50); drag-reorder; hover-only actions на mobile; modal stack >1; рабочие кнопки оплаты.

## Accessibility Floor

Behavioral; контраст — `DESIGN.md` / shadcn AA.

- WCAG 2.2 AA на ключевых потоках: регистрация, бронь, Friends-only gate, копирование ссылки.
- Каждое поле формы — видимый `<label>`; ошибки — текст рядом с полем, не только цвет.
- Status pill не кодирует смысл одним цветом: всегда текст («Открыт» / …).
- Focus ring `{colors.ring}` на всех интерактивных.
- Gate Friends-only и anon gate — заголовок уровня `h1`, объявляется screen reader при входе на страницу.
- Toast — `aria-live="polite"`; гонка брони — `assertive`.
- Нижняя tab-bar: `aria-current="page"`.
- Не полагаться на hover для снятия брони / меню владельца на touch.

## Inspiration & Anti-patterns

- **Взять:** дисциплину «один ясный статус» у хороших RSVP/registry; спокойный copy у Linear-like tools (без hype).
- **Отвергнуть:** Amazon Wishlist «buy for me» checkout в R1; тайные брони без имени (против A-23); empty state вместо FO gate; «не найдено» как soft-deny; feed/stories друзей; gamification streaks.

## Key Flows

Имена и сценарии зеркалят PRD UJ-*; кульминация обязательна.

### Flow 1 — Сергей готовит два списка (UJ-1)

**Протагонист:** Сергей, владелец, вечер перед днём рождения.

1. Уже в сессии; открывает **Мои списки**.
2. В «Открытый» добавляет «Наушники» (цена 8 000 ₽) и «Книга по кухне» (без цены).
3. В «Только друзья» — «Механическая клавиатура» и «Ужин в любимом месте».
4. Копирует Ссылку на Friends-only; кидает Марине в мессенджер (вне продукта).
5. Через Поиск находит Марину → «Добавить в друзья».
6. **Кульминация:** Марина принимает (уведомление Сергею). Сергей открывает превью FO как Друг с другой сессии / проверяет, что до принятия ссылка у неё показывала gate. Оба списка наполнены; ссылки скопированы.
7. **Резолюция:** ждёт броней; статусы обновляются без чата-координации.

**Край:** Дима отклоняет инвайт → FO скрыт; Сергей видит «Отклонено».

**Failure:** ник занят при смене в настройках → inline error «Этот ник уже занят».

### Flow 2 — Марина бронирует Friends-only (UJ-2)

**Протагонист:** Марина, близкая подруга.

1. Принимает приглашение на **Друзья**.
2. Открывает Ссылку на FO (или Профиль Сергея — видит оба списка).
3. Открывает «Механическая клавиатура» → «Куплю сам» → confirm.
4. **Кульминация:** pill «Забронирован», подпись «Берёт Марина»; кнопка у других недоступна.
5. Покупает вне сервиса; позже Сергей жмёт «Отметить полученным» → `закрыт`.

**Край (гонка с Димой):** второй получает Toast «Кто-то только что забрал…».

### Flow 3 — Алексей по Discoverable-ссылке (UJ-3)

**Протагонист:** Алексей, коллега, не друг.

1. Анонимно открывает Discoverable-ссылку → anon gate.
2. Регистрируется; редирект обратно на `/l/{token}`.
3. Видит **только** открытый Список (не FO, не обязан заходить в Профиль).
4. Бронирует «Наушники».
5. **Кульминация:** бронь видна; FO по-прежнему недоступен. Профиль `/u/sergey` — отдельный вход.

### Flow 4 — Марина по Friends-only-ссылке (UJ-3b)

1. Друг: ссылка → подарки FO.
2. **Край не-друг (auth):** та же ссылка → Friends-only gate с объяснением; zero gifts.
3. **Край аноним:** anon gate → после входа, если не друг → то же объяснение.

### Flow 5 — Дима снимает бронь (UJ-4)

1. **Мои брони** → «Снять бронь» → confirm.
2. **Кульминация:** подарок `открыт`; владелец получает in-app уведомление.

### Flow 6 — Бывший друг и бронь (UJ-5)

1. Сергей удаляет Диму из друзей.
2. Дима по FO-ссылке видит **gate** (не 404).
3. **Кульминация:** в **Мои брони** бронь жива; может снять. Названия других FO-подарков не утекают.
