# Gift List — Experience Spine

> MVP после D-20…D-42. Визуал — в `DESIGN.md` (разделы App и Next-страницы). Этот spine — поведение, одно на Android, iOS и браузер.
> Оплата, денежный сбор, share-sheet, per-gift links — **вне** этого документа.
> **`prototype/index.html` устарел** (2026-10-28): в нём два списка, Friends-only gate и веб-sidebar. Модель брони D-12 / D-13 там верна, оболочка и модель видимости — нет. Актуальный макет — [`mockups/app-key-screens.html`](mockups/app-key-screens.html): Мой вишлист, деталь и бронь, Друзья и «Найти знакомых», Мои брони, `/l` и вход. Правило старшинства — `DESIGN.md`, в начале.

## Foundation

- **Форм-фактор (D-40):** одно приложение Expo на Android, iOS и в браузере — все потоки одинаковы. В браузере нет только сверки книги контактов: вместо неё поиск по нику и ненавязчивая подсказка установить приложение. Next.js отдаёт четыре свои страницы: `/l/{token}`, `/i/{token}`, `/unsubscribe/{token}`, `/admin`. Выход iOS — шаг публикации, поведение не меняет. Сначала Google Play, затем App Store. Имя продукта на экранах берётся из одной переменной, не из текста макета (D-35, AD-24).
- **UI-система:** приложение — React Native (react-native-web в браузере) по разделу **App** в `DESIGN.md`: одна спека с адаптивными раскладками, отдельного дизайна для веба нет. Next-страницы — shadcn/ui на Next.js + Tailwind (UX-A1 принято в AD-2), раздел **Next-страницы**. Behavioral delta здесь, visual delta в `DESIGN.md`.
- **Локаль:** [ASSUMPTION: UX-A9] UI на русском; multi-locale вне R1.
- **Тема:** [ASSUMPTION: UX-A8] только light.
- **Аутентификация:** бронь, друзья и свой вишлист — после сессии. Аноним на `/l/{token}` видит желания «всем» и кнопку «Куплю сам», которая ведёт на вход (D-29).
- **Стейки:** [ASSUMPTION: UX-A10] consumer/hobby (узкий круг); ошибка статуса брони дороже отсутствующей «вау»-фичи.

## Information Architecture

Две поверхности на одном домене (AD-26): **приложение** (Expo; на Android и iOS — установленное, в браузере — веб-сборка) и **Next-страницы**. Маршрут приложения в браузере — настоящий URL: глубокая ссылка, обновление и «назад» ведут на тот же экран. На телефоне те же пути открываются через App Links / Universal Links.

**Next-страницы** (серверный рендер; своего UI вошедшего нет)

| Страница | Кто | Назначение |
|----------|-----|------------|
| `/l/{token}` | аноним — смотрит здесь; вошедший — передаётся в приложение | Имя владельца и желания «всем»; мета-теги превью; «Куплю сам» → вход в приложении (D-29, Story 3.3) |
| `/i/{token}` | аноним / вошедший | Приглашение: «Принять» → регистрация в приложении; вошедший → подтверждение в приложении (Story 4.7) |

**Навигация приложения** — состав и вид в `DESIGN.md` → App → Навигация (UX-A13, принято). Здесь — только правила поведения:

- Активный раздел — `aria-current="page"` в браузере, `accessibilityState.selected` на телефоне.
- Вложенные экраны (деталь, профиль, настройки) открываются поверх раздела, из которого пришли; вкладка остаётся подсвеченной.
- Системное «назад» (Android, жест iOS, кнопка браузера) закрывает верхний экран или слой. На корневом экране вкладки Android «назад» сначала возвращает на «Вишлист», затем сворачивает приложение.
- Переход по ссылке из письма или App Link открывает экран внутри правильной вкладки, «назад» ведёт к её корню, а не наружу.
- Анонимные экраны (вход, регистрация, сброс) — без вкладок и меню.

**Не в IA R1:** оплата, платная подписка, «Мои взносы», payout, share-sheet, лента, OAuth, тёмная тема, жалобы и репорты (D-34), «Предложить идею» (Раунд 1.5, D-42). Удаление аккаунта — есть, Flow 12.

**Closure check:** UJ-1→Мой вишлист + Форма желания + Поиск + копирование; UJ-2→Друзья + Профиль/Вишлист по ссылке + бронь; UJ-3→`/l` (аноним) → вход → Вишлист по ссылке; UJ-3b→Вишлист по ссылке у друга; UJ-4→Мои брони; UJ-5→Вишлист по ссылке без желаний «друзьям» + Мои брони; UJ-7→Уведомления + Мои брони + карточка владельца; UJ-8→письмо → Профиль; знакомые→Найти знакомых (телефон) / Поиск (браузер); приглашение→`/i` → Регистрация / «Добавить в друзья?» (Flow 15); теги и архив→Форма + Мой вишлист (Flow 16); подборки→Подборки (Flow 17); блок→Профиль + Настройки. «Ближайшие даты» отложены (UX-A16).

## Voice and Tone

Микрокопирайт. Brand voice — `DESIGN.md` Brand & Style.

| Do | Don't |
|----|-------|
| «Куплю сам» | «Забронировать айтем» / «Claim gift» |
| «Пока нет открытых желаний» — когда зрителю нечего показать | «Часть желаний скрыта», «Доступ запрещён», «404» |
| «Установите приложение: поиск друзей по контактам» — один раз, с крестиком | «Скачайте приложение, чтобы продолжить» |
| «Ссылка скопирована» | «Successfully copied to clipboard!» |
| «Берёт Марина» — только тем, кому Марина разрешила | Показывать имя владельцу без согласия дарителя (D-13) |
| «Срок брони истёк» + понятные кнопки | «Вы забыли!», «Напоминаем ещё раз» |
| «Подарок у вас?» | «Подтвердите, что даритель не врёт» |
| «Подарок закрыт — уже получен» | «Error: closed state» |
| «Чтобы забронировать «{название}», войдите или зарегистрируйтесь» | Прятать желания «всем» от анонима за входом |
| «Время на отмену вышло» | «Ошибка 409» |
| Спокойно про конкуренцию: «Кто-то только что забрал этот подарок» | Обвинять пользователя |
| Без обещаний оплаты в R1 | Кнопка «Скоро можно будет оплатить» как CTA |

**Аноним на ссылке вишлиста (`/l`):** желания «всем» видны сразу. На экране входа после «Куплю сам»: «Чтобы забронировать «{название}», войдите или зарегистрируйтесь.» После входа — вишлист этого человека в приложении с открытым confirm брони, без новой дружбы.

**Пусто, когда скрытое не показывают:** «Пока нет открытых желаний.» Не писать «список только для друзей» и не показывать число скрытых. Friends-only gate снят (D-23).

**Словарь.** В интерфейсе — «желание» и «вишлист» в единственном числе: «Открыть вишлист», «обновите вишлист», «Деталь желания». «Подарок» — только в устойчивых фразах о вручении: «Подарок у вас?», «Кто-то только что забрал этот подарок», «Уже подарено», «Подарил». Слова «списки» во множественном числе нет: вишлист один (D-23).

**«Найти знакомых» в браузере:** заголовок «Найти знакомых»; текст «Сверка с контактами работает в приложении на телефоне. Здесь можно найти человека по нику или имени.»; поле поиска сразу под текстом; ниже — подсказка установить приложение (если её не закрыли).

**Отношение → статус и меню.** Одно правило для строки человека в Поиске, Друзьях, Подписках, Моих подписчиках, Найти знакомых и для кнопок в профиле (там те же действия, только кнопками). Chip показывает одно, самое сильное отношение; подписки в обе стороны — «Взаимная подписка».

| Отношение со мной | Chip | Меню ⋯ (по порядку) |
|-------------------|------|---------------------|
| Нет | — | Открыть профиль · Добавить в друзья · Подписаться · ─ · Заблокировать |
| Я отправил приглашение | Ожидает ответа | Открыть профиль · Отменить приглашение · Подписаться / Отписаться · ─ · Заблокировать |
| Он отправил мне приглашение | Зовёт в друзья | Открыть профиль · Принять приглашение · Отклонить · Подписаться / Отписаться · ─ · Заблокировать |
| Я отклонил его приглашение < 24 ч назад | — | Как «Нет», но «Добавить в друзья» недоступно: «Можно снова через N ч» (A-16) |
| Друзья | Друзья | Открыть профиль · ─ · Удалить из друзей · Заблокировать |
| Я подписан | Вы подписаны | Открыть профиль · Добавить в друзья · Отписаться · ─ · Заблокировать |
| Он подписан на меня | Подписан на вас | Открыть профиль · Добавить в друзья · Подписаться · ─ · Убрать подписчика · Заблокировать |
| Подписаны друг на друга | Взаимная подписка | Открыть профиль · Добавить в друзья · Отписаться · ─ · Убрать подписчика · Заблокировать |
| Это я | Это вы | Меню нет, строка ведёт в мой профиль |
| Блок (в любую сторону) | — | Строки нет: заблокированный не виден в поиске и списках (AD-7). Разблокировать — Настройки → «Заблокированные» |

Правила:
- У друга нет пунктов подписки: дружба уже даёт больше, чем подписка (Story 4.6). При «Удалить из друзей» подписки не создаются автоматически.
- «Добавить в друзья» при встречном приглашении сразу делает друзьями (ARCH-A12) — в меню это пункт «Принять приглашение».
- Подтверждение нужно только для «Удалить из друзей» («Удалить {имя} из друзей? Желания «друзьям» перестанут быть видны друг другу. Брони останутся.»), «Убрать подписчика» («{имя} перестанет видеть ваши желания «всем» в подписках.») и «Заблокировать» (текст — паттерн Block). Остальное — сразу, toast: «Приглашение отправлено», «Приглашение отменено», «Вы подписались», «Вы отписались», «{имя} теперь в друзьях», «{имя} больше не подписан».
- После действия строка остаётся на месте, меняется только chip; фокус возвращается на ⋯ этой строки. В «Подписках» и «Моих подписчиках» строка после «Отписаться» / «Убрать подписчика» исчезает — фокус по правилу «Куда уходит фокус».
- Optimistic UI с откатом и toast «Нет сети. Попробуйте ещё раз.»
- Подпись ⋯ для диктора: «Действия: {имя}»; chip входит в подпись строки: «Олег Сидоров, @oleg_s, друзья».

## State Patterns

| Состояние | Поверхность | Поведение |
|-----------|-------------|-----------|
| Cold load | Любая | Skeleton карточек/строк под ожидаемый layout; через 10 с без ответа — экран «Нет сети при загрузке». |
| Нет сети при загрузке / ошибка загрузки | Любой экран списка | Вместо skeleton: «Не получилось загрузить. Проверьте сеть.» + «Повторить» (primary). Уже показанные данные не стираются, если ошибка при обновлении — тогда toast. |
| Сессия истекла | Любой auth-экран | Ответ 401 → экран входа с `?next=` на текущий экран; toast «Сессия закончилась, войдите снова». Черновик формы сохраняется локально и возвращается после входа. |
| Желание не найдено | `/gifts/{id}` по прямой ссылке | Один текст для всех случаев — нет права (unfriend, Block, `секрет` чужого), удалено, в архиве у чужого: «Желание не найдено.» + «К моему вишлисту». Без «скрыто» и без разницы в текстах (AD-7). |
| Пустой экран | См. Empty states | Тексты — таблица Empty states. |
| Зрителю нечего показать | Профиль, Вишлист по ссылке, `/l` | «Пока нет открытых желаний.» Без CTA создания, без числа скрытых. Одинаково для анонима, подписчика, не-друга и друга. |
| Аноним на `/l` | `/l/{token}` | Видит желания «всем»; «Куплю сам» → вход в приложении (Voice and Tone). |
| Вошедший на `/l` | `/l/{token}` → приложение | Сразу экран «Вишлист по ссылке», без промежуточной страницы. |
| Список не найден | `/l/{bad}`, Block, удалённый аккаунт | «Список не найден.» |
| Нет приложения на телефоне | App Link `/l`, `/i`, письмо | Открывается тот же экран в браузере; на Android/iOS-браузере вверху «Найти знакомых» — Install hint. |
| Профиль не найден | `/u/{bad}` | «Пользователь не найден.» |
| Гонка брони | Деталь | Toast: «Кто-то только что забрал этот подарок.» Карточка → `забронирован` (имя — по видимости держателя). Тот же toast, если желание заняли, пока зритель входил по `?next=`: confirm не открывается. Если его удалили за это время — «Желание не найдено». |
| Сеть недоступна | Действие | Toast destructive: «Нет сети. Попробуйте ещё раз.» Не молчаливый fail. |
| Срок брони истёк | Мои брони, уведомления, карточка | Держателю — уведомление с действиями; через 3 дня — запрос владельцу; через 7 дней молчания — снятие, если нет «Купил» (FR-29). |
| Бронь с «Купил», оба молчат | Карточка владельца, Мои брони | Подписи по таблице «Подписи брони»; без новых уведомлений. |
| Владелец изменил / удалил забронированное желание | Держатель | Уведомление + письмо. |
| Закрыто, окно отмены открыто | Мой вишлист, деталь | Карточка в «Получено» с «Вернуть в открытые · ещё N мин». После 10 мин кнопки нет. |
| Срок желания вышел | Мой вишлист | Без брони или с бронью без «Купил» — желание в «Архиве». С «Купил» / после «Подарил» — остаётся на месте до закрытия (Story 2.6). |
| Unfriend при активной брони | Вишлист по ссылке / Мои брони | Желания «друзьям» пропадают без объяснения; бронь живёт в «Мои брони» как reservation card (UJ-5, A-14). |
| Скрыт из поиска | Поиск | Не в выдаче; прямые `/u/{ник}` и ссылка на вишлист работают (FR-8). |
| Pending invite | Профиль | Желания «друзьям» не видны; chip «Ожидает ответа». |
| Контакты запрещены | Найти знакомых (телефон) | Поиск по нику; экран не блокируется (FR-50). |
| Браузер, контакты | Найти знакомых (браузер) | Объяснение + поиск по нику; запроса разрешения нет. |
| `/i`, своя ссылка | `/i/{token}` → приложение | «Это ваша ссылка-приглашение. Отправьте её друзьям.» + «Скопировать». |
| `/i`, уже друзья | `/i/{token}` → приложение | «Вы уже друзья с {имя}.» + «Открыть вишлист». |
| `/i`, Block или невалидный токен | `/i/{token}` | «Приглашение не найдено.» Один текст. |
| `/unsubscribe`, невалидный токен | `/unsubscribe/{bad}` | «Ссылка недействительна. Управлять письмами можно в настройках приложения.» |
| `/admin`, аноним или USER | `/admin` | «Не найдено.» Без формы входа. |

| `открыт` | Открыт | «Куплю сам» | — | Редактировать, видимость, удалить, «Отметить полученным» |
| `забронирован` | Забронирован | Подписи брони (выше) | Подписи брони; продлить, Купил, Подарил, видимость, снять | Без имени (если не разрешено), без «Куплен»; снять чужую бронь (с предупреждениями); «Отметить полученным»; ответы на запросы; редактировать (с уведомлением держателю); видимость и quantity не меняются |
| `закрыт` | Получен | В секции «Уже подарено» | — | Секция «Получено»; «Вернуть в открытые» в окне 10 мин; «Хочу ещё такой»; удалить с confirm |

Нет UI для `сбор` / оплаты в R1.

## Interaction Primitives

- **Primary input:** касание на Android и iOS; мышь, касание и клавиатура в браузере. Hover, фокус, Tab и Esc — `DESIGN.md` → App → Мышь и клавиатура.
- **Бронь:** один тап/клик по «Куплю сам» → Reserve confirm (дата + два переключателя, см. Component Patterns) → Подтвердить / Отмена. Confirm нужен: необратимость социальной координации важнее скорости (SM-2).
- **Снятие своей брони:** confirm «Снять бронь? Желание снова станет открытым.»
- **Закрытие владельцем:** confirm «Подарок «{название}» получен?» (+ при брони «Бронь будет закрыта, бронировавший получит уведомление»); затем undo toast «Отменить» и 10 мин на «Вернуть в открытые» (D-43). Уведомление держателю — после окна. Иного возврата нет *[UX-A11]*.
- **Снятие чужой брони владельцем:** confirm; при «Купил» — «Даритель отметил, что подарок уже куплен. Если снять бронь, его может купить кто-то ещё»; при «Подарил» — основные «Получил» / «Не получал».
- **Правка забронированного желания:** hint в форме «Желание забронировано — бронировавший получит уведомление». Видимость и «Один раз / Можно дарить снова» заблокированы.
- **Копирование ссылки:** без confirm; Toast.
- **Удаление желания `забронирован`:** сильный confirm + предупреждение, что бронь снимется и бронировавший получит уведомление (FR-10); при «Купил» — предупреждение «уже куплен»; при «Подарил» основное действие — «Отметить полученным».
- **Esc / scrim / системное «назад»:** закрывает верхний слой (меню, шторку, диалог, деталь); внутри диалога сначала возвращает прежний шаг. Фокус возвращается на то, что слой открыло, а если его нет — по правилу `DESIGN.md` → App → Доступность «Куда уходит фокус». Черновик формы не теряется молча: при изменениях — шаг «Не сохранять изменения?».
- **Шторка vs диалог:** compact — шторка снизу (закрывается свайпом вниз, scrim, «назад» и видимой кнопкой «Отмена» / «Закрыть»); medium и шире — диалог по центру. Поведение и тексты одинаковы. Confirm внутри детали или формы — шаг того же слоя, не второй слой.
- **Banned R1:** infinite scroll как единственный способ (исключение: список друзей — подгрузка при прокрутке допустима, потому что есть строка поиска; в остальных списках — пагинация/«ещё» при >50); drag-reorder; hover-only actions на mobile; modal stack >1; рабочие кнопки оплаты.

## Accessibility Floor

Behavioral; контраст и размеры — `DESIGN.md` → Colors и App → Доступность.

- **Цель:** WCAG 2.2 AA в браузере (веб-сборка приложения и Next-страницы); TalkBack и VoiceOver на Android и iOS; касание не меньше 44×44 везде.
- Ключевые потоки проверяются на всех трёх платформах: регистрация, «Куплю сам» (confirm с датой и двумя переключателями), «Отметить полученным» + «Отменить», копирование ссылки, `/l` анонимом (Story 6.4).
- Undo toast: объявляется через постоянный ToastHost (`DESIGN.md` → App → Доступность); на паузе при hover и фокусе, при включённом дикторе не скрывается сам. Отмена доступна 10 мин и без toast — «Вернуть в открытые» на карточке (WCAG 2.2.1, D-43). При появлении toast фокус не переносится; после закрытия желания фокус — на «Отменить» (правило «Куда уходит фокус»).
- Гонка брони и «Нет сети» — объявляются сразу (`assertive`).
- Каждое поле — видимая подпись, связанная с полем (`<label>` / `accessibilityLabel` = подпись); ошибка — текстом рядом, программно связана с полем (`aria-describedby` / `accessibilityHint`), при отправке — сводка объявляется, фокус переходит к первому полю с ошибкой. Автозаполнение и показ пароля — `DESIGN.md` → Поля входа (3.3.8, 1.3.5).
- Status pill, чип видимости, фаза брони — смысл словом, не цветом.
- Заголовок экрана — `h1` в браузере, `accessibilityRole="header"` на телефоне; при переходе фокус диктора — на заголовок. В браузере у каждого маршрута свой `document.title`; `lang="ru"`; landmarks и skip link — `DESIGN.md` → App → Доступность.
- Навигация: в браузере нижние вкладки и боковое меню — `<nav aria-label="Разделы">` со ссылками и `aria-current="page"` (это переходы по URL, не `tablist`); на Android/iOS вкладки — `accessibilityRole="tab"` + `selected`. Badge входит в подпись («Друзья, 2 запроса»). Выбранный раздел — не только цветом.
- Меню пользователя и ⋯: `aria-haspopup="menu"` + `aria-expanded`, пункты `menuitem`, стрелки и Esc.
- Шторка и диалог: фокус внутрь при открытии, ловушка фокуса, возврат при закрытии (с запасным правилом, если открывшего элемента нет); на телефоне — `accessibilityViewIsModal` / `importantForAccessibility` у фона. Деталь, открытая по прямой ссылке, — фокус на заголовке.
- Сегмент «Друзья · Подписки · Запросы» переключает панели на одном экране: `tablist`/`tab`/`tabpanel`, `selected`, стрелки; подгрузка объявляется («Загружаем…», «Показаны все (N)»).
- Карточка желания: основная зона — ссылка на деталь, чип и ⋯ — соседние элементы, плюс `accessibilityActions` (`DESIGN.md` → WishCard).
- «Написать автору» есть на всех экранах: у вошедшего — в «Профиле» / меню пользователя, у анонима и на Next-страницах — в футере (3.2.6).
- Переключатели в confirm брони — `switch` с состоянием (`aria-checked`); вся строка нажимается.
- Системный размер шрифта до 200% не ломает потоки (высоты — `min-height`); «уменьшить движение» убирает сдвиги и мерцание скелетона. Ориентация не блокируется.
- Ничего не доступно только по hover или только жестом: у свайпа всегда есть кнопка.

## Responsive & Platform

Одна спека приложения с адаптивными раскладками; поведение и тексты на всех платформах одинаковы. Визуал раскладок — `DESIGN.md` → App → Точки перехода и Широкий экран *[ASSUMPTION: UX-A12]*.

| Класс ширины | Навигация | Списки желаний | Слои | Прочее |
|--------------|-----------|----------------|------|--------|
| compact | Нижние вкладки + колокольчик в шапке | Одна колонка | Шторка снизу; деталь — отдельный экран | «Куплю сам» прилипает к низу |
| medium | Нижние вкладки + колокольчик | Сетка | Диалог по центру; деталь — экран | Правой колонки нет |
| expanded | Боковое меню, без шапки с колокольчиком | Сетка | Диалог по центру; деталь — диалог поверх сетки с URL `/gifts/{id}` | — |
| wide | Боковое меню | Сетка | Как expanded | В браузере — правая колонка с подсказкой установить приложение, пока её не закрыли |

Границы классов и число колонок сетки — только в `DESIGN.md` → App → Точки перехода.

Смена ширины (поворот, изменение окна) не теряет состояние: открытый диалог становится шторкой и обратно, черновик формы сохраняется, прокрутка списка остаётся на той же карточке.

| Платформа | Отличия |
|-----------|---------|
| **Android** | Системная «назад» на всех экранах (см. IA). App Links открывают `/l`, `/i`, ссылки из писем в приложении. Сверка контактов (`expo-contacts`). Сессия — токен в `expo-secure-store` |
| **iOS** | Жест «назад» от края; шторки — системные модальные. Universal Links. Сверка контактов. Выход в App Store — после Google Play, поведение то же. Ориентация — любая (`"orientation": "default"` и на Android) |
| **Браузер** (веб-сборка приложения) | Всё, кроме сверки контактов: «Найти знакомых» объясняет и предлагает поиск по нику (Story 8.1). Свой номер в настройках указать можно. У каждого экрана свой URL; «назад», обновление и глубокая ссылка работают. Сессия — httpOnly cookie того же домена; переход с Next-страниц без повторного входа. Install hint — один, закрывается; место — `DESIGN.md`. Мышь и клавиатура — `DESIGN.md` → App |
| **Next-страницы** | `/l`, `/i`, `/unsubscribe`, `/admin` — серверный рендер, сначала телефон; первый показ без загрузки приложения (UX-DR10). Вошедшего `/l` и `/i` сразу передают в приложение. `/admin` — для компьютера |

Без PWA и офлайн-хранилища: при потере сети на действии — toast «Нет сети. Попробуйте ещё раз.»; при загрузке — экран «Не получилось загрузить» с «Повторить». Safe area — для вкладок, прилипшей «Куплю сам» и шторок на iOS и Android с жестовой навигацией.

## Inspiration & Anti-patterns

- **Взять:** дисциплину «один ясный статус» у хороших RSVP/registry; спокойный copy у Linear-like tools (без hype).
- **Отвергнуть:** Amazon Wishlist «buy for me» checkout в R1; напоминания до Срока брони и повторные «пинги» (одно письмо за 3 дня до даты окончания желания — отдельное правило D-26); автозакрытие по словам дарителя; авто-снятие купленной брони; счётчик или намёк на скрытые желания; «не найдено» вместо пустого состояния для существующего списка; растянутый телефон на широком экране; навязчивые баннеры «скачайте приложение»; feed/stories друзей; gamification streaks.

## Key Flows

Имена и сценарии зеркалят PRD UJ-*; у каждого потока протагонист и кульминация.

### Flow 1 — Сергей готовит один вишлист (UJ-1)

**Протагонист:** Сергей, владелец, вечер перед днём рождения.

1. Уже в сессии; открывает **Мой вишлист**.
2. Добавляет «Наушники» и фотографирует коробку — приложение ужимает фото до сотни килобайт. Видимость по умолчанию «всем». Добавляет «Клавиатуру» и в форме выбирает «друзьям». «Подарок для жены» ставит «секрет».
3. Копирует одну ссылку и отправляет Марине вне продукта.
4. Через поиск находит Марину → «Добавить в друзья».
5. **Кульминация:** до принятия Марина по ссылке видит только «Наушники». После принятия видит и клавиатуру. «Секрет» не видит никто, кроме Сергея, и он нигде не посчитан.
6. **Резолюция:** ждёт броней единичных желаний.

**Край:** Дима отклоняет инвайт → желания «друзьям» ему не видны; Сергей видит «Отклонено».

**Failure:** нет сети при сохранении желания → toast «Нет сети. Попробуйте ещё раз.», черновик формы остаётся.

### Flow 2 — Марина бронирует желание «друзьям» (UJ-2)

**Протагонист:** Марина, близкая подруга.

1. Принимает приглашение на **Друзья**.
2. Открывает ссылку Сергея (или его Профиль) — видит желания «всем» и «друзьям» в одном вишлисте.
3. Открывает «Механическая клавиатура» → «Куплю сам» → confirm: дата по умолчанию (+7 дней), переключатели по умолчанию.
4. **Кульминация:** pill «Забронирован»; Диме видно «Берёт Марина», Сергею — «Забронирован» без имени; кнопка у других недоступна.
5. Покупает вне сервиса → «Купил»; после праздника → «Подарил»; Сергей получает «Подарок у вас?» → «Получил» → `закрыт`.

**Край (гонка с Димой):** второй получает Toast «Кто-то только что забрал…».

### Flow 3 — Алексей по публичной ссылке (UJ-3)

**Протагонист:** Алексей, коллега, не друг.

1. Анонимно открывает ссылку и видит «Наушники» (видимость «всем»). Клавиатуру «для друзей» не видит и не знает, что она есть.
2. Страница `/l` — серверная, открылась мгновенно в браузере телефона. Жмёт «Куплю сам» → экран входа приложения «Чтобы забронировать «Наушники», войдите или зарегистрируйтесь» → регистрация → вишлист Сергея в приложении (браузерная сборка) с открытым confirm. Другом не стал.
3. Подтверждает бронь в шторке.
4. **Кульминация:** бронь видна; желания «для друзей» по-прежнему отсутствуют в списке.

**Failure:** пока Алексей регистрировался, «Наушники» забронировал кто-то другой → confirm не открывается, toast «Кто-то только что забрал этот подарок», карточка `забронирован`. Если желание удалили — «Желание не найдено».

### Flow 4 — Марина, уже друг, открывает ту же ссылку (UJ-3b)

**Протагонист:** Марина, подруга Сергея, открывает ссылку из чата.

1. Вошедшую `/l` сразу передаёт в приложение — «Вишлист по ссылке».
2. **Кульминация:** в одном вишлисте желания «всем» и «друзьям», без пометок, что кому видно.

**Край:** подписчик на той же ссылке видит только публичные, без текста «остальное скрыто».
**Край (PRD UJ-3b):** у Сергея нет желаний «всем», Марина ещё не друг → «Пока нет открытых желаний», а не «закрыто» и не «не найдено».

### Flow 5 — Дима снимает бронь (UJ-4)

**Протагонист:** Дима, друг Сергея, передумал дарить.

1. **Мои брони** → «Снять бронь» → confirm.
2. **Кульминация:** желание `открыт`; владелец получает in-app уведомление.

### Flow 6 — Бывший друг и бронь (UJ-5)

**Протагонист:** Дима, которого Сергей удалил из друзей.

1. Сергей удаляет Диму из друзей.
2. Дима по ссылке видит только желания «всем», без объяснения и без счётчика (не 404).
3. **Кульминация:** в **Мои брони** бронь жива со всем циклом сроков; может продлить, отметить «Купил» / «Подарил», снять. Названия желаний «друзьям» не утекают.

**Край (блок):** Сергей блокирует Диму → профиль и ссылка взаимно «не найдены», приглашения и подписки запрещены; бронь Димы живёт в «Мои брони» (Story 4.5, A-14).

### Flow 7 — Забытая бронь (UJ-7)

**Протагонист:** Сергей, владелец; Дима забыл про бронь.

1. Срок брони Димы наступил → уведомление + письмо с действиями «Подарил» / «Купил, ещё не вручил» / «Продлить до…» / «Снять бронь».
2. Дима молчит 3 дня → Сергею «Срок брони «Y» истёк, даритель пока не ответил. Подарок уже у вас?».
3. **Кульминация:** Сергей жмёт «Не получал, оставить бронь» → Диме «Владелец продлил вашу бронь «Y» до DD.MM».

**Край:** оба молчат 7 дней, «Купил» нет → бронь снята, оба получают уведомление и письмо.
**Край:** «Купил» стоит → бронь висит с меткой «Срок брони истёк», новых уведомлений нет.

### Flow 8 — Подарок пришёл не через сервис

**Протагонист:** Сергей, владелец.

1. Сергей получил «Наушники» от коллеги офлайн; на подарке анонимная бронь.
2. «Отметить полученным» → confirm → toast «Отмечено полученным · Отменить».
3. **Кульминация:** через 10 мин, когда окно отмены закрылось, держателю «Владелец отметил «Наушники» полученным. Если вы его ещё не вручали — подарок пришёл от кого-то другого».

**Край:** Сергей ошибся желанием и заметил через 3 минуты → в «Получено» у карточки «Вернуть в открытые · ещё 7 мин» → бронь и её фаза восстановлены, держатель ничего не получает.

### Flow 9 — Напоминание о ДР (UJ-8)

**Протагонист:** Марина, подруга Сергея.

1. До ДР Сергея 14 дней; у него 4 открытых желания, видимых Марине.
2. Около 10:00 по её поясу Марине приходит письмо и уведомление «У Сергея день рождения 14 ноября» с тремя названиями.
3. **Кульминация:** «Открыть вишлист» → вход, если нет сессии → Профиль Сергея → «Куплю сам» (Flow 2).

**Край:** все желания заняты или ДР скрыт → письма нет.
**Край:** «Отписаться» в футере → `/unsubscribe/{token}` → «Вы отписались от напоминаний о днях рождения друзей» · «Вернуть».
**Связанный путь (FR-35):** за 30 дней до своего ДР Сергей получает письмо «Скоро ваш день рождения — обновите вишлист» → «Мой вишлист».

### Flow 10 — Подписка и контакты

**Протагонист:** Сергей, ставит приложение на Android.

1. Сергей разрешает контакты. В списке появляется Марина, потому что номер совпал. Дружба не создаётся.
2. Он открывает её профиль и видит только желания «всем». День рождения не показан.
3. **Кульминация:** «Подписаться» — Марина появляется во вкладке «Подписки», объём тот же: только «всем». «Добавить в друзья» — заявка, как раньше.
**Край:** разрешение контактов отклонено → поиск по нику работает, экран не блокируется.

### Flow 11 — Предложить идею *(Раунд 1.5, D-42 — не в первом пилоте)*

1. Сергей пишет брату идею «рыбацкий дождевик» и снимает галочку «показать, что это я».
2. Брат получает уведомление туда, где у него включены каналы.
3. Брат принимает и сам выбирает видимость, например «друзьям».
4. **Кульминация:** у брата в вишлисте появляется обычное желание. У Сергея нет отдельной кнопки «забронировать первым». Если желание видно Сергею, он бронирует его как любое другое. Брат имя не видел.
**Край:** брат прячет желание в «секрет» → права брони нет.

### Flow 12 — Удаление аккаунта

1. Настройки → «Удалить аккаунт» → подтверждение с именем.
2. **Кульминация:** сессия закончилась, ссылка вишлиста открывается как «Список не найден». Тот же путь на Android, iOS и в браузере.

### Flow 13 — Срок желания через 3 дня (D-26)

**Протагонист:** Марина, держатель брони.

1. Марина забронировала «Билет на БИ-2». У желания дата окончания через 3 дня.
2. Около 10:00 по её поясу приходит одно письмо и уведомление: «Срок желания «Билет на БИ-2» через 3 дня».
3. **Кульминация:** в день даты, если «Купил» не отмечен, бронь снимается и желание уходит в архив одной операцией; Марина получает «Срок желания вышел, бронь снята» — без кнопок (Story 2.6).

**Край:** Марина забронировала за день до даты → письма «через 3 дня» нет, есть только письмо в день срока.
**Край:** она уже отметила «Купил» или «Подарил» → статус не меняется, бронь остаётся; приходит «Срок желания вышел. Если уже подарили — отметьте» + «Подарил».

### Flow 14 — Сергей ищет знакомых с ноутбука

**Протагонист:** Сергей, вечером за ноутбуком, приложение на телефон пока не ставил.

1. Открывает сервис в браузере (окно 1440 px): боковое меню слева, вишлист сеткой в 2 колонки, справа подсказка «Установите приложение: поиск друзей по контактам».
2. Друзья → «Найти знакомых». Экран объясняет, что сверка с контактами есть в приложении на телефоне, и сразу даёт поле поиска по нику.
3. Находит @marina, «Добавить в друзья». Tab-ом проходит до кнопки, Enter — заявка ушла, toast «Приглашение отправлено».
4. **Кульминация:** закрывает подсказку крестиком — она больше не появляется в этом браузере, правая колонка исчезает, сетка становится в 3 колонки. Работа не прерывалась ни разу.
5. **Резолюция:** позже ставит приложение на Android, разрешает контакты — находит ещё троих.

**Край:** узкое окно браузера (compact) — вкладки снизу, подсказка одной карточкой вверху «Найти знакомых».

### Flow 15 — Марина регистрируется по приглашению Сергея (Story 4.7)

**Протагонист:** Марина, у неё ещё нет аккаунта; Сергей прислал ссылку-приглашение в мессенджер.

1. Мессенджер строит превью `/i/{token}` — ничего не создаётся.
2. Марина открывает ссылку: серверная страница «Сергей приглашает вас в друзья» и что даст дружба.
3. «Принять приглашение» → регистрация в приложении (браузерная сборка или установленное через App Link), токен передаётся.
4. **Кульминация:** сразу после регистрации она друг Сергея и видит его желания «всем» и «друзьям» — без поиска и заявки.

**Край:** у Марины уже есть аккаунт → «У меня уже есть аккаунт» → вход → экран «Добавить Сергея в друзья?» → «Добавить» (без подтверждения ребро не создаётся).
**Край:** Сергей открыл свою же ссылку → «Это ваша ссылка-приглашение»; уже друзья → «Вы уже друзья с Сергеем».
**Failure:** невалидный токен или блок → «Приглашение не найдено».

### Flow 16 — Сергей разбирает архив (Story 2.5, 2.6)

**Протагонист:** Сергей, владелец, после праздников.

1. В форме «Велосипед» отмечает тег «мечта» и ставит «Убрать в архив после: 31.12».
2. 31 декабря желание без брони уходит в «Архив (1)» внизу вишлиста.
3. **Кульминация:** в январе он открывает «Архив» → ⋯ → «Вернуть в вишлист» без даты — желание снова `открыт`, тег на месте.

**Край:** «Скопировать» вместо возврата → новое желание `открыт` с теми же полями, архивное остаётся.

### Flow 17 — Подборка подсказывает идею (Story 10.1)

**Протагонист:** Сергей, пустой вишлист, не знает, что попросить.

1. В пустом вишлисте жмёт «Посмотреть подборки» → «Подборки» → «Для рыбалки».
2. У идеи «Термос» жмёт «Добавить в мой вишлист».
3. **Кульминация:** кнопка становится «Добавлено», toast «Добавлено в вишлист»; в «Мой вишлист» — обычное желание `открыт` с видимостью «всем».

**Край:** подборок нет → «Подборок пока нет».
