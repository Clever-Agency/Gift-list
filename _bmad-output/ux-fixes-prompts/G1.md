## Bug (reproduced live with Playwright on Expo web http://localhost:8081)
Open / then /gifts/new, type a title, press the browser Back button: the app goes to / with NO dialog; the draft is lost silently. usePreventRemove does not fire on web because the browser has already changed the URL (popstate); React Navigation's web linking then resets state to match the URL, which bypasses beforeRemove. (Verify this reasoning in apps/mobile/node_modules/expo-router/build — look at how it handles popstate/history — and state your finding in the summary.)
Spec: EXPERIENCE.md:279 «Черновик формы не теряется молча» -> same dialog «Сохранить изменения?».

## Expected
On web only (Platform.OS === "web"), while the guard is enabled (dirty, not saving, no bypass):
- Browser Back shows the SAME ConfirmDialog and the URL/screen stays on the form.
  Suggested mechanism: when the guard becomes enabled, push one sentinel history entry (window.history.pushState({ giftFormGuard: true }, "", window.location.href)); on popstate while enabled, re-push the sentinel (so the form stays) and call onBlocked with a pending "browser back" marker. On «Не сохранять» -> proceed(): remove the listener, then window.history.go(-2) (or go(-1) if the sentinel was already consumed) so the user really goes back; on cross/Esc -> cancel(): stay, keep the sentinel. When the guard becomes disabled (saved, clean, unmount) remove the listener and, if the sentinel is still on top and we are not navigating away by ourselves, pop it with history.back() only when safe — explain your choice to avoid leaving a duplicate history entry.
- Also add eforeunload (preventDefault + returnValue="") while enabled so a reload/tab close asks the browser's native confirm.
- Our own exits (save success, «Не сохранять», clean «Отмена») must not be intercepted and must not leave a stray sentinel entry (work with the bypass from G2 if present).
- Implement it inside useDiscardGuard (or a sibling hook use-browser-back-guard.ts in apps/mobile/src/session used by useDiscardGuard) so both screens get it without duplicated code. Native behaviour must not change.

## Acceptance criteria
1. Web: dirty form + history.back() => dialog visible, form still mounted, location unchanged.
2. «Не сохранять» after a browser back => the app navigates back to the previous page (list).
3. Cross/Esc after a browser back => dialog closes, form and draft stay; a second Back shows the dialog again.
4. Clean form: browser back works normally, no sentinel pushed.
5. beforeunload handler is registered only while dirty.
6. Native (Platform.OS !== "web"): no window/history access at all.
