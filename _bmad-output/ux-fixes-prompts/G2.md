## Bug
In both screens the code does setAllowLeave(true) and then navigates in the SAME tick:
- new.tsx:136-143 leave() (setAllowLeave(true); router.back() or router.dismissTo("/")), used by clean «Отмена» and by «Не сохранять» (new.tsx:164-168 leaveDiscard) when no system back was blocked.
- edit.tsx:231-236 the same leave(); edit.tsx:184-185 save success (setAllowLeave(true); router.dismissTo with toast gift_updated); new.tsx:95-96 save success (dismissTo with toast gift_created); the UNAUTHENTICATED hand-over (new.tsx:111, edit.tsx:199).
React state is applied on the next render, but usePreventRemove reads enabled from the last committed render, so at the moment of router.back() the guard is still enabled for a dirty form: on native the exit after «Не сохранять» can be blocked and the dialog reopens. After save success it currently works only by accident because submitting was true in the last render.

## Expected
Our own deliberate exits (save success, «Не сохранять», clean «Отмена», session-expired hand-over) are NEVER intercepted, independent of render timing and of submitting.

## Implementation guidance
- Give useDiscardGuard a synchronous bypass, e.g. a method llowNextLeave() / leaveWith(fn) that sets a ref read inside the usePreventRemove callback: if the bypass ref is set, the callback immediately calls 
avigation.dispatch(event.data.action) instead of onBlocked. (usePreventRemove callback receives { data: { action } }.) Keep proceed()/cancel().
- Replace the llowLeave state usage in both screens with that method (remove the state if it becomes dead). If the leave fails (session sign-out failed), reset the bypass.
- Do not change UX copy or the dialog.

## Acceptance criteria
1. Dirty form -> «Отмена» -> dialog -> «Не сохранять» leaves via router.back()/dismissTo exactly once and the dialog does NOT reopen, even when the preventRemove mock keeps blocking until a re-render.
2. Save success leaves to the list with the toast param and is not intercepted, even if submitting were false.
3. A real system back on a dirty form (callback fired by the mock without bypass) still opens the dialog.
4. No dead state/vars left.
